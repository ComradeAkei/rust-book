# 18.1. extern "C" и соглашение о вызовах

Чтобы позвать функцию из C, её объявляют в блоке `extern`. Объявление —
это обещание компилятору: вот имя символа, вот его сигнатура, вот
соглашение о вызовах. Тело придёт от компоновщика. Проверить обещание
компилятор не может — он не видит заголовка C, — поэтому вся
ответственность за совпадение на программисте.

Различайте объявление и определение: объявление сообщает имя и типы,
определение содержит исполняемое тело функции. В блоке `extern` тела нет;
при сборке компоновщик находит его в другом объектном файле или библиотеке.
Сигнатура `fn c_add(a: i32, b: i32) -> i32` говорит, что передаются два
значения `i32` и возвращается одно `i32`; она ничего не говорит о том,
какой алгоритм находится внутри.

```rust
{{#include ../../code/ch18/src/abi.rs:extern}}
```

Строка `"C"` — это соглашение о вызовах: как аргументы раскладываются по
регистрам и стеку, кто их убирает, как возвращается результат. Для
стандартного C это `"C"` (на каждой платформе своё, но компилятор знает
правило). Есть и другие (`"system"`, `"stdcall"` на Windows), но `"C"` —
основное. Сама функция `c_add` приходит из нашего `c/support.c`, который
`build.rs` компилирует и отдаёт компоновщику; libc Rust линкует всегда, а
чтобы назвать другую библиотеку, есть `#[link]` ([18.6](06-tools.md)).

<div class="box trap">

**Ловушка.** В [edition][g-edition] 2024 блок `extern` обязан быть `unsafe extern` —
это и подчёркивает, что объявления внутри непроверяемы. Просто `extern "C"
{ … }` больше не компилируется:

```rust
extern "C" {
    fn c_add(a: i32, b: i32) -> i32; // error: extern blocks must be unsafe
}
```

Отдельные функции внутри блока можно пометить `safe` — тогда их зовут без
`unsafe` (это редкость, для заведомо безопасных символов вроде `errno`).

</div>

<div class="box check">

**Что компилятор проверяет, а что нет.** Сигнатуру в `extern` он принимает
на веру: перепутанная ширина или число аргументов из
[мотивирующей проблемы](index.md) скомпилируются и дадут UB при вызове. Но
тип *указателя на функцию* он проверяет — обычную `fn` не подставить туда,
где ждут `extern "C" fn`, потому что соглашения о вызовах разные:

```rust
fn plain(x: i32) -> i32 { x }
let _cb: extern "C" fn(i32) -> i32 = plain;
// error[E0308]: mismatched types ... expected fn pointer `extern "C" fn(_) -> _`
```

Этим пользуются обратные вызовы ([18.5](05-callback.md)): переходник обязан
быть `extern "C"`, и компилятор это гарантирует.

</div>

<div class="box c">

**Как в C.** В C объявление функции — тоже обещание: заголовок `.h`
декларирует сигнатуру, а определение приходит из другого модуля при
компоновке. Разница в том, что в C заголовок обычно пишет автор библиотеки
и ошибиться в нём труднее (хотя рассинхрон `.h` и `.c` — классический баг).
В Rust объявление пишет *потребитель*, вручную повторяя сигнатуру C, —
поэтому инструменты вроде `bindgen` ([18.6](06-tools.md)) генерируют его из
того же `.h`, чтобы не ошибиться.

</div>
