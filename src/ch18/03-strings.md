# 18.3. Строки и core::ffi

Строка в C и строка в Rust устроены по-разному, и граница — то место, где
разница становится опасной. В C строка — это указатель на байты,
оканчивающиеся нулём: длины нет (её ищут, считая до нуля), кодировки нет
(просто байты). В Rust `&str` — это указатель и длина, с жёсткой гарантией
UTF-8, и нуль внутри разрешён. Мост между ними — два типа: `CString`
(владеющая строка с нулём на конце) и `CStr` (заём такой строки).

Например, Rust-строка `"ab"` содержит два байта `[97, 98]`, а её длина
передаётся отдельно. C-строка для того же текста содержит `[97, 98, 0]`;
последний байт — признак конца, а не символ `"0"` (у него код 48).
Поэтому наличие подходящих букв в памяти ещё не делает буфер C-строкой.

## Передать строку в C

`&str` нельзя отдать в C напрямую: у него нет завершающего нуля, а внутри
может быть нуль, который C примет за конец. `CString::new` решает обе
проблемы — дописывает нуль и проверяет, что внутри нуля нет.

```rust
{{#include ../../code/ch18/src/strings.rs:into_c}}
```

`CString::new` вернёт `Err`, если в строке есть нуль, — иначе C увидел бы её
обрезанной. `c.as_ptr()` даёт `*const c_char` на время, пока `c` жива;
выпустить указатель за пределы жизни `CString` нельзя — получился бы висячий
указатель. Здесь он не переживает выражения, что и отмечает `// SAFETY`.

Для строк, известных на этапе компиляции, выделять `CString` в куче не
нужно — есть литерал `c"..."`:

## Прочитать строку из C

Когда C возвращает `*const c_char`, его оборачивают в `CStr::from_ptr` —
заём байтов до первого нуля. Дальше встаёт вопрос кодировки: C ничего не
обещает про UTF-8, поэтому `to_str()` возвращает `Result`, а не паникует.

```rust
{{#include ../../code/ch18/src/strings.rs:from_c}}
```

В нашей C-библиотеке единица «температура» намеренно записана в Latin-1
(байт `0xB0` — это `°`), и это не корректный UTF-8. `to_str()` на ней вернёт
`Err`, а `to_string_lossy()` заменит сбойный байт на `�` и даст строку,
которую можно показать. Выбор между ними — решение программиста: строгий
разбор или терпимый показ.

<div class="box trap">

**Ловушка.** `CStr::from_ptr` крайне требователен: указатель обязан вести
на валидную, оканчивающуюся нулём строку, которая жива всё время заёма, и
`from_ptr` сам сканирует её до нуля (стоимость `O(len)`). Два частых UB:
взять `CStr` на строку, которую C вот-вот освободит (висячий заём), и
передать в C `CString`, уже уронённую в Rust (`as_ptr` на мёртвой строке).
Время жизни здесь не проверяет никто — его держит программист.

</div>

<div class="box c">

**Как в C.** Всё это — ровно те грабли, на которые C наступает каждый день:
`strlen` по невалидному указателю, строка без завершающего нуля, обрезка на
внутреннем нуле, чужая кодировка, принятая за ASCII. Rust не прячет
C-строку, но заворачивает её в типы, которые делают опасность видимой:
`CString::new` не даст пронести внутренний нуль, `to_str()` не даст молча
принять не-UTF-8. Байты те же — договор явный.

</div>
