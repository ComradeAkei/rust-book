# 18.2. repr(C) и раскладка на границе

Чтобы передать структуру в C по значению или по указателю, её раскладка в
памяти должна в точности совпадать с C-структурой: тот же порядок полей, то
же выравнивание, та же набивка. Обычный Rust-тип для этого не годится —
представление `#[repr(Rust)]` по умолчанию компилятор волен менять: он
переставляет поля ради экономии места ([6](../ch06/index.md)), и порядок
между сборками не гарантирован. На границе с C это недопустимо.

## repr(C): раскладка как в C

`#[repr(C)]` отключает перестановку и задаёт раскладку по правилам C: поля
в порядке объявления, выравнивание каждого — как у его типа. Тогда
структуру можно передавать в обе стороны по значению.

```rust
{{#include ../../code/ch18/src/layout.rs:repr}}
```

`Point` с `#[repr(C)]` неотличим от `struct CPoint { int32_t x, y; }`:
два `int` подряд. Передача по значению следует тому же C-соглашению —
маленькая структура уедет в регистрах, большая через стек, но об этом
договариваются обе стороны одинаково, потому что раскладка и ABI совпадают.
`c_int` из `core::ffi` — это и есть C-шный `int` на данной платформе; не
`i32` «на глаз», а именно тот тип, что подразумевает ABI.

## Перечисления с C-представлением

У Rust-перечисления по умолчанию ни размер дискриминанта, ни его значения
не фиксированы. Для C его помечают `#[repr(C)]` (или `#[repr(i32)]`): тогда
это `int` с заданными значениями.

```rust
{{#include ../../code/ch18/src/layout.rs:enum}}
```

Так перечисление можно и принять из C, и отдать в C как `int`. Без пометки
передавать его через границу нельзя: значение дискриминанта — деталь
реализации.

## repr(transparent): обёртка без следа

Иногда хочется типобезопасную обёртку (не перепутать милливольты с
миллиамперами), но в памяти — ровно `int`, который ждёт C.
`#[repr(transparent)]` даёт именно это: тип неотличим от единственного
непустого поля.

```rust
{{#include ../../code/ch18/src/layout.rs:transparent}}
```

`Millivolts` передаётся в C всюду, где ждут `int`, но в Rust остаётся
отдельным типом. На `repr(transparent)` построены `NonZero*` и многие
обёртки стандартной библиотеки — а также приём «новый тип поверх указателя»
для умных указателей из [17.3](../ch17/03-nonnull.md).

<div class="box trap">

**Ловушка.** `#[repr(C)]` фиксирует раскладку, но не делает типы
совместимыми по смыслу. `bool` в Rust — один байт со значениями 0/1, и
`#[repr(C)]` этого не меняет: принять из C байт 2 как `bool` — всё равно UB
([17.4](../ch17/04-transmute.md)). То же с `char` (это скаляр Unicode, не
C-шный `char` — тот `c_char`), со ссылками (не `null`) и с перечислениями
(только заданные значения). Совпадение раскладки — не разрешение подсунуть
недопустимый образец.

</div>

<div class="box ref">

**Как в стандартной библиотеке.** `std::os::raw` и `core::ffi` дают имена
C-типов: `c_int`, `c_char`, `c_void`, `c_long`, `c_ulong`. Они разворачиваются
в правильную для платформы ширину, поэтому код переносим: `c_long` — 32 бита
на Windows и 64 на Linux. Писать `i64` вместо `c_long` — та же ошибка
ширины, что в [мотивирующей проблеме](index.md), только спрятанная.

</div>
