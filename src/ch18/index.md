# 18. FFI с C

## Мотивирующая проблема

Весь системный мир говорит на ABI языка C: ядро, libc, OpenSSL, zlib,
SQLite, драйверы. Чтобы Rust был системным языком, он обязан и звать C, и
показываться C. Объявить чужую функцию в Rust просто:

```rust
unsafe extern "C" {
    fn strtol(s: *const core::ffi::c_char) -> i32; // ?
}
```

А настоящий прототип в C такой:

```c
long strtol(const char *nptr, char **endptr, int base);
```

Объявление выше компилируется — и это мина. Компилятор полностью доверяет
вашей сигнатуре: он не видит заголовка C и не может сверить ни число
аргументов (здесь потеряны `endptr` и `base`), ни ширину (`long` против
`i32`), ни соглашение о вызовах. Вызов пойдёт с неправильным стеком и
регистрами — неопределённое поведение, которое компилятор не ловит, а
компоновщик в лучшем случае заметит лишь отсутствующий символ.

И это лишь первая из мин границы. Строка в C — это указатель на байты до
нуля, без длины и без обещания про UTF-8; в Rust — `&str` с длиной и
гарантией кодировки. У C нет ни `Drop`, ни времён жизни, поэтому «кто
выделил, тот и освобождает» держится на одной дисциплине — отсюда утечки,
двойные освобождения, висячие указатели. А паника Rust, долетевшая до
кадра C, — тоже UB.

## Что делает Rust

Глава — про то, как пройти границу C, назвав каждое решение явно, и про
инструменты, которые это автоматизируют.

- Блок `unsafe extern "C"` ([18.1](01-abi.md)) — объявление чужой функции
  как обещание про её сигнатуру и ABI; `#[link]` называет библиотеку.
- `#[repr(C)]` ([18.2](02-layout.md)) — раскладка структур и перечислений,
  совпадающая с C; `#[repr(transparent)]` для обёрток.
- Строки и `core::ffi` ([18.3](03-strings.md)) — `CStr`/`CString`, литерал
  `c"..."`, и что делать с не-UTF-8 и внутренним нулём.
- Владение через границу ([18.4](04-owned.md)) — `Box::into_raw`/`from_raw`
  и непрозрачный описатель, которым Rust-объект отдают в C.
- Обратные вызовы ([18.5](05-callback.md)) — указатели на функции,
  переходник для замыкания и запрет панике пересекать границу.
- Настоящая библиотека и инструменты ([18.6](06-tools.md)) — обёртка над
  zlib, `bindgen`, `cbindgen`, крейт `cc` и сценарии сборки.

Общий принцип тот же, что в [главе 16](../ch16/index.md): опасное заперто
за безопасным API, каждый `unsafe` снабжён `// SAFETY`, а то, что C
вызывает Rust, проверено настоящей C-программой под санитайзером.

## Код главы

Глава хостовая: она линкуется с C — нашим `c/support.c`, libc и zlib,
— поэтому под Miri (Miri не исполняет чужой код) и под Cortex-M не идёт.
Всё проверяется:

```console
$ cargo test -p ch18                 # вызовы C из Rust, обёртка zlib, doc-тесты
$ bash code/ch18/c/run.sh            # C вызывает Rust (раздел 18.4) под ASan
$ cargo test -p ch18-solutions       # задачи A, B, D и логика FIFO задачи C
$ bash solutions/ch18/c/run.sh       # C управляет кольцевым буфером (задача C) под ASan
```

Вспомогательную C-библиотеку собирает `build.rs`, вызывая системный
компилятор (`cc`/`gcc`) и `ar`, — без крейта `cc`. Для zlib нужен
`libz.so` (пакет `zlib1g-dev`).
