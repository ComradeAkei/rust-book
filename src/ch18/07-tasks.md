# 18.7. Задачи

Все четыре задачи решаются кодом: заготовки — в `exercises/ch18`, тесты,
общие для заготовок и решений, — в `tests-shared/ch18.rs`. Задачи A, B и D
зовут C (libc, glibc, zlib), задача C делится надвое: логику FIFO проверяет
Rust-тест, а экспорт в C — C-программа под AddressSanitizer.

```console
$ cargo test -p ch18-exercises            # задачи A, B, D и логика FIFO задачи C
$ cargo test -p ch18-exercises a_          # одна задача
$ bash solutions/ch18/c/run.sh            # драйвер задачи C на C под ASan (эталон)
```

Пока функции не реализованы, тесты падают на `todo!()`. Разборы — в
[приложении E](../appendix-e/ch18.md), но сначала попробуйте сами.

## A. Каталог объявлений

Объявите шесть функций стандартной библиотеки C в блоке `unsafe extern "C"`
с точными типами и оберните каждую безопасно. Прототипы даны в комментарии.

```rust
{{#include ../../exercises/ch18/src/a_decls.rs:skeleton}}
```

Соль задачи — в типах: `strlen` возвращает `size_t` (`usize`, не `i32`);
аргумент `toupper` — `int`, а не `char`; `abs(i32::MIN)` в C — UB, его надо
отвергнуть; `strchr` возвращает указатель внутрь строки, из которого нужно
получить смещение. Для каждой функции назовите, какой была бы типичная
ошибка в объявлении и чем она опасна (разбор — в приложении E).

```console
$ cargo test -p ch18-exercises a_
```

## B. qsort_r с замыканием

Отсортируйте срез `i32`, вызвав `qsort_r` из glibc с компаратором-замыканием.

```rust
{{#include ../../exercises/ch18/src/b_qsort.rs:skeleton}}
```

Замыкание передайте как `void *arg`, а вызывайте переходником `extern "C"`
фиксированного типа, который достаёт его из `arg` ([18.5](05-callback.md)).
`Ordering` приводится к `i32` как `-1/0/1` — ровно знак, которого ждёт
`qsort`. И главное: паника в компараторе не должна пересечь границу C —
оберните вызов в `catch_unwind`. Тест проверяет и сортировку с захватом
направления, и что паникующий компаратор не роняет процесс.

```console
$ cargo test -p ch18-exercises b_
```

## C. Кольцевой буфер за непрозрачным описателем

Реализуйте кольцевой буфер фиксированной ёмкости (FIFO) и экспортируйте его
в C как непрозрачный описатель: `rb_new`, `rb_push`, `rb_pop`, `rb_len`,
`rb_free`.

```rust
{{#include ../../exercises/ch18/src/c_ring.rs:skeleton}}
```

Описатель отдавайте через `Box::into_raw` в `rb_new` и забирайте `from_raw`
в `rb_free` — ровно один раз ([18.4](04-owned.md)). Функции, разыменовывающие
описатель, помечены `unsafe` и несут `# Safety`. Логику FIFO проверяет
общий Rust-тест; экспорт в C — драйвер `rb_test.c`, который под
AddressSanitizer поймал бы и выход за буфер, и утечку при забытом `rb_free`.
Готовый драйвер и заголовок — в `solutions/ch18/c/`; направьте их на свой
крейт (добавьте `crate-type = ["lib", "staticlib"]`, он уже есть в заготовке).

```console
$ cargo test -p ch18-exercises c_ring
$ bash solutions/ch18/c/run.sh    # эталон; для своего крейта поправьте -p в run.sh
```

## D. Безопасная обёртка над zlib

Объявите `compressBound`, `compress2`, `uncompress` из zlib
(`#[link(name = "z")]`) и напишите над ними безопасные `compress` и
`decompress`.

```rust
{{#include ../../exercises/ch18/src/d_zlib.rs:skeleton}}
```

Обёртка сама считает размер буфера назначения (`compressBound`), передаёт
его длину через out-параметр и усекает `Vec` по фактической; код возврата,
отличный от нуля, превращает в `Err`. Тест проверяет круг
«сжать → распаковать → то же самое» и что явно не-zlib-поток отвергается
ошибкой, а не возвращает мусор.

```console
$ cargo test -p ch18-exercises d_
```
