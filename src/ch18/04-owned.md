# 18.4. Владение через границу

У C нет ни `Drop`, ни времён жизни, ни заёмщика. Правило «кто выделил, тот
и освобождает» держится на одной дисциплине, и за границей её не
подстрахует компилятор: отданный в C `Box`, который никто не вернёт, —
утечка; дважды освобождённый — двойное `free`; прочитанный после
освобождения — use-after-free. Rust даёт для этого две парные операции:
`Box::into_raw` снимает ответственность за освобождение и отдаёт сырой
указатель, `Box::from_raw` возвращает её — ровно один раз.

## Отдать и забрать

Пока указатель у C, Rust про него «забыл»: Box не уронится сам. Утечки нет
только потому, что мы заберём указатель назад.

```rust
{{#include ../../code/ch18/src/owned.rs:roundtrip}}
```

`into_raw` отдаёт владение (деструктор больше не сработает автоматически),
`from_raw` забирает его обратно — и забрать нужно ровно один раз, иначе
двойное освобождение. Здесь C лишь хранит и возвращает тот же указатель,
не разыменовывая и ничего не освобождая, поэтому `// SAFETY` может
утверждать, что указатель по-прежнему валиден.

## Экспорт: непрозрачный описатель

В обратную сторону Rust-объект отдают в C как *непрозрачный описатель*:
указатель, за которым Rust-значение, а C видит лишь адрес и не знает
устройства. Функции с C-ABI и неискажённым именем (`#[unsafe(no_mangle)]
extern "C"`) создают, используют и освобождают его.

```rust
{{#include ../../code/ch18/src/owned.rs:export}}
```

Договор симметричен `roundtrip`: `ch18_counter_new` выделяет через `into_raw`
и отдаёт владение C; `ch18_counter_free` забирает его обратно `from_raw` и
роняет. Между ними C волен звать `bump` сколько угодно. Функции, которые
разыменовывают описатель, помечены `unsafe` и несут `# Safety`:
ответственность за живой, не освобождённый указатель — на вызывающем, то
есть на C.

Эту сторону нельзя проверить Rust-тестом — её проверяет настоящая
C-программа, которая создаёт, дёргает и освобождает счётчик, под
AddressSanitizer с LeakSanitizer: забыли бы `free` — всплыла бы утечка
Box.

```console
$ bash code/ch18/c/run.sh
ok    счётчик из Rust: 5 нажатий = 5
```

<div class="box trap">

**Ловушка.** `#[unsafe(no_mangle)]` обязателен: без него Rust исказит имя
символа, и C его не найдёт (ошибка компоновки). Тип описателя для C —
указатель на *неполный* тип (`typedef struct Counter Counter;`), чтобы C не
мог заглянуть внутрь и зависеть от раскладки. И паника из экспортированной
функции не должна вылететь в C — об этом [18.5](05-callback.md).

</div>

<div class="box ref">

**Как в стандартной библиотеке и экосистеме.** Непрозрачный описатель — это
как `FILE *` из stdio: C держит указатель, а устройство скрыто. Так
устроены почти все C-библиотеки с состоянием (`sqlite3 *`, `z_stream`), и
так же Rust-библиотеки отдают себя в C: `into_raw` на конструкторе,
`from_raw` на деструкторе, `&mut *ptr` в операциях. Задача C этой главы —
построить такой описатель для кольцевого буфера.

</div>
