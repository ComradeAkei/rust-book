# 2. Выражения, управление потоком, сопоставление с образцом

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** Всё есть выражение, блоки как значения, loop с break value, метки циклов. match с проверкой полноты, образцы: диапазоны, @, |, срезы [first, .., last], режимы связывания. Охранные условия, if let, let else, цепочки if let ... && ... из edition 2024, matches!.

**Как в C.** switch с проваливанием и забытым break, нет проверки полноты по enum.

**Железо.** Во что компилируется match: таблица переходов, дерево сравнений, битовая маска. Предсказатель переходов, #[cold], core::hint::assert_unchecked.

**Трюки и ловушки.** Срезовые образцы для разбора протоколов, match по кортежу как таблица состояний. Временные значения в скрутинируемом выражении match живут до конца match, и MutexGuard в нём даёт deadlock. Edition 2024 изменила область жизни временных значений в if let и в хвостовых выражениях.

**Задачи**

- A. Для пяти match предскажите, где LLVM построит таблицу переходов. Проверьте по ассемблеру и найдите порог плотности значений.
- B. Декодер подмножества 16-битных инструкций Thumb (MOV, ADD, SUB, B, LDR) через match по битовым маскам. Тесты строятся на опкодах из llvm-objdump вашей же прошивки.
- C. Лексер мини-языка как конечный автомат на loop и match с метками. Сравните скорость с версией на регулярных выражениях.
- D. Воспроизведите deadlock из-за временного MutexGuard в if let ... else. Покажите, что в edition 2021 он есть, а в 2024 нет, и найдите вариант, который виснет в обеих.
