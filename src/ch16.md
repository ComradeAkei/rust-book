# 16. unsafe и неопределённое поведение

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** Пять возможностей unsafe: разыменование сырых указателей, вызов unsafe fn, доступ к static mut, реализация unsafe trait, чтение полей union. Инварианты валидности и безопасности. Перечень UB в Rust. Provenance и API строгого provenance (with_addr, map_addr, expose_provenance). Модели алиасинга Stacked Borrows и Tree Borrows, Miri. Новое в edition 2024: unsafe extern, атрибуты #[unsafe(...)], линт unsafe_op_in_unsafe_fn, запрет ссылок на static mut.

**Как в C.** В C UB невидимо и может быть в любой строке. В Rust оно локализовано в unsafe-блоках, но последствия те же.

**Железо.** Что оптимизатор делает с UB: удаляет проверки и переставляет код до точки ошибки. Почему &mut на буфер, который пишет DMA, уже является UB.

**Трюки и ловушки.** Маленький unsafe-блок за безопасным API, предусловия через debug_assert!, линт clippy undocumented_unsafe_blocks. «Тесты проходят» не доказывает корректность. Безопасный код в том же модуле может нарушить инвариант, на который опирается unsafe, поэтому граница доверия это модуль.

**Задачи**

- A. Каталог из 12 фрагментов: найдите UB в каждом и подтвердите Miri. Для тех, где Miri молчит, объясните почему.
- B. Безопасная функция, возвращающая две разные строки матрицы как &mut [T], с комментариями SAFETY. Прогон под Miri в обеих моделях алиасинга.
- C. Дан крейт с безопасным, но unsound API. Напишите программу без единого unsafe, которая через этот API получает use-after-free, затем исправьте API.
- D. Найдите пример, корректный под Tree Borrows и ошибочный под Stacked Borrows. Объясните разницу моделей и что она значит для автора unsafe-кода.
