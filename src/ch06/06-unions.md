# 6.6. union

`union` в Rust устроен так же, как в C: все поля начинаются со смещения 0,
размер равен наибольшему полю с учётом выравнивания. Тега нет, и какое
поле сейчас «активно», знает только программист. Поэтому чтение поля
union — операция `unsafe`, а запись безопасна.

```rust
{{#include ../../code/ch06/src/unions.rs:float_bits}}
```

<div class="box hood">

**Под капотом.** Обе функции компилируются в одинаковый код, и LLVM
заметил это сам: `ch06_bits_union` в объектном файле — просто второе имя
функции `ch06_bits_safe`, обе метки указывают на одну секцию.

```console
$ cargo build -p ch06 --release --target thumbv7m-none-eabi
$ llvm-objdump -t target/thumbv7m-none-eabi/release/deps/libch06-*.rlib | grep 'F .*ch06_bits'
00000000 g     F .text.ch06_bits_safe	00000006 ch06_bits_safe
00000000 g     F .text.ch06_bits_safe	00000006 ch06_bits_union
```

Сам код зависит от того, где живёт `f32`:

```text
x86_64:              thumbv7m:              thumbv7em-none-eabihf:
	movd eax, xmm0   	push {r7, lr}      	push {r7, lr}
	ret              	mov r7, sp         	mov r7, sp
	                 	pop {r7, pc}       	vmov r0, s0
	                                       	pop {r7, pc}
```

На x86_64 вещественный аргумент приходит в `xmm0`, а целый результат
уходит в `eax`. У Cortex-M3 нет FPU, по soft-float ABI `f32` уже лежит в
`r0`, и делать нечего. Cortex-M4F с hard-float ABI получает аргумент в
регистре FPU `s0` и переносит его в `r0` одной инструкцией.

</div>

Перевод битов float в целое через union законен в Rust, если любой набор
битов допустим для поля, которое вы читаете. Для `u32` это так. Для
`bool`, `char`, ссылок и enum — нет: прочитать `bool` из union, в который
записали `u8` со значением 2, значит получить UB.

## Размеченное объединение вручную

```rust
{{#include ../../code/ch06/src/unions.rs:tagged_by_hand}}
```

Так выглядит код, когда нужна точная C-раскладка и enum по какой-то
причине не подходит. Компилятор ничем не помогает: `tag` и `data` связаны
только комментарием. В Rust для этого почти всегда лучше enum с
`repr(C)` или `repr(u8)` из раздела [6.3](03-enums.md), а union остаётся
для FFI с C-кодом, который уже использует union, и для низкоуровневых
типов вроде `MaybeUninit<T>`: в core это union из `()` и `ManuallyDrop<T>`.

<div class="box c">

**Как в C.** В C99 и C11 чтение не того члена union, в который писали,
разрешено и переинтерпретирует байты (сноска к 6.5.2.3 стандарта). В C++
это неопределённое поведение, а в C через приведение указателей
`*(uint32_t *)&f` — нарушение strict aliasing. В Rust правил strict
aliasing по типам нет вовсе: важно только, допустимы ли байты для
читаемого типа. Это делает перевод через union и через приведение сырых
указателей одинаково законным, если байты подходят.

</div>

<div class="box trap">

**Ловушка.** У union нет ниши: `Option<FloatBits>` занимает 8 байт, а не 4.
Компилятор не знает, какое поле активно, а значит, не может найти
запрещённый шаблон битов.

</div>
