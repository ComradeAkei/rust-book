# 6. Составные типы и раскладка памяти

## Мотивирующая проблема

Прошивка станции телеметрии отправляет отсчёт датчика на хост. Первая
версия, как её написал бы любой из нас на C:

```c
#include <stdint.h>
#include <unistd.h>

struct sample {
    uint8_t  channel;
    uint32_t value;
    uint8_t  flags;
};

void send_sample(int fd, uint8_t ch, uint32_t v, uint8_t fl)
{
    struct sample s;
    s.channel = ch;
    s.value = v;
    s.flags = fl;
    write(fd, &s, sizeof s);
}
```

В этих строках три ошибки, и ни одну компилятор не покажет.

1. `sizeof s` равен 12, а не 6. Компилятор вставил 3 байта после `channel`,
   чтобы `value` лежал по адресу, кратному 4, и ещё 3 байта в конце, чтобы
   в массиве `struct sample[2]` второй элемент тоже был выровнен.
2. Эти 6 байт никто не инициализировал. В провод уходит то, что лежало на
   стеке до вызова функции: куски чужих переменных, адреса, иногда ключи.
   В ядре Linux тот же шаблон с `copy_to_user` по структуре с дырами
   много раз приводил к утечке содержимого стека ядра в пространство
   пользователя.
3. Протокол теперь зависит от ABI. Добавьте в структуру `uint64_t`, и на
   32-битном x86 (System V i386, где `uint64_t` внутри структуры выравнивается
   на 4) получится одна раскладка, а на x86_64 и ARM (выравнивание 8)
   другая.

Типичное «исправление» делает хуже:

```c
struct __attribute__((packed)) sample { uint8_t channel; uint32_t value; uint8_t flags; };

void bump(uint32_t *v) { *v += 1; }   /* компилятор считает *v выровненным */

bump(&s.value);                        /* адрес нечётный */
```

На x86 это работает. На Cortex-M3 обычно тоже: инструкция `LDR` умеет
читать невыровненное слово. На Cortex-M0 тот же код падает в HardFault.
Cortex-M3 тоже падает, если функция по такому указателю читает два
соседних слова: компилятор вправе объединить их в одну инструкцию `LDRD`
или `LDM`, а они требуют выравнивания на 4. GCC начиная с версии 9 хотя
бы предупреждает (`-Waddress-of-packed-member`), но только предупреждает.

## Что делает Rust

- Раскладка по умолчанию не обещана, и компилятор пользуется этим, чтобы
  сам убирать дыры. Там, где раскладка нужна (провод, регистры, FFI), она
  задаётся явно атрибутом `repr`, а проверяется при компиляции.
- Ссылка на поле `packed`-структуры запрещена: это ошибка E0793, а не
  предупреждение.
- Байты выравнивания считаются неинициализированными. Прочитать их как
  `u8` нельзя, и Miri ловит такую попытку.
- В провод данные уходят через явное кодирование (`to_le_bytes`), а не
  копированием памяти структуры.

Кроме того, система типов позволяет описывать данные плотнее, чем C:
перечисление с данными занимает ровно столько, сколько нужно, а `Option`
от ссылки не тратит ни одного байта на признак «нет значения».

## Код главы

Все фрагменты главы взяты из файлов репозитория и проверяются тестами:

```console
$ cargo test -p ch06 -p ch06-regs        # примеры
$ cargo +nightly miri test -p ch06       # те же тесты под Miri
$ cargo run -p ch06 --example sizes      # таблица размеров на хосте
$ cd firmware && bash run-demos.sh       # та же таблица на Cortex-M3 и опыты с выравниванием
```

Числа в тексте получены на rustc 1.97.0 для `x86_64-unknown-linux-gnu`,
`thumbv6m-none-eabi`, `thumbv7m-none-eabi` и `thumbv7em-none-eabihf`.
Ассемблер снят командой `cargo asm --simplify` из release-сборки.
