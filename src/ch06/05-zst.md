# 6.5. Типы нулевого размера

Тип нулевого размера (zero-sized type, ZST) не занимает памяти вовсе:
`()`, единичные структуры, `PhantomData<T>`, массивы `[T; 0]`, enum из
одного варианта без данных. Значение такого типа нельзя «положить» в
память, поэтому операции над ним компилируются в ничто.

## Маркеры состояния

ZST позволяют хранить в типе знание, которого нет в данных. Вывод GPIO
бывает входом или выходом, и запись в выход, сконфигурированный как вход,
— ошибка, которую хочется поймать при компиляции:

```rust
{{#include ../../code/ch06/src/zst.rs:markers}}
```

`Pin<Output>` занимает 1 байт, ровно как номер вывода. `PhantomData<Mode>`
говорит компилятору: «этот тип логически содержит `Mode`», и без него
неиспользуемый параметр типа был бы ошибкой E0392. Вызов `set_high` у
`Pin<Input>` не компилируется: такого метода нет. Этот приём называется
typestate, и в главе 27 на нём построен драйвер GPIO настоящего
микроконтроллера.

## Массив нулевой длины

```rust
{{#include ../../code/ch06/src/zst.rs:zst_array}}
```

`[u64; 0]` имеет размер 0 и выравнивание 8. Поле такого типа выравнивает
всю структуру, не добавляя данных: `AlignedTo8` занимает 8 байт (3 байта
данных и 5 байт хвостового выравнивания) и начинается по адресу,
кратному 8. Это пригодится для буферов DMA, к которым контроллер
предъявляет требования по выравниванию.

## ZST в коллекциях

```rust
{{#include ../../code/ch06/src/zst.rs:vec_unit}}
```

`Vec<()>` никогда не обращается к аллокатору: место под миллион нулевых
значений равно нулю байт. Его ёмкость сразу равна `usize::MAX`, а
указатель внутри — висячий, но выровненный адрес, по которому никто не
будет читать. `HashSet<K>` в std устроен как обёртка над `HashMap<K, ()>`,
и значения в нём не стоят ничего.

<div class="box c">

**Как в C.** Ближайший аналог — пустая структура как расширение GCC или
гибкий массив `char data[]` в конце структуры. Ни то, ни другое не даёт
проверок типов: маркер состояния в C обычно хранится в поле `int mode`,
которое проверяется во время выполнения и занимает память.

</div>

<div class="box trap">

**Ловушка.** Адрес значения ZST ничего не значит. Два разных значения `()`
могут иметь один адрес, а одно и то же — разные адреса в разных местах
программы. Не используйте адреса ZST как идентификаторы объектов. И
осторожнее с арифметикой указателей: `ptr.add(1)` для `*const ()` не
сдвигает адрес, потому что шаг равен размеру типа, то есть нулю.

</div>
