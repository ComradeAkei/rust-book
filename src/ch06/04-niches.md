# 6.4. Ниши

## Что такое ниша

У многих типов часть битовых шаблонов недопустима:

| Тип | Допустимые значения | Свободно |
|---|---|---|
| `bool` | 0 и 1 | 254 значения байта |
| `char` | 0..=0xD7FF и 0xE000..=0x10FFFF | суррогаты и всё выше 0x10FFFF |
| `&T`, `&mut T`, `Box<T>` | корректные ссылки и [владеющие][g-ownership] указатели; нулевой адрес запрещён | 0 |
| `NonNull<T>` | ненулевой указатель; пригодность к разыменованию — отдельное условие | 0 |
| `NonZeroU32` и другие `NonZero*` | всё, кроме 0 | 0 |
| `fn()` | адрес функции | 0 |
| enum без данных из N вариантов | N значений тега | остальные значения тега |

Ненулевого адреса недостаточно для корректной ссылки: нужны живые
данные подходящего типа, выравнивание и допустимый доступ.
`NonNull` гарантирует именно отсутствие нуля, а не все эти условия;
он может быть висячим, пока его не разыменовывают. Это различие
подчёркивает [документация NonNull](https://doc.rust-lang.org/std/ptr/struct.NonNull.html).

Такой неиспользуемый шаблон называется *нишей* (niche). Если внешнему enum нужно
отличить один-два варианта без данных, компилятор кодирует их значениями
из ниши и не добавляет отдельный тег. Самый частый случай — `Option<T>`:
`None` кодируется запрещённым для `T` значением.

```rust
{{#include ../../code/ch06/src/niche.rs:sensor_id}}
```

`Option<SensorId>` занимает 4 байта: `None` — это ноль, который `SensorId`
принимать не может по построению.

## Гарантии и наблюдения

Часть нишевых оптимизаций гарантирована документацией `core::option`
(раздел «Representation»), и на них можно опираться в FFI:
`Option<&T>` передаётся в C как обычный указатель, где `NULL` означает
`None`.

```rust
{{#include ../../code/ch06/src/niche.rs:guaranteed}}
```

Остальное — поведение текущего компилятора:

| Тип | Размер на x86_64 | Как закодирован `None` в rustc 1.97 |
|---|---|---|
| `Option<bool>` | 1 | 2 |
| `Option<Option<bool>>` | 1 | `None` = 255, `Some(None)` = 2 |
| `Option<char>` | 4 | 0xFFFF_FFFF |
| `Option<Ordering>` | 1 | −2 (`Ordering` занимает −1, 0, 1) |
| `Option<Reading>` | 4 | 255 в байте `channel` |
| `Option<u32>` | 8 | отдельный тег: у `u32` ниши нет |
| `Option<*const u8>` | 16 | отдельный тег: [сырой указатель][g-raw-pointer] может быть нулём |
| `Option<Cell<bool>>` | 2 | отдельный тег: ниша спрятана, см. ниже |

Значения в последнем столбце проверяет тест:

```rust
{{#include ../../code/ch06/src/niche.rs:values}}
```

Обратите внимание, что компилятор не обязан брать «следующее» значение
после допустимых. Для `char` он выбрал не 0x110000, а 0xFFFF_FFFF, для
`Option<Option<bool>>` не 3, а 255. Конкретный выбор — деталь реализации,
и полагаться можно только на гарантии из документации: ноль для ссылок,
`Box`, `NonNull`, `NonZero*` и указателей на функции.

Ниша может лежать не в первом поле и даже не в поле верхнего уровня:

```rust
{{#include ../../code/ch06/src/niche.rs:custom_niche}}
```

У `Reading` есть 2 байта `value` и 1 байт `channel`, где из 256 значений
занято 3. `Option<Reading>` кодирует `None` одним из 253 свободных значений
в байте `channel` (сейчас это 255), а байты `value` у `None` не
инициализированы.

<div class="box hood">

**Под капотом.** Нишевая оптимизация не только экономит память, но и
убирает код. Распаковка `Option<NonZeroU32>` с подстановкой нуля:

```rust
{{#include ../../code/ch06/src/asm_demo.rs:niche_asm}}
```

x86_64:

```text
ch06_unwrap_or_zero:
	mov eax, edi
	ret
```

thumbv7m (и thumbv6m так же):

```text
ch06_unwrap_or_zero:
	push {r7, lr}
	mov r7, sp
	pop {r7, pc}
```

Ни одного сравнения. `None` хранится как 0, `Some(v)` как само `v`, и
ответ «0 для `None`, иначе значение» совпадает с битами аргумента. На
Cortex-M аргумент уже лежит в `r0`, где должен оказаться результат, и от
функции остался только пролог с указателем кадра.

Проверка `Option<&u8>::is_some` — это проверка указателя на ноль:

```text
x86_64:                      thumbv7m:                 thumbv6m:
	test rdi, rdi            	cmp r0, #0             	subs r1, r0, #1
	setne al                 	it ne                  	sbcs r0, r1
	ret                      	movne r0, #1
```

Вариант для Cortex-M0 стоит разобрать: в ARMv6-M нет [условного
выполнения][g-conditional-execution] `it`, и LLVM считает `r0 != 0` через флаг переноса. `subs r1,
r0, #1` ставит C = 1, если вычитание прошло без заёма, то есть если `r0 ≥
1`. `sbcs r0, r1` вычисляет `r0 - r1 - (1 - C) = r0 - (r0 - 1) - (1 - C) =
C`. Результат 1 для ненулевого указателя и 0 для нулевого, без единого
перехода.

</div>

## Что прячет нишу

```rust
{{#include ../../code/ch06/src/niche.rs:blockers}}
```

| Тип | Размер `Option<_>` | Причина |
|---|---|---|
| `Cell<bool>`, `RefCell<T>`, [атомики][g-atomic], `Mutex<T>` | +тег | внутри `UnsafeCell`: значение меняется через `&`, компилятор не может хранить в нём чужой тег |
| `MaybeUninit<bool>` | +тег | там может лежать что угодно, в том числе «запрещённое» |
| `union` | +тег | компилятор не знает, какое поле активно |
| два варианта с данными, у каждого своя ниша | +тег | `enum { A(bool), B(bool) }` занимает 2 байта: ниша одна, а различать надо два варианта с данными |
| enum ровно из 256 вариантов | +тег | свободных значений тега не осталось |

`repr(C)` на структуре нишу не прячет: `Option<WithBool>` для
`#[repr(C)] struct WithBool { a: u32, b: bool }` занимает те же 8 байт.

<div class="box trick">

**Трюк.** Своя ниша стоит одной строки. Если ноль в протоколе означает «нет
датчика», храните номер в `NonZeroU16` или `NonZeroU32`: и тип точнее
описывает данные, и `Option` бесплатен. Так устроен `Measurement` в
сквозном проекте (раздел [6.11](11-project.md)). Если нужна ниша в
середине диапазона, подойдёт enum без данных: `enum Percent { P0, P1, ...,
P100 }` оставляет свободными 155 значений.

</div>

<div class="box trap">

**Ловушка.** Ниша делает некоторые битовые шаблоны недопустимыми, а значит,
создать такой шаблон в `unsafe`-коде — неопределённое поведение. Нулевая
ссылка, `bool` со значением 2, `char` из суррогатной пары — всё это UB в
момент создания значения, даже если его ни разу не прочитали. Отсюда
правило из главы 16: `transmute` и `ptr::read` в тип с нишей требуют
доказать, что биты допустимы.

</div>
