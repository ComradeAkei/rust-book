# 6.1. Структуры и выравнивание

## Три вида структур

```rust
{{#include ../../code/ch06/src/newtype.rs:struct_kinds}}
```

- Структура с именованными полями — аналог `struct` из C.
- *Кортежная структура* (tuple struct): поля без имён, доступ через `.0`,
  `.1`. Удобна, когда имя поля ничего не добавляет к имени типа.
- *Единичная структура* (unit struct) без полей. Она занимает 0 байт и
  нужна как маркер в системе типов, об этом раздел [6.5](05-zst.md).

`Point3` занимает 6 байт, `Rgb` 3 байта, `Tick` 0 байт. Отличие от C в том,
что в C пустая структура запрещена стандартом (GCC разрешает её как
расширение и даёт ей размер 0, а g++ размер 1).

## Newtype

Кортежная структура с одним полем (*newtype*) — самый дешёвый способ
получить новый тип. В памяти `Millimeters` ничем не отличается от `i32`,
но смешать их нельзя:

```rust
{{#include ../../code/ch06/src/newtype.rs:units}}
```

```rust,ignore
let d = Millimeters(10) + CentiCelsius(2150); // error[E0308]: mismatched types
```

Атрибут `repr(transparent)` обещает больше, чем просто одинаковый размер:
обёртка передаётся через ABI точно так же, как её единственное поле. Это
важно для FFI (глава 18) и для регистров периферии (раздел
[6.9](09-registers.md)). Без атрибута размер на практике совпадёт, но
это не обещано, а способ передачи в регистрах формально не гарантирован.

<div class="box c">

**Как в C.** `typedef int32_t millimeters;` не создаёт нового типа, а только
синоним: `millimeters + centi_celsius` компилируется молча. Чтобы получить
настоящую проверку, в C оборачивают значение в `struct { int32_t v; }` и
теряют арифметику. В Rust арифметика возвращается реализацией `Add` для
нужных пар типов.

</div>

## Выравнивание

<div class="box ref">

**Справка: зачем процессору выравнивание.** Обращение к нескольким
байтам может пересечь границу машинного слова или кэш-линии и
потребовать дополнительной работы. Значение называется *естественно
выровненным*, если его адрес кратен его размеру: `u32` по адресу,
кратному 4, `u64` по адресу, кратному 8. Но выравнивание типа задаёт
платформа: оно не всегда совпадает с размером и само по себе не
обещает ни одной транзакции шины, ни атомарности доступа.

Невыровненное значение может пересечь границу слова или строки кэша.
Тогда процессор либо делает два обращения и склеивает результат (x86, а
также Cortex-M3 и M4 для части инструкций), либо отказывается и
генерирует исключение (Cortex-M0 всегда, Cortex-M3 и M4 для `LDRD`,
`LDM`, `STRD`, `STM`). Подробности и опыты в QEMU в разделе
[6.7](07-packed.md).

</div>

В Rust у каждого типа есть *выравнивание* `align_of::<T>()`: степень
двойки, которой должен быть кратен адрес любого значения этого типа. И
*размер* `size_of::<T>()`, который всегда кратен выравниванию. Второе
правило нужно для массивов: элементы `[T; N]` идут подряд с шагом
`size_of::<T>()`, и каждый из них должен быть выровнен.

Например, при размере 8 и выравнивании 4 элементы могут начинаться
по адресам 100, 108, 116: каждый адрес кратен 4. Ровно это требование,
а не скорость конкретной инструкции, фиксирует
[Rust Reference](https://doc.rust-lang.org/reference/type-layout.html#size-and-alignment).

| Тип | x86_64: size / align | thumbv6m, thumbv7m: size / align |
|---|---|---|
| `u8`, `bool` | 1 / 1 | 1 / 1 |
| `u16` | 2 / 2 | 2 / 2 |
| `u32`, `f32`, `char` | 4 / 4 | 4 / 4 |
| `u64`, `f64` | 8 / 8 | 8 / 8 |
| `u128` | 16 / 16 | 16 / 8 |
| `usize`, `&T` | 8 / 8 | 4 / 4 |
| `&[T]`, `&str` | 16 / 8 | 8 / 4 |

Значения в таблице не взяты из документации, а измерены: для хоста
программой `cargo run -p ch06 --example sizes`, для Cortex-M прошивкой
`firmware/ch06-uart` и объектными файлами под обе [цели][g-target].

<div class="box trap">

**Ловушка.** Выравнивание `u128` различается даже между версиями
компилятора: до Rust 1.77 на x86_64 оно было 8, затем его подняли до 16,
чтобы совпасть с `__int128` из GCC и Clang. Структура с полем `u128`,
которую вы передаёте в C, меняла раскладку при обновлении rustc. Для
`repr(C)`-типов на границе с C используйте только типы с закреплённым ABI.

</div>
