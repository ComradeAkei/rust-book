# 13.2. Адаптеры и ленивость

## Ничего не происходит, пока не попросили

*Адаптер* — метод итератора, который возвращает новый итератор: `map`
превращает каждый элемент, `filter` пропускает не все, `zip` идёт по
двум сразу. Сам адаптер не делает ничего — он только запоминает, что
делать, когда у него попросят элемент. Это видно, если считать вызовы
замыкания:

```rust
{{#include ../../code/ch13/src/adapters.rs:lazy}}
```

`lazy_calls()` возвращает `([0, 2, 6], Some(80), 160)`. После
построения цепочки замыкание не вызвано ни разу. Первый `next` у
`filter` попросил элемент у `map`, тот — у среза: 3 превратилось в 30,
30 не прошло фильтр, и `filter` попросил ещё; 8 превратилось в 80, и
80 вернулось. Два вызова. `sum` дочитал остальные четыре. Каждый
элемент проходит цепочку целиком, прежде чем начнётся следующий: это
не «сначала `map` по всему массиву, потом `filter`», и промежуточного
массива нет.

Цепочку без потребителя компилятор замечает: тип `Map` помечен
`#[must_use]`, и предупреждение объясняет причину:

```console
warning: unused `Map` that must be used
 --> lazy.rs:2:5
  |
2 |     data.iter().map(|b| b + 1);
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: iterators are lazy and do nothing unless consumed
  = note: `#[warn(unused_must_use)]` (part of `#[warn(unused)]`) on by default
```

Тест `rustc_lazy_warning` проверяет это сообщение у закреплённого
rustc.

## Конвейер — один цикл

Среднее напряжение по отсчётам 12-битного АЦП без насыщенных отсчётов —
три шага, каждый своим адаптером:

```rust
{{#include ../../code/ch13/src/adapters.rs:mean}}
```

В C это был бы один цикл с `if` и двумя счётчиками, и в ассемблере
получается именно он. Ни вызовов, ни промежуточных буферов; цикл
развёрнут вдвое, а деление на 4095 заменено умножением на обратное:

```console
$ cargo asm -p ch13 --lib --simplify ch13_mean_mv
ch13_mean_mv:
	test rsi, rsi
	je .LBB61_1
…
.LBB61_5:
	movzx r9d, word ptr [rdi + 2*rdx]
	test r9d, r9d
	je .LBB61_8
	cmp r9d, 4095
	je .LBB61_8
	imul r9d, r9d, 3300
	imul r9, r9, 268501009
	shr r9, 40
	add r9d, eax
	inc ecx
	mov eax, r9d
.LBB61_8:
	movzx r9d, word ptr [rdi + 2*rdx + 2]
…
.LBB61_16:
	test ecx, ecx
	je .LBB61_1
	xor edx, edx
	div ecx
…
```

`movzx` читает отсчёт, два сравнения — это `filter`, `imul` на 3300 и
пара `imul`/`shr` вместо деления на 4095 — это `map`, `add` и `inc` —
`fold` с его парой `(s, n)`. Настоящее деление `div` одно, в конце: это
`checked_div`, и проверка `test ecx, ecx` перед ним — проверка на ноль,
которая и выбирает между `Some` и `None`. Векторизации нет: `filter`
делает сложение условным, и LLVM 22 не стал строить для него маски.

Cortex-M3 делает то же: `mul` на 3300, `umull` на 0x10010011 и сдвиг
старшего слова — деление на 4095, развёрнутое вчетверо, и одна `udiv`
в конце. А у Cortex-M0 нет ни аппаратного деления, ни умножения
32×32→64, и деление на константу остаётся вызовом `__aeabi_uidiv` на
каждый отсчёт. Тест `rustc_pipeline` проверяет все три цели.

<div class="box hood">

**Под капотом.** Цепочка компилируется в один цикл потому, что каждый
адаптер — обобщённая структура, а замыкание — её параметр типа.
`Filter<Map<Iter<u16>, F1>, F2>::next` вызывает `Map::next`, тот —
`Iter::next` и `F1`, и все эти вызовы мономорфизированы под конкретные
`F1` и `F2` и встраиваются, как обобщённая функция из главы 12. Свёртку
`fold` адаптеры к тому же пересылают внутрь: `Map::fold` вызывает
`fold` у внутреннего итератора с замыканием, которое сначала применяет
`F1`. Раздел [13.5](05-codegen.md) показывает, когда это важно.

</div>

## Тип цепочки

Тип цепочки — вложенные структуры, по одной на адаптер:

```rust
{{#include ../../code/ch13/src/adapters.rs:type_name}}
```

```text
core::iter::adapters::filter::Filter<core::iter::adapters::map::Map<core::slice::iter::Iter<'_, i32>, ch13::adapters::chain_type::{{closure}}>, ch13::adapters::chain_type::{{closure}}>
16
```

Шестнадцать байт на x86-64 — два указателя `slice::Iter`. Замыкания
ничего не захватили, их типы нулевого размера, и `Map` с `Filter` не
добавили ни байта. Размер адаптера — размер того, что ему нужно
помнить (тест `observed_adapter_types`, слово — 8 байт):

| Цепочка над `d.iter()` | Размер | Что добавилось |
|---|---|---|
| `.map(\|x\| x * 2)` | 2 слова | ничего: замыкание без захвата |
| `.map(\|x\| x * k)` | 3 слова | ссылка на `k` |
| `.enumerate()` | 3 слова | счётчик |
| `.chain(&d)` | 4 слова | второй итератор |
| `.peekable()` | 4 слова | подсмотренный элемент: `Option<Option<&i32>>` |
| `.zip(&d)` | 6 слов | второй итератор, индекс и длина |
| `d.chunks_exact(2)` | 5 слов | срез, хвост и размер куска |

Тип цепочки длинный, но писать его не нужно: функция возвращает
`impl Iterator<Item = …>`, как `window_sums` из введения, и вызывающий
знает о результате только то, что это итератор.

## Справочник адаптеров

| Адаптер | Что делает | Пример ниже |
|---|---|---|
| `map(f)` | `f(x)` для каждого | `ch13_mean_mv` |
| `filter(p)` | только `x`, для которых `p(&x)` | `ch13_mean_mv` |
| `filter_map(f)` | `y` из `Some(y) = f(x)` | |
| `enumerate()` | пары `(номер, x)` | `mismatches` |
| `zip(other)` | пары `(x, y)`, до конца более короткого | `first_mismatch` |
| `chain(other)` | сначала все свои, потом все чужие | `frame_crc` |
| `flat_map(f)`, `flatten()` | элементы итераторов `f(x)` подряд | `hex` |
| `scan(s, f)` | `fold`, который отдаёт промежуточные значения | `undelta` |
| `skip_while(p)`, `take_while(p)` | пропустить начало, взять начало | `payload` |
| `map_while(f)` | `map`, который останавливается на первом `None` | `leading_number` |
| `peekable()` | `peek` и `next_if` — заглянуть, не забирая | `rle` |
| `skip(n)`, `take(n)`, `step_by(n)` | по счёту | `decimate_rev` |
| `rev()` | с конца, если итератор умеет | `decimate_rev` |
| `cycle()` | по кругу без конца | `test_pattern` |
| `inspect(f)` | вызвать `f(&x)` и отдать `x` дальше | отладка, тесты |
| `copied()`, `cloned()` | `&T` → `T` | везде |
| `fuse()` | после первого `None` — только `None` | раздел [13.4](04-custom.md) |

`windows(n)`, `chunks(n)` и `chunks_exact(n)` — методы среза, а не
итератора: им нужно знать, где элементы лежат в памяти, чтобы отдавать
куски срезами без копирования.

## zip

`zip` идёт по двум последовательностям сразу и останавливается на конце
более короткой. Номер первого байта, в котором принятый кадр разошёлся
с ожидаемым:

```rust
{{#include ../../code/ch13/src/adapters.rs:zip}}
```

`mismatches` пишет номера несовпавших байтов в буфер вызывающего, и
`zip` с `out.iter_mut()` сам ограничивает запись его длиной: если
несовпадений больше, чем места, лишние не пишутся, а `count()` говорит,
сколько записано. Индекса, который можно вывести за буфер, в функции
нет. Обратная сторона той же остановки — ловушка из раздела
[13.6](06-tricks.md): несовпадение длин `zip` не замечает.

## chain

CRC кадра из главы 6 считается по заголовку без поля CRC и по нагрузке,
а в буфере между ними лежит само поле CRC. `chain` склеивает два
участка в одну последовательность без копирования:

```rust
{{#include ../../code/ch13/src/adapters.rs:chain}}
```

`crc16` берёт `impl IntoIterator<Item = &u8>`, поэтому принимает и
`&[u8]`, и `&[u8; N]`, и цепочку. Для кадра измерения из тестов проекта
`frame_crc` даёт 0x73e5 — то самое значение, что стоит в байтах 6 и 7
кадра. Внутри `chain` хранит оба итератора и на каждом шаге проверяет,
не кончился ли первый; во что это обходится и как этого избежать —
раздел [13.5](05-codegen.md).

## flat_map и scan

`flat_map` применяет функцию, которая возвращает итератор (или что
угодно с `IntoIterator`), и отдаёт его элементы подряд. Каждый байт
шестнадцатеричного дампа — две цифры:

```rust
{{#include ../../code/ch13/src/adapters.rs:flat_map}}
```

`hex(&[0xa5, 0x01, 0xff])` — `"a501ff"`. Массив `[u8; 2]` реализует
`IntoIterator` по значению, поэтому замыкание может вернуть его прямо,
без вектора на каждый байт.

`scan` — свёртка, которая отдаёт промежуточные значения и может
оборвать поток. Датчик шлёт первое значение целиком, а дальше разности,
и `scan` восстанавливает значения, неся текущее как состояние:

```rust
{{#include ../../code/ch13/src/adapters.rs:scan}}
```

`undelta(100, &[2, -1, 5])` даёт 100, 102, 101, 106. На переполнении
`checked_add` возвращает `None`, оператор `?` возвращает его из
замыкания, и поток кончается: `undelta(32766, &[1, 1, -5])` даёт 32766
и 32767, а не мусор после переноса. `iter::once(first)` — итератор
из одного элемента; с `chain` он ставит первое значение перед
остальными.

## take_while, skip_while, map_while

Строка с UART: преамбула из байтов 0x55, по которой приёмник
подстраивает скорость, затем текст до нуля:

```rust
{{#include ../../code/ch13/src/adapters.rs:while}}
```

`payload(b"\x55\x55\x55T=21\0junk")` даёт `T=21`. `skip_while`
пропускает, пока условие истинно, и после первого ложного отдаёт всё
подряд, даже если дальше снова встретится 0x55. `take_while` отдаёт,
пока условие истинно, и на первом ложном кончается. `map_while`
совмещает `map` и `take_while`: замыкание возвращает `Option`, и первый
`None` заканчивает поток. `leading_number(b"1234,56")` — 1234.

У `take_while` есть свойство, о котором легко забыть: чтобы узнать, что
условие ложно, он забирает этот элемент из исходного итератора, и тот
пропадает. Об этом — раздел [13.6](06-tricks.md).

## peekable

`peekable` добавляет итератору `peek` — посмотреть следующий элемент, не
забирая его, — и `next_if`/`next_if_eq` — забрать, только если он
подходит. Кодирование длинами серий:

```rust
{{#include ../../code/ch13/src/adapters.rs:peekable}}
```

`rle(&[1, 1, 1, 0, 0, 7], …)` записывает `(1, 3), (0, 2), (7, 1)`.
Внутренний цикл забирает байты, пока они равны первому, и первый
неравный остаётся в итераторе для следующей серии. Без `peekable`
пришлось бы держать «лишний» байт в отдельной переменной — то, что
`Peekable` и хранит в своём поле.

## windows, chunks, chunks_exact

`windows(n)` отдаёт перекрывающиеся окна, `chunks(n)` —
неперекрывающиеся куски, последний может быть короче, `chunks_exact(n)`
— куски ровно по `n`, а неполный хвост отдаёт отдельно:

```rust
{{#include ../../code/ch13/src/adapters.rs:windows}}
```

`moving_avg4(&[4, 8, 12, 16, 20])` — 10 и 14: окон два, и каждое —
срез исходного буфера. Из байтов `34 12 cd ab ee` `words_le` собирает
0x1234 и 0xabcd, а `ee` возвращает хвостом. `c[0]` и `c[1]` не выйдут
за кусок: у `chunks_exact(2)` он всегда из двух байт. Почему `chunks_exact` к тому же быстрее `chunks` — раздел
[13.5](05-codegen.md).

## rev, step_by, cycle


`decimate_rev` для отсчётов 0…9 даёт 9, 5, 1: с конца, каждый
четвёртый. `test_pattern(5)` — 0xAA, 0x55, 0xAA, 0x55, 0xAA:

элементов; `cycle().sum()` не вернётся никогда.
