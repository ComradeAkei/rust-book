# 27.4. Периферия во владении

## Peripherals::take()

PAC из раздела [27.3](03-pac.md) даёт доступ к регистрам, но не решает,
*кто* к ним обращается. Это решает одно значение — `Peripherals`,
структура со всеми блоками кристалла:

```rust
{{#include ../../firmware/ch27-periph/src/main.rs:take}}
```

```console
$ cd firmware && cargo run --release -p ch27-periph
UART0: 115200 бод при 12 МГц, IBRD 6, FBRD 33
Peripherals::take() второй раз: None
размер Peripherals 0 байт, PF0<Output> 0 байт
PF0: после set_high true, после toggle низкий true
74HC595 <- 0xa5; выводы PB2..PB0 после write: 001
delay_us(100): прошло не меньше 1200 тактов: true
```

Второй `take()` вернул `None`. svd2rust сгенерировал его так:

```rust,ignore
static mut DEVICE_PERIPHERALS: bool = false;

pub fn take() -> Option<Self> {
    critical_section::with(|_| {
        if unsafe { DEVICE_PERIPHERALS } {
            return None;
        }
        Some(unsafe { Peripherals::steal() })
    })
}
```

Флаг «уже выдано» — `static mut`, проверка и запись — в критической
секции: иначе `main` и обработчик прерывания могли бы оба увидеть
`false` и получить по копии. Критическую секцию даёт крейт
critical-section, а реализацию для одного ядра — запрет прерываний —
возможность `critical-section-single-core` крейта cortex-m (раздел
[27.6](06-interrupts.md)).

Сама структура весит ноль байт: каждый блок в ней — `Periph` нулевого
размера с адресом в типе. Владеть значением нулевого размера — значит
владеть *правом* обращаться к регистрам, и это право можно передать
функции, положить в структуру драйвера или поглотить. В машинном коде от
него ничего не остаётся.

`steal()` выдаёт копию без проверки и поэтому `unsafe`: две копии одного
UART у двух драйверов — гонка, которую компилятор уже не видит. Тот же
обход — `Uart0::ptr()`, [сырой указатель][g-raw-pointer] на блок; им пользуются там, где
владелец заведомо не мешает, — обработчик прерывания UART0 в задаче
[27.C](10-tasks.md) читает DR через него.

## Порт делится на выводы

Порт GPIO — восемь выводов, и у каждого свой владелец: светодиод,
кнопка, UART. HAL делит значение порта на восемь значений:

```rust
{{#include ../../code/ch27-hal/src/gpio.rs:port}}
```

`split` принимает порт по значению: `dp.gpiof` поглощается, и второй
раз его не разделить. Каждый вывод `Parts` — отдельное поле, его можно
забрать из структуры и отдать кому угодно.

переведённых в альтернативную функцию.

## Смена режима без чтения-изменения-записи

Режим вывода — три бита в трёх регистрах порта: AFSEL (альтернативная
функция), DIR (выход) и DEN (цифровой вход-выход). Бит вывода N — бит N
каждого регистра. В C смена режима — `GPIOF->DIR |= 1 << n;`: чтение,
`or`, запись. Если между чтением и записью прерывание меняет режим
другого вывода того же порта, его изменение пропадёт — запись вернёт
старое значение регистра.

Cortex-M3 умеет писать один бит одной транзакцией шины. Первый мегабайт
SRAM (с 0x2000_0000) и первый мегабайт периферии (с 0x4000_0000)
отражены в области-псевдониме **bit-band**: каждому биту — своё слово.
Запись 1 в слово ставит бит, 0 — сбрасывает, остальные биты того же
регистра не меняются.

```rust
{{#include ../../code/ch27/src/bitband.rs:alias}}
```

Бит 3 регистра DIR порта F (0x4002_5400) — слово 0x424A_800C: так
проверяет тест `aliases`. Вывод HAL пишет каждый из трёх битов режима
так:

```rust
{{#include ../../code/ch27-hal/src/gpio.rs:bitband}}
```

Уровень вывода — тоже без чтения: у регистра DATA порта Stellaris биты
2–9 *адреса* — маска. Запись по адресу `DATA + (1 << N) * 4` меняет
только вывод N, остальные выводы порта она не трогает, поэтому
`set_high` — это `data(1 << N).write(…)`, а не `modify`.

## Во что это компилируется

Одна и та же запись — PF0 в высокий уровень — тремя способами, с
[неискажёнными][g-mangling] именами, чтобы найти их в ассемблере:

```rust
{{#include ../../code/ch27-hal/src/probe.rs:three}}
```

Тест `asm.rs` собирает HAL с возможностью `probe` под Cortex-M3 без [LTO][g-lto],
как библиотеку, и сравнивает:

```rust
{{#include ../../code/ch27-hal/tests/asm.rs:same}}
```

```text
ch27_hal_set_high:
	push	{r7, lr}
	mov	r7, sp
	movw	r0, #20484
	movs	r1, #1
	movt	r0, #16386
	str	r1, [r0]
	pop	{r7, pc}
```

`movw` и `movt` собирают адрес 0x4002_5004 (20484 = 0x5004, 16386 =
0x4002), `str` пишет единицу. Тело `ch27_pac_set_high` — те же
инструкции, а `ch27_raw_set_high` в ассемблере вовсе нет — есть строка
`ch27_raw_set_high = ch27_pac_set_high`: LLVM увидел два одинаковых
тела и оставил одно. Ссылка `&mut PF0<Output>` в аргументе HAL-версии
ничего не стоит: у значения нулевого размера нет адреса, который нужно
читать, и r0 на входе не используется.

Смена режима — три записи в псевдонимы:

```text
ch27_hal_into_output:
	push	{r7, lr}
	mov	r7, sp
	movw	r0, #32768
	movs	r1, #0
	movt	r0, #16970
	str.w	r1, [r0, #1024]
	movs	r1, #1
	str	r1, [r0]
	movw	r0, #41856
	movt	r0, #16970
	str	r1, [r0]
	pop	{r7, pc}
```

0x424A_8000 — псевдоним бита 0 DIR, плюс 1024 — бита 0 AFSEL (смещение
регистра 0x420 против 0x400, разница 0x20 байт — 0x400 в псевдонимах),
0x424A_A380 — бита 0 DEN. Функция `alias` с её `match` и `assert!`
встроилась и свернулась в константы: в коде нет ни её вызова, ни
проверок. Это работа оптимизатора, а не вычисление при компиляции из
главы 25: аргумент `alias` здесь — указатель на регистр, а не
константа, и известен он становится только после встраивания. Тест
`rustc_into_output_is_three_bitband_stores` следит, чтобы так и
оставалось.

<div class="box trap">

**Ловушка.** Первая версия HAL давала здесь три вызова `bl` —
`bitband::alias` не встраивалась. Обычная, не [обобщённая][g-generic] функция
другого крейта без LTO доступна только как вызов: тело для встраивания
rustc кладёт в [метаданные крейта][g-crate-metadata] лишь у обобщённых функций, у функций с
`#[inline]` и у самых маленьких, которые он признаёт встраиваемыми сам.
`alias` с её `match` и паниками к маленьким не относится. Поэтому она
помечена `#[inline]`, а тест ассемблера ловит, если пометку уберут.
Release-сборки прошивок книги идут с LTO, и в них разница исчезает, —
но HAL пишут для всех сборок, а не только для сборок с LTO.

</div>

<div class="box c">

**Как в C.** Bit-band в C — макрос с той же формулой, что в `alias`;
такие макросы есть в заголовках многих производителей и в примерах ARM.
Библиотека TI для этих кристаллов (StellarisWare, ныне TivaWare) пишет
вывод по замаскированному адресу DATA, как `set_high`. Отличие —
не в машинном коде, он тот же, а в том, что `GPIOF->DIR |= 1;` из любого
файла прошивки в Rust без `unsafe` написать нельзя: регистры порта у
владельца, а вывод — у своего драйвера.

</div>

<div class="box hood">

**Под капотом.** Bit-band — возможность Cortex-M3 и M4; у Cortex-M0, M0+,
M7 и M33 его нет. HAL для таких ядер обходится без чтения-изменения-
записи по-другому, если это умеет кристалл: у STM32 — регистр BSRR, в
котором одни биты ставят уровень, другие сбрасывают; у nRF — пары
регистров OUTSET и OUTCLR. Где нет ни того, ни другого, остаётся
критическая секция вокруг `modify`.

</div>

<div class="box check">

**Проверь себя.** Почему `split` принимает `&mut Sysctl`, а не
