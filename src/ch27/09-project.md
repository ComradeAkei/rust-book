# 27.9. Сквозной проект: станция на HAL

В главе 26 станция кодировала кадры из `sample` — функции, которая
выдумывала отсчёты, — и сама же их разбирала (раздел
[26.7](../ch26/07-project.md)). Шаг главы 27 — станция, которая
измеряет: таймер запускает АЦП, отсчёт приходит прерыванием, кадры
уходят в UART0, а разбирает их другая программа — тест на хосте.

## Схема

```text
TIMER0, 10 мс ──(TAOTE)──▶ АЦП, последовательность 3
                              │ выборка закончилась
                              ▼
                       прерывание ADC0SS3 ──▶ Spsc<Sample, 8>
                                                    │
main: pop ─▶ Measurement ─▶ encode ─▶ UART0 ─▶ файл QEMU ─▶ тест на хосте
```

Таймер запускает АЦП сам, без программы: бит TAOTE в его регистре CTL
— «запуск АЦП по каждому периоду». Программа узнаёт об отсчёте из
прерывания, а между обработчиком и `main` — очередь SPSC из главы 21.

```rust
{{#include ../../firmware/ch27-station/src/main.rs:queue}}
```

АЦП нужен только обработчику — чтобы забрать отсчёт и сбросить запрос, —
но настраивает его `main`: `Mutex<RefCell<Option<Adc>>>`, как таймер в
разделе [27.6](06-interrupts.md). Отсчёты идут через очередь, а не через
`Mutex`: писатель один, читатель один, и `Spsc` из главы 21 обходится
атомарными `load` и `store`, без критической секции и без запрета
прерываний. Если `main` не успевает, очередь переполняется, и отсчёт
считается в `DROPPED`, а не теряется молча.

Пустая очередь — `wfi` до следующего прерывания. Здесь есть окно
пропущенного пробуждения из раздела [27.6](06-interrupts.md): отсчёт,
пришедший между пустым `pop` и `wfi`, пролежит в очереди до следующего
прерывания. Здесь это допустимо, и вот почему. Следующее прерывание
придёт не позже чем через период, через 10 мс, — АЦП запускает таймер,
а не программа. Отсчёт не теряется, а только ждёт: в очереди ему есть
место. Задержка кадра на один период для станции с периодом 10 мс
ничего не меняет. Консоль из задачи [27.C](10-tasks.md), где следующего
байта может не быть вовсе, закрывает окно запретом прерываний.

## Запуск

UART0 выдаёт двоичные кадры, и смешивать их с текстом нельзя. Отчёт
станция печатает через semihosting, а UART0 QEMU пишет в файл:

```console
$ cd firmware && cargo build --release -p ch27-station
$ qemu-system-arm -cpu cortex-m3 -machine lm3s6965evb -nographic \
    -monitor none -semihosting-config enable=on,target=native \
    -serial file:frames.bin -kernel target/thumbv7m-none-eabi/release/ch27-station
станция: 20 кадров измерений, 360 байт в UART0, 1500..1520 мВ
отсчётов АЦП 20, потеряно в очереди 0
$ od -An -tx1 -N18 frames.bin
 a5 01 01 00 0a 00 c2 a7 01 00 00 00 00 00 dc 05
 00 00
```

Первый кадр по байтам:

| Байты | Поле | Значение |
|---|---|---|
| `a5` | `magic` | 0xA5 |
| `01` | `version` | 1 |
| `01` | `kind` | измерение |
| `00` | `seq` | 0 |
| `0a 00` | `len` | 10 байт полезной нагрузки |
| `c2 a7` | `crc` | CRC-16/CCITT-FALSE |
| `01 00` | `sensor` | 1 |
| `00 00 00 00` | `timestamp_ms` | 0 |
| `dc 05 00 00` | `value` | 1500 мВ |

Настоящего входа у модели АЦП в QEMU нет: она выдаёт 0x200 плюс
немного псевдослучайного шума, отсчёты от 512 до 519 из 1023. При
опорном напряжении 3 В это 1500–1520 мВ — так и написано в отчёте.

`stats` из раздела [13.8](../ch13/08-project.md) считает кадры по видам,
ошибки CRC и мусор между кадрами: 20 измерений, ни одной ошибки, ни байта
мусора. Дальше — каждый кадр: смещение 18·i, номер i, датчик 1, время 10·i
мс и значение в пределах шума АЦП. Тест собирает прошивку закреплённым
cargo, запускает QEMU с минутным пределом и в CI выполняется в задании
Cortex-M отдельным шагом.

## Что получилось

```console
$ llvm-size target/thumbv7m-none-eabi/release/ch27-station
   text	   data	    bss	    dec	    hex	filename
   4248	      0	     96	   4344	   10f8	target/thumbv7m-none-eabi/release/ch27-station
```

**96 байт ОЗУ.** 72 из них — очередь `Spsc<Sample, 8>`, остальное —
`ADC`, два счётчика, флаг `Peripherals` и `HSTDOUT` semihosting.

**Таблица CRC, которой нет в исходнике.** В `llvm-nm` прошивки есть
`.L.crctable.64` на 512 байт: кодер зовёт побитовую `crc16`, а LLVM при
`opt-level = 3` узнал цикл и подставил табличный алгоритм — то самое
наблюдение из раздела [25.7](../ch25/07-project.md), теперь на прошивке.

**Драйверы — нулевого размера.** `Serial`, `Timer0`, `Adc`, выводы PA0 и
PA1 — значения без полей или с полями нулевого размера; в ОЗУ от них
только признак `Option` и счётчик `RefCell` у `ADC`.
