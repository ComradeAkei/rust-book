# 27. Cortex-M на Rust

## Мотивирующая проблема

Прошивка на C для Cortex-M начинается с чужого кода. Производитель
кристалла даёт заголовок на десятки тысяч строк — структуры регистров и
макросы битов, сгенерированные из описания кристалла, — и [HAL][g-hal] поверх
него. ARM даёт *CMSIS* (Common Microcontroller Software Interface
Standard): `NVIC_EnableIRQ`, `__disable_irq`, `SysTick_Config`. Всё это
работает, и всё это держится на соглашениях, которые компилятор не
проверяет:

- **периферия общая.** `GPIOF->DIR |= 1;` можно написать в любом файле
  прошивки. Два драйвера, которые настраивают один вывод по-разному,
  компилируются и компонуются, а спорят уже на плате;
- **режим вывода — в голове программиста.** Вывод, настроенный на вход,
  можно «включить» записью в регистр данных; [UART][g-uart] на выводах, которые
  никто не перевёл в альтернативную функцию, молчит;
- **данные, общие с обработчиком прерывания, — `volatile` глобальные
  переменные.** `volatile` не делает [чтение-изменение-запись][g-rmw] атомарной
  и не защищает структуру из двух полей, а забытое
  `__disable_irq()` проявляется раз в сутки;
- **обработчик называется по имени из таблицы векторов.** Опечатка в
  `TIMER0A_Handler` — и прерывание уходит в `Default_Handler`, бесконечный
  цикл, без единого предупреждения;
- **сбой — это HardFault без подробностей.** Что именно случилось, знают
  регистры CFSR и HFSR, но читать их надо уметь, а обработчик по
  умолчанию просто зависает.

## Что делает Rust

Rust не меняет процессор: те же регистры, те же исключения, тот же
[NVIC][g-nvic]. Меняется то, что о них знает компилятор.

- **Периферия — значение.** `Peripherals::take()` отдаёт её один раз;
  второй вызов — `None`. Драйвер, которому нужен UART, принимает его
  во [владение][g-ownership], и второго владельца у UART нет.
- **Режим вывода — тип.** `PF0<Output>` и `PF0<Input>` — разные [типы
  нулевого размера][g-zst]: у входа нет `set_high`, а UART принимает только
  выводы в режиме периферии. Ошибка — при компиляции, а в машинном коде
  от типов не остаётся ни байта.
- **Общие данные — через типы с правилами.** `Mutex<RefCell<T>>` из
  critical-section даёт доступ только внутри критической секции, [атомики][g-atomic]
  — без неё; [RTIC][g-rtic] выводит из объявленных приоритетов, где нужна
  блокировка, и делает её записью в [BASEPRI][g-basepri].
- **Имя обработчика проверяет компилятор.** `#[interrupt] fn TIMER0A()` —
  это вариант перечисления прерываний из [PAC][g-pac]; опечатка — ошибка сборки.
- **Регистры сбоев разбирает код.** Обработчик HardFault получает
  сохранённый кадр как структуру, CFSR раскладывается на биты в
  нескольких строках.

Глава идёт снизу вверх: ядро и исключения, NVIC, PAC из описания
кристалла, владение периферией, HAL и драйверы на [embedded-hal][g-embedded-hal] 1.0,
прерывания и общее состояние, сбои и защита стека, RTIC. Всё
выполняется в QEMU на машине lm3s6965evb — Stellaris LM3S6965, Cortex-M3
на 12 МГц.

## Код главы

Разбор исключений, приоритетов, адресов [bit-band][g-bit-band], регистров [MPU][g-mpu] и
драйвер 74HC595 — в `code/ch27`, библиотеке [`no_std`][g-no-std], которую тесты
проверяют на [хосте][g-host]. PAC кристалла — `code/ch27-pac`, его строит
svd2rust по `code/ch27/svd/lm3s6965.svd`. Маленький HAL —
`code/ch27-hal`. Прошивки разделов — `firmware/ch27-*`, задачи — в
`exercises/ch27` и `solutions/ch27`, прошивки задач — `firmware/ch27-tasks`.

```console
$ cargo test -p ch27 -p ch27-hal        # разбор, драйвер, ассемблер HAL, ошибки типов
$ cargo test -p ch27-solutions          # задачи A–D
$ cd firmware && cargo run --release -p ch27-core      # раздел 27.1 в QEMU
$ cd firmware && cargo run --release -p ch27-rtic      # раздел 27.8
$ cargo test -p ch27 --test station -- --ignored       # проект: станция в QEMU, кадры на хосте
```

Прошивки этой главы — только для Cortex-M3 и старше: им нужны BASEPRI,
MPU и регистры сбоев [ARMv7-M][g-armv7m], которых у Cortex-M0 нет. Вывод снят с
rustc 1.97.0 и QEMU 8.2.2, ассемблер — под thumbv7m-none-eabi; тесты
`rustc_*` сверяют его с закреплённым компилятором при каждом прогоне.
