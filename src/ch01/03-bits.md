# 1.3. Битовые методы и инструкции

У целых типов есть методы для операций, которые в C пишут через
встроенные функции компилятора (`__builtin_clz`, `__builtin_popcount`) или
через макросы из сдвигов и масок:

```rust
{{#include ../../code/ch01/src/bits.rs:bits}}
```

| Метод | Что считает | `0x0000_00F0_u32` |
|---|---|---|
| `leading_zeros` | нули слева до первой единицы | 24 |
| `trailing_zeros` | нули справа | 4 |
| `count_ones` | число единиц | 4 |
| `swap_bytes` | обратный порядок байт | `0xF000_0000` |
| `reverse_bits` | обратный порядок битов | `0x0F00_0000` |
| `rotate_left(n)` | циклический сдвиг | `rotate_left(28)` → `0x0000_000F` |
| `checked_ilog2` | номер старшей единицы | `Some(7)` |

Для нуля ответ определён всегда: `0_u32.leading_zeros()` равно 32,
`0_u32.count_ones()` равно 0. Единственное исключение — логарифм, у нуля
его нет:

## Одна инструкция или десять

Во что превращается каждый метод, зависит от того, какие инструкции
обещает цель. Базовый уровень `x86_64-unknown-linux-gnu` — процессор 2003
года без `lzcnt` и `popcnt`, и без указаний компилятор не вправе ими
пользоваться:

```text
$ cargo asm -p ch01 --lib ch01_clz
ch01_clz:
	mov eax, 63
	bsr eax, edi
	xor eax, 31
	ret

$ cargo asm -p ch01 --lib --target-cpu=x86-64-v3 ch01_clz
ch01_clz:
	lzcnt eax, edi
	ret
```

`bsr` (bit scan reverse) возвращает номер старшей единицы, а не число
нулей перед ней, отсюда `xor eax, 31` (для 0..31 это то же, что 31 − x).
Для нулевого источника Intel называет результат `bsr` неопределённым, а
AMD обещает не трогать приёмник. Так ведут себя и процессоры Intel, и LLVM
этим пользуется: заранее кладёт в `eax` 63, и для нуля получается
`63 ^ 31 = 32`. На уровне `x86-64-v3` (Haswell и новее) есть `lzcnt`,
которая сразу считает нули и для нуля даёт 32.

С подсчётом единиц разница больше:

```text
$ cargo asm -p ch01 --lib ch01_popcount
ch01_popcount:
	mov eax, edi
	shr eax
	and eax, 1431655765
	sub edi, eax
	mov eax, edi
	and eax, 858993459
	shr edi, 2
	and edi, 858993459
	add edi, eax
	mov eax, edi
	shr eax, 4
	add eax, edi
	and eax, 252645135
	imul eax, eax, 16843009
	shr eax, 24
	ret

$ cargo asm -p ch01 --lib --target-cpu=x86-64-v2 ch01_popcount
ch01_popcount:
	popcnt eax, edi
	ret
```

Длинный вариант — классический алгоритм SWAR (SIMD within a register):
константы `0x5555_5555`, `0x3333_3333` и `0x0F0F_0F0F` складывают биты
парами, четвёрками и байтами, а умножение на `0x0101_0101` собирает сумму
четырёх байт в старшем. Пятнадцать инструкций без ветвлений и без
обращений к памяти.

На ARM картина другая: `clz` есть с ARMv5, а подсчёта единиц нет ни в
ARMv7-M, ни в ARMv6-M.

```text
$ cargo asm -p ch01 --lib --target thumbv7m-none-eabi ch01_clz
ch01_clz:
	push {r7, lr}
	mov r7, sp
	clz r0, r0
	pop {r7, pc}

$ cargo asm -p ch01 --lib --target thumbv6m-none-eabi ch01_clz
ch01_clz:
	push {r7, lr}
	add r7, sp, #0
	cmp r0, #0
	beq .LBB14_2
	bl __clzsi2
	pop {r7, pc}
.LBB14_2:
	movs r0, #32
	pop {r7, pc}
```

`clz` на ARM определена для нуля и даёт 32. У Cortex-M0 (ARMv6-M) этой
инструкции нет, и компилятор вызывает `__clzsi2` из `compiler_builtins`,
а случай нуля обрабатывает сам до вызова. `count_ones` на всех трёх ядрах
Cortex-M компилируется в тот же SWAR, что и на базовом x86_64, только
константы на M0 грузятся из памяти рядом с кодом (`ldr r2, .LCPI24_0`):
`movs` на ARMv6-M умеет только 8-битные непосредственные значения.

Остальные методы из листинга — одна инструкция на любой из целей:

| Метод | x86_64 | Cortex-M0, M3, M4F |
|---|---|---|
| `swap_bytes` | `bswap eax` | `rev r0, r0` |
| `rotate_left(n)` | `rol eax, cl` | `rsbs r1, r1, #0` + `rors r0, r1` |

ARM умеет вращать только вправо, и вращение влево на n — это вращение
вправо на 32 − n, то есть на −n по модулю 32: `rsbs` вычисляет 0 − n,
а `rors` берёт из него младшие 5 бит.

<div class="box c">

**Как в C.** `__builtin_clz(0)` и `__builtin_ctz(0)` — неопределённое
поведение, и UBSan сообщает о нём как о `passing zero to clz()` (пример
есть в приложении A). Компилятор пользуется этим: на x86_64 без `lzcnt`
он выдаёт голые `bsr` и `xor`, и для нуля функция возвращает мусор. Стандарт
C23 добавил `<stdbit.h>` с функциями `stdc_leading_zeros` и подобными,
определёнными для нуля; в glibc 2.39 они есть, и
`stdc_leading_zeros_ui(0)` даёт 32. Методы Rust определены для всех входов
с самого начала, а цена этого на ARM нулевая, на x86_64 — одна `mov`.

</div>

<div class="box trick">

**Трюк: `target-cpu` для хоста.** Если программа запускается только на
вашей машине, `RUSTFLAGS="-C target-cpu=native"` или строка
`rustflags = ["-C", "target-cpu=native"]` в `.cargo/config.toml` разрешают
компилятору все инструкции процессора, на котором идёт сборка: `lzcnt`,
`popcnt`, BMI2, AVX2. Для программы, которую получат другие, выбирайте
уровень из списка `x86-64-v2`, `x86-64-v3`, `x86-64-v4`: на процессоре без
нужных инструкций она упадёт с SIGILL. Для Cortex-M набор инструкций уже
задан целью: `thumbv7em` гарантирует `clz` и `qadd`,
`thumbv7em-none-eabihf` — ещё и FPU одинарной точности, `thumbv6m` — ничего
из этого.

</div>
