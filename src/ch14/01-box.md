# 14.1. Box

`Box<T>` — указатель на значение в куче и единственный его владелец.
`Box::new(x)` просит у распределителя блок размером с `T`, перемещает
туда `x` и возвращает указатель. Когда `Box` уничтожается, сначала
уничтожается значение, затем блок возвращается распределителю. В C это
`malloc`, инициализация и `free`, но `free` вставляет компилятор, а
владелец у блока всегда ровно один: `Box` перемещается, как любое
значение без `Copy` (глава 3), и после перемещения старая переменная
недоступна.

## Сколько места занимает Box

Документация `std` гарантирует раскладку `Box`, и тест
`guaranteed_box_sizes` в `code/ch14/src/boxes.rs` её проверяет:

| Тип | Размер на x86-64 | Почему |
|---|---|---|
| `Box<u64>` | 8 | адрес блока |
| `Option<Box<u64>>` | 8 | `None` — нулевой адрес, `Box` нулевым не бывает (глава 6) |
| `Box<[u8]>`, `Box<str>` | 16 | толстый указатель: адрес и длина |
| `Box<dyn Fn()>` | 16 | адрес и таблица методов (глава 11) |

Распределитель видит только размер и выравнивание значения. Тест
`box_allocates_exactly_the_value` в `code/ch14/tests/alloc.rs` ставит
распределитель-счётчик, который записывает каждое обращение:
`Box::new(5u32)` — один `alloc` на 4 байта с выравниванием 4,
`Box::new([0u64; 3])` — 24 байта с выравниванием 8. `Box<dyn Debug>` из
`u16` просит 2 байта: таблица методов лежит в статической памяти
программы, её не выделяют. А `Box::new(())` не обращается к
распределителю вовсе: у типа нулевого размера нечего хранить, и `Box`
держит висячий, но выровненный адрес.

<div class="box ref">

**Справка: куча на Cortex-M.** Распределитель `Box` в Linux — `malloc`
из glibc, который берёт память у ядра через `brk` и `mmap`. На
микроконтроллере ядра нет, и `alloc` — крейт с `Box`, `Vec` и `Rc` —
работает, только если программа объявила `#[global_allocator]`:
обычно это область ОЗУ между `.bss` и стеком, отданная крейту вроде
`embedded-alloc`. Без распределителя прошивка с `Box` не соберётся.
Многие прошивки обходятся без кучи совсем, и примеры этой главы
собираются для Cortex-M в двух вариантах: с `alloc` и без, где остаются
только ячейки из раздела 14.5. Свой распределитель появится в главе 15.

</div>

## Рекурсивные типы

Условие тревоги станции — дерево выражений над показаниями каналов.
Узел `Add` содержит два узла того же типа:

```rust
{{#include ../../code/ch14/src/boxes.rs:expr}}
```

Без указателя у такого типа нет размера: `Expr` содержит `Expr`, который
содержит `Expr`, и так без конца. Компилятор отвергает тип и подсказывает,
что делать:

```console
error[E0072]: recursive type `Expr` has infinite size
 --> src/main.rs:1:1
  |
1 | enum Expr {
  | ^^^^^^^^^
2 |     Const(i32),
3 |     Add(Expr, Expr),
  |         ---- recursive without indirection
  |
help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
  |
3 |     Add(Box<Expr>, Expr),
  |         ++++    +
```

Подсказка правит только первое поле: второй `Expr` компилятор покажет
следующей ошибкой. С `Box` в обоих полях размер `Expr` — тег и два
указателя, 24 байта на x86-64 (наблюдение `observed_expr_size`: порядок
и упаковку полей `repr(Rust)` не обещает). Само дерево строится из
`Box::new`:

```rust
{{#include ../../code/ch14/src/boxes.rs:alarm}}
```

В C это `struct expr { int kind; struct expr *a, *b; }` и рекурсивная
функция освобождения, которую легко забыть или вызвать дважды. Здесь
деструктор `Expr` уничтожает оба `Box`, а они — свои поддеревья:
освобождение рекурсивно и написано компилятором. Для очень глубоких
деревьев — длинных списков — рекурсия может переполнить стек; эта
ловушка вернётся в задаче [14.C](09-tasks.md#c-двусвязный-список-дважды).

## Выход значения из Box

`Box` — единственный умный указатель, из которого значение можно
переместить разыменованием:

```rust
{{#include ../../code/ch14/src/boxes.rs:unbox}}
```

`*b` перемещает строку, а блок `Box` освобождается. Тест
`unbox_moves_string_out` проверяет, что буфер строки не копировался:
переместились три слова заголовка `String`. С `Rc` так нельзя —
значением владеют все клоны сразу:

```console
error[E0507]: cannot move out of an `Rc`
 --> src/main.rs:3:5
  |
3 |     *r
  |     ^^ move occurs because value has type `String`, which does not implement the `Copy` trait
```

Для `Rc` есть `try_unwrap` и `into_inner`, которые отдают значение,
только если ссылка последняя (раздел [14.3](03-rc.md)).

## Box::leak, into_raw и from_raw

Конфигурацию, которую прочли при старте и которая нужна до конца
работы, удобно держать по ссылке `'static`. `Box::leak` превращает
`Box<T>` в `&'static mut T` и забывает про освобождение:

```rust
{{#include ../../code/ch14/src/boxes.rs:leak}}
```

Это честная утечка: блок не вернётся распределителю никогда. Для
данных на всё время работы это ровно то, что нужно, и в прошивке, где
программа не завершается, так обычно и делают.

Через границу, которая знает только адреса, — в C, в контекст
прерывания, в дескриптор DMA — владение передают сырым указателем:

```rust
{{#include ../../code/ch14/src/boxes.rs:raw}}
```

`into_raw` отдаёт адрес и не вызывает деструктор: теперь за значение
отвечает тот, кто держит указатель. `from_raw` возвращает владение, и
вызвать его можно ровно один раз — второй `from_raw` с тем же адресом
даёт два `Box` на один блок и двойное освобождение. Без Miri программа
с такой ошибкой у нас падала с SIGSEGV в отладочной сборке и с SIGILL в
release. Miri ловит её раньше, уже при создании второго `Box`: висячий
`Box` — недопустимое значение типа, даже если его ни разу не
разыменовали:

```rust
{{#include ../../code/ch14/tests/ub.rs:double_from_raw}}
```

```console
$ cargo +nightly miri test -p ch14 --test ub -- --ignored --exact double_from_raw
error: Undefined Behavior: constructing invalid value of type std::boxed::Box<ch14::boxes::Config>: encountered a dangling box (use-after-free)
…
             2: ch14::boxes::from_raw
                 at code/ch14/src/boxes.rs:110:14: 110:30
             3: double_from_raw
                 at code/ch14/tests/ub.rs:45:19: 45:30
```

## Большой буфер сразу в куче

Буфер на 16 МиБ — вдвое больше стека главного потока в Linux:

```rust
{{#include ../../code/ch14/src/boxes.rs:big}}
```

Естественная запись `Box::new([0; BIG])` в отладочной сборке сначала
строит массив на стеке, как аргумент функции, и только потом копирует в
кучу. Пример `code/ch14/examples/bigbox.rs` проверяет все три способа:

```console
$ cargo run -p ch14 --example bigbox new
thread 'main' (19434) has overflowed its stack
fatal runtime error: stack overflow, aborting
$ cargo run --release -p ch14 --example bigbox new
new: 16 МиБ в куче, сумма 0
$ cargo run -p ch14 --example bigbox zeroed
zeroed: 16 МиБ в куче, сумма 0
```

В release массива на стеке нет вовсе. LLVM видит, что выделенный блок
сразу заполняют нулями, и заменяет выделение и заполнение одним
вызовом распределителя, который отдаёт обнулённую память:

```console
$ cargo asm -p ch14 --example bigbox --simplify bigbox::by_new
bigbox::by_new:
	push rax
	call qword ptr [rip + __rustc::__rust_no_alloc_shim_is_unstable_v2@GOTPCREL]
	mov edi, 16777216
	mov esi, 1
	call qword ptr [rip + __rustc::__rust_alloc_zeroed@GOTPCREL]
	test rax, rax
	je .LBB7_2
	pop rcx
	ret
.LBB7_2:
	mov edi, 1
	mov esi, 16777216
	call qword ptr [rip + alloc::alloc::handle_alloc_error@GOTPCREL]
```

Это оптимизация, а не обещание языка. Массив, который строится
сложнее, остаётся на стеке и в release: режим `seq` того же примера
строит 16 МиБ через `Box::new(array::from_fn(|i| i as u32))` и
переполняет стек в обеих сборках (тест `cargo_observed_bigbox_from_fn`).

`Box::new_zeroed` делает тот же вызов `__rust_alloc_zeroed` явно, в
любой сборке. Системный распределитель отвечает на него `calloc`, а
glibc для больших блоков — свежими страницами `mmap`, которые ядро и
так выдаёт нулевыми: обнулять ничего не приходится. `vec![0; n]` делает
то же и подходит, когда длина известна только во время работы;
`into_boxed_slice` превращает вектор в `Box<[u8]>` без копирования,
если ёмкость равна длине, а `try_into` — в `Box<[u8; N]>`, если длина
совпала с `N`. Тест `cargo_bigbox` в `code/ch14/tests/run.rs` собирает
пример в обоих профилях и проверяет все шесть исходов `new`, `zeroed`
и `vec`.

<div class="box trap">

**Ловушка: Box в параметре.** `fn f(b: Box<Config>)` заставляет
вызывающего выделить блок, даже если `f` нужна только ссылка, а
`&Config` принимает и `&*boxed`, и ссылку на значение на стеке. clippy
предупреждает об этом (`boxed_local`). `Box` в параметре нужен, когда
функция забирает владение и хранит значение дальше — например, кладёт
`Box<dyn Listener>` в список.

</div>
