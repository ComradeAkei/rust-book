# 14.8. Трюки и ловушки

## Чей clone

`Rc<String>` реализует `Clone`, и `String` тоже. Какой `clone` вызовет
точка, решает порядок поиска методов из раздела [14.2](02-deref.md):
сначала сам `Rc<String>`, и только потом то, во что он
разыменовывается:

```rust
{{#include ../../code/ch14/src/tricks.rs:which_clone}}
```

`which_clone()` возвращает `(2, false)`: `rc.clone()` — второй указатель
на тот же блок, `(*rc).clone()` — новая строка в своём буфере. Для
читателя кода разница не видна, поэтому клон указателя принято писать
явно — `Rc::clone(&rc)`: так видно, что копируется счётчик, а не
данные. clippy умеет требовать этого линтом `clone_on_ref_ptr` из группы
`restriction`.

## Временные значения в if let, match и for

`Ref` из `borrow()` — временное значение, и живёт оно не до конца
выражения, а по правилам, которые зависят от места:

```rust
{{#include ../../code/ch14/src/tricks.rs:scrutinee}}
```

В редакции 2024 временные значения условия `if let` уничтожаются перед
веткой `else`, и `first_or_insert` работает: `borrow_mut` в `else` уже
не видит `Ref`. В редакции 2021 `Ref` жил до конца всего `if let`, и та
же функция паниковала (doc-тест `edition2021,should_panic` у
`first_or_insert` проверяет это). В `match` временные значения условия живут до
конца всего `match` в обеих редакциях, и `first_or_insert_match` с пустым
списком паникует:

```console
thread 'main' (1751) panicked at code/ch14/src/tricks.rs:38:17:
RefCell already borrowed
```

С заголовком `for` то же самое: выражение после `in` вычисляется один
раз, и его временные значения живут, пока идёт весь цикл:

```rust
{{#include ../../code/ch14/src/tricks.rs:for_head}}
```

```console
thread 'main' (1753) panicked at code/ch14/src/tricks.rs:51:13:
RefCell already borrowed
```

`chs.borrow().len()` — число, и кажется, что `Ref` давно не нужен. Но
`0..chs.borrow().len()` — выражение заголовка, и `Ref` из него
уничтожится только после цикла. Лекарство одно: вынести всё, что
заимствует ячейку, в `let` перед `match` или `for`. Тесты
`match_keeps_borrow_to_the_end` и `for_head_keeps_borrow` закрепляют
обе паники.

## `Rc<[T]>` вместо `Rc<Vec<T>>`

Отсчёты, которые раздают нескольким потребителям, удобно держать в
`Rc`. Но `Rc<Vec<i16>>` — это два блока: `RcInner` со счётчиками и
заголовком вектора, и буфер вектора. `Rc<[i16]>` — один:

```rust
{{#include ../../code/ch14/src/tricks.rs:rc_slice}}
```

Тест `observed_rc_slice_vs_rc_vec` записывает обращения к
распределителю для десяти отсчётов. `Rc::new(samples)` выделяет 40 байт
под `RcInner` с заголовком вектора, и блоков становится два — буфер на
20 байт остаётся. `Rc::from(samples)` выделяет 40 байт под счётчики и
сами отсчёты, копирует их и сразу освобождает буфер вектора: в конце
блок один. Разница видна и при каждом чтении:

```rust
{{#include ../../code/ch14/src/codegen.rs:rc_vec}}
```

```console
$ cargo asm -p ch14 --lib --simplify ch14_get_rc_vec
ch14_get_rc_vec:
	mov rcx, qword ptr [rdi]
	mov rax, qword ptr [rcx + 32]
	cmp rsi, rax
	jae .LBB105_2
	mov rax, qword ptr [rcx + 24]
	movzx eax, word ptr [rax + 2*rsi]
	ret
…
$ cargo asm -p ch14 --lib --simplify ch14_get_rc_slice
ch14_get_rc_slice:
	mov rax, qword ptr [rdi + 8]
	cmp rsi, rax
	jae .LBB104_2
	mov rax, qword ptr [rdi]
	movzx eax, word ptr [rax + 2*rsi + 16]
	ret
…
```

Через `Rc<Vec>` — адрес блока, из блока длина и адрес буфера, из
буфера отсчёт: три зависимых загрузки, и каждая может промахнуться
мимо кэша. Через `Rc<[i16]>` длина лежит в самом толстом указателе, а
отсчёты — в блоке сразу за двумя счётчиками, по смещению 16: две
загрузки. Цена `Rc<[T]>` — его нельзя растить: длина зафиксирована при
создании. Для неизменяемых данных — таблиц, снимков, строк
конфигурации (`Rc<str>` вместо `Rc<String>`) — это то, что нужно.

## == сравнивает значения

```rust
{{#include ../../code/ch14/src/tricks.rs:ptr_eq}}
```

`==` у `Rc` сравнивает значения, как у самого `T`: две конфигурации с
одинаковым периодом равны, даже если это разные блоки. «Тот же ли это
объект» спрашивают `Rc::ptr_eq` — тест `eq_compares_values` проверяет
оба ответа. Для `Rc<dyn Trait>` `ptr_eq` сравнивает только адреса и не
смотрит на таблицы методов: одна и та же реализация может оказаться в
двух таблицах из разных единиц компиляции.

## Срез ячеек: windows с записью

Удержание пиков — каждый отсчёт становится максимумом из себя и
предыдущего. Перекрывающиеся окна `windows(2)` есть только у `&[T]`:
у `&mut [T]` их нет, потому что два окна давали бы две изменяемые
ссылки на один элемент. Но если превратить `&mut [i16]` в `&[Cell<i16>]`,
окна снова доступны, и писать можно в любое:

```rust
{{#include ../../code/ch14/src/tricks.rs:cells_slice}}
```

`Cell::from_mut` превращает `&mut T` в `&Cell<T>` — бесплатно, раскладка
одна и та же, а единственность `&mut` гарантирует, что других ссылок
нет. `as_slice_of_cells` превращает `&Cell<[T]>` в `&[Cell<T>]`. Тест
`peaks_are_held` проверяет результат на `[3, 1, 4, 1, 5, 9, 2, 6]`. Код
после оптимизации — обычный цикл по срезу: ячейка ничего не стоит.

## Arc::into_inner, а не try_unwrap

Значение, которое держат несколько потоков, должен забрать последний.
Естественный код — каждый поток в конце зовёт `Arc::try_unwrap` для
своего клона — содержит гонку: два последних потока одновременно видят
счётчик 2, оба получают `Err` с клоном, оба уничтожают клоны, и
значение не достаётся никому, а уничтожается вместе с последним клоном.
`Arc::into_inner` уменьшает счётчик и забирает значение одной
атомарной операцией и обещает, что ровно один получит `Some`:

```rust
{{#include ../../code/ch14/src/tricks.rs:into_inner}}
```

Тест `into_inner_gives_exactly_one` повторяет это по пятьдесят раз для
1, 2, 4 и 8 потоков.

<div class="box trap">

**Ловушка: порядок вычисления.** Паника `RefCell` зависит от того, в
каком порядке вычисляются части выражения, а в Rust этот порядок
определён: слева направо, получатель метода раньше аргументов,
операнды раньше операции. В C порядок вычисления аргументов не
определён, и та же ошибка могла бы то проявляться, то нет в зависимости
от компилятора. Здесь паника воспроизводится всегда — но только если её
можно предсказать, читая код. Задача
[14.A](09-tasks.md#a-где-паникует-refcell) проверяет, умеете ли вы.

</div>
