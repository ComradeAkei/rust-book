# 25.4. static с внутренней изменяемостью

## Инициализатор static — всегда константа

Значение `static` вычисляет компилятор, и в образ программы попадают
готовые байты. Кода, который выполнялся бы до `main` и заполнял
глобальные объекты, в языке нет. Отсюда два следствия. Первое: порядок
инициализации глобальных объектов не может быть ошибкой — его просто
нет. Второе: всё, что нужно менять во время работы, должно уметь
*создаваться* при компиляции. Конструкторы атомиков, `Mutex`, `Cell` —
`const fn` именно поэтому.

<div class="box c">

**Как в C.** В C инициализатор объекта со статическим временем жизни
тоже обязан быть константным выражением, и `static pthread_mutex_t m =
PTHREAD_MUTEX_INITIALIZER;` — макрос, раскрывающийся в константу. В C++
— нет: глобальный объект с конструктором инициализируется кодом до
`main`, и порядок между единицами трансляции не определён («static
initialization order fiasco»). Rust здесь ближе к C, но
`Mutex::new(Config::DEFAULT)` — обычный вызов `const fn`, а не макрос
со знанием внутренностей типа.

</div>

`AtomicU32::new(0)` — `const fn`, и `TICKS` лежит в `.bss`: код
запуска обнулит его вместе с остальными, и только. Ни `mut`, ни

инструкций нет (раздел [21.4](../ch21/04-hardware.md)). Функция
`on_systick` стоит под `#[cfg(target_has_atomic = "32")]`, и на
thumbv6m-none-eabi её нет вовсе; `load` и `store` есть везде. На M0
счётчик, который меняют и прерывание, и основной цикл, требует
критической секции.

## static mut в редакции 2024

`static mut` — глобальная переменная C без всяких гарантий: любое
обращение `unsafe`, а за отсутствие гонок отвечает программист. До
редакции 2024 на ссылки на `static mut` было предупреждение, теперь —
ошибка (запрещающая проверка `static_mut_refs`), даже если ссылка
неявная, через вызов метода:

```text
error: creating a shared reference to mutable static
 --> smut.rs:4:14
  |
4 |     unsafe { SAMPLES.len() }
  |              ^^^^^^^^^^^^^ shared reference to mutable static
  |
  = note: shared references to mutable statics are dangerous; it's undefined behavior if the static is mutated or if a mutable reference is created for it while the shared reference lives
  = note: `#[deny(static_mut_refs)]` (part of `#[deny(rust_2024_compatibility)]`) on by default
```

Ссылка опасна тем, что живёт: пока жива `&SAMPLES`, компилятор вправе
считать, что массив не меняется, а прерывание его меняет — это UB
(раздел [16.1](../ch16/01-abilities.md)). Обращение к самому месту
ссылки не создаёт и в `unsafe` разрешено: чтение, запись, индекс,
`N += 1`. Адрес — `&raw mut SAMPLES` — берётся даже без `unsafe`: опасно
разыменование, а не адрес. Оба варианта — doc-тест модуля `statics`.

Получается, что `static mut` годится для узкого случая: буфер, адрес
которого отдают DMA или C-коду, и данные, к которым обращаются только
через сырые указатели. Для всего остального — атомики, `Mutex`
(на [хосте][g-host]), `critical_section::Mutex` (на МК) или `static mut` внутри
`#[entry]`, который cortex-m-rt превращает в `&'static mut` для одной
функции (раздел [24.4](../ch24/04-attributes.md)).

## Mutex::new в static

```rust

```

`Mutex::new` — `const fn` с Rust 1.63, и `CONFIG` готов до `main` без
кода инициализации: на Linux мьютекс `std` — это 32-битное слово для
[futex][g-futex] и флаг [отравления][g-poisoning], а начальное состояние «свободен» — нули. Тест
`observed_sizes` фиксирует, что `Mutex<u32>` занимает 12 байт на
x86-64 Linux: 4 байта futex, байт флага, выравнивание и сам `u32`.
Это наблюдение о реализации, а не гарантия: на других системах `std`
устроена иначе.

## LazyLock против таблицы при компиляции

Таблицу, которую можно посчитать при компиляции, надо считать при
компиляции. А если её параметр известен только при запуске?

```rust
{{#include ../../code/ch25/src/statics.rs:lazy}}
```

`SCALE` строится при первом обращении: множитель приходит из
переменной окружения `STATION_SCALE`. `LazyLock` (раздел
[14.6](../ch14/06-lazy.md)) хранит саму таблицу и состояние `Once`, и
каждое обращение сначала проверяет, построена ли таблица. Тест
`observed_sizes` показывает цену хранения: `LazyLock<[u32; 256]>` — 1032
байта, на 8 больше таблицы: 4 байта состояния и выравнивание под
указатель на функцию-инициализатор, который лежит на месте таблицы,
пока её нет. А `SCALE3` с известным множителем — просто
1024 байта в `.rodata`: ни состояния, ни проверки, ни кода построения.

Выбор по одному вопросу: *когда* известно значение?

| Значение известно | Чем строить | Где лежит |
|---|---|---|
| при сборке | `static` с `const fn` или блоком | `.rodata`, во flash |
| при сборке, но считать долго или нужен внешний файл | `build.rs` ([8.5](../ch08/05-build-rs.md)) | `.rodata` |
| при запуске, хост | `LazyLock` или `OnceLock` | ОЗУ: `.data` или `.bss` |
| при запуске, МК | заполнить в `main` и отдать ссылку | ОЗУ |

На микроконтроллере `LazyLock` нет — это часть `std`. Таблицу,
зависящую от калибровки, прошивка строит в `main` до разрешения
прерываний и дальше пользуется ссылкой; как отдать её обработчикам
прерываний без `static mut` — глава 27.
