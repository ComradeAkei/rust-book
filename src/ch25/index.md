# 25. Вычисления при компиляции

## Мотивирующая проблема

Прошивке нужны числа, которые известны до её запуска: делитель частоты
UART для заданной скорости, таблица CRC, таблица синуса, коэффициенты
фильтра, проверка, что структура заголовка совпадает с той, что описал
загрузчик. В C у программиста три инструмента, и ни один не годится для
настоящих вычислений.

**Препроцессор** считает в `#if` только целые числа в `intmax_t`: ни
`sizeof`, ни перечислений, ни функций. Делитель UART он посчитать может,
и `#error` остановит сборку, если делитель вышел меньше единицы:

```c
{{#include ../../code/ch25/c/divisor.c:divisor}}
```

Но формула записана макросами без типов, а таблицу из 256 элементов
препроцессор не построит.

**`const`** в C — не константа, а неизменяемая переменная. Размер
массива в области файла обязан быть константным выражением, и `const
int` им не является:

```c
{{#include ../../code/ch25/c/const_size.c:const_size}}
```

C23 добавил `constexpr`, но только для объектов. Размер массива из
`constexpr` теперь годится, а элемент `constexpr`-массива в
`_Static_assert` и вызов функции в инициализаторе — нет: функций,
вычисляемых при компиляции, в C нет вовсе.

```c
{{#include ../../code/ch25/c/constexpr.c:constexpr}}
```

```console
$ gcc -std=c2x -c constexpr.c
constexpr.c:10:25: error: expression in static assertion is not constant
constexpr.c:13:25: error: initializer element is not constant
```

**Внешний генератор** остаётся для всего остального: скрипт на Python
печатает таблицу CRC в `crc_table.h`, а в репозиторий попадает 256 чисел,
которые никто не проверяет глазами. Или таблицу считают при запуске, в
`init_crc_table()`, и она занимает ОЗУ. Или переписывают из даташита — и
забывают `const`: `uint16_t crc_table[256] = {…}` без `const` попадает в
`.data`, занимает 512 байт и во flash, и в ОЗУ, а код запуска копирует её
при каждой загрузке (раздел [8.8](../ch08/08-sections.md)).

## Что делает Rust

Rust выполняет код при компиляции. **`const fn`** — обычная функция,
которую компилятор умеет выполнить своим интерпретатором, когда её
результат нужен в константе: в `const`, в `static`, в длине массива, в
блоке `const { … }`. Та же функция работает и при выполнении, как
обычная. Таблица CRC — цикл `while` в `const fn`, и в прошивке от него
остаётся только результат: 512 байт в `.rodata`, во flash, без единой
инструкции построения.

- **`const` и `static`** ([25.1](01-consts.md)) — значение без адреса и
  объект с адресом; что из этого следует для образцов, массивов и
  ссылок.
- **`const fn`** ([25.2](02-const-fn.md)) — что интерпретатор умеет и
  чего пока нет; паника при вычислении — ошибка компиляции с текстом
  паники.
- **Проверки при компиляции** ([25.3](03-checks.md)) — `const _: () =
  assert!(…)` вместо `_Static_assert`, но с вызовом любой `const fn`;
  когда именно компилятор вычисляет константу.
- **`static` с внутренней изменяемостью** ([25.4](04-statics.md)) —
  атомики и `Mutex::new` без кода инициализации, почему `static mut`
  почти нельзя трогать в редакции 2024, `LazyLock` против таблицы при
  компиляции.
- **Таблицы и литералы** ([25.5](05-tables.md)) — деление без
  инструкции деления на Cortex-M0, байты кадра из строки `hex!("A5 01 …")`.
- **Во flash или в ОЗУ** ([25.6](06-flash.md)) — что из этого стоит ОЗУ
  на настоящей прошивке.

Главная мысль главы: в Rust нет второго языка для вычислений при
компиляции. Нет препроцессора с его арифметикой, нет шаблонного
метапрограммирования, нет генератора на Python: та же функция, которую
вы тестируете обычным `#[test]`, считает таблицу для прошивки, а её
паника на неверных входных данных останавливает сборку.

## Код главы

Примеры 25.1–25.5 и шаг проекта лежат в `code/ch25`, прошивка раздела
25.6 — в `firmware/ch25-flash`, задачи — в `exercises/ch25` и
`solutions/ch25`. Библиотека без возможности `std` собирается на все
три цели Cortex-M; то, что требует `std` (`Mutex`, `LazyLock`), лежит в
модуле `hosted` за этой возможностью.

```console
$ cargo test -p ch25                  # примеры, ассемблер Cortex-M0/M3, check против build
$ cargo +nightly test --doc -p ch25   # коды ошибок в doc-тестах
$ cargo test -p ch25-solutions        # задачи A–D
$ cargo test -p telemetry-frame       # шаг проекта: таблица CRC против побитового цикла
$ bash code/ch25/c/run.sh             # C17, C23 и препроцессор
$ cd firmware && cargo run --release -p ch25-flash   # раздел 25.6 в QEMU
```

Программы, которые компилятор должен отвергнуть, — doc-тесты
`compile_fail` с кодом ошибки; коды сверяет nightly rustdoc в CI.
Тексты сообщений сняты с rustc 1.97.0 (LLVM 22) и gcc 13.3, ассемблер —
`cargo rustc --release -- --emit asm` под thumbv6m-none-eabi и
thumbv7m-none-eabi, и тесты `rustc_*` сверяют его с закреплённым
компилятором при каждом прогоне.
