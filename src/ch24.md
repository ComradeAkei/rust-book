# 24. Процедурные макросы

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** Три вида: derive, атрибутные, функциональные. Крейт proc-macro, TokenStream, syn, quote, proc_macro2. Спаны и диагностика через syn::Error, атрибуты-помощники, тестирование ошибок компиляции через trybuild, влияние на время сборки.

**Как в C.** Внешние генераторы кода (protoc, yacc), которые запускаются отдельным шагом сборки.

**Железо.** Процедурный макрос выполняется на хосте даже при сборке под Cortex-M. Атрибуты #[entry] и #[interrupt] из cortex-m-rt как пример того, что макрос проверяет сигнатуру и правила за человека.

**Трюки и ловушки.** Генерация const-проверок размеров из derive. Полные пути ::core::... в сгенерированном коде. Плохие спаны дают непонятные ошибки для пользователя.

**Задачи**

- A. Раскройте через cargo expand #[derive(Debug)] и #[entry] из cortex-m-rt и объясните каждую строку.
- B. #[derive(Bitfield)]: упаковка полей с атрибутами #[bits(3)] в u32 с геттерами и сеттерами. Переполнение 32 бит даёт ошибку компиляции с правильным спаном, проверка через trybuild.
- C. Атрибут #[timed] замеряет время функции. На Cortex-M3 и старше он читает счётчик циклов DWT, на хосте Instant.
- D. Функциональный макрос include_svd! читает SVD-файл при компиляции и генерирует API регистров только для указанной периферии. Сравните с svd2rust по размеру кода и времени сборки.
