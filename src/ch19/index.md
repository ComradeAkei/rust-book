# 19. Встроенный ассемблер, интринсики и SIMD

**Перед чтением.** В [разделе 0.3](../ch00/03-asm.md) показано, как читать
инструкции и регистры, а в [главе 16](../ch16/index.md) — как обосновывать
unsafe. Здесь недостаточно получить нужное число: нужно ещё точно сообщить
компилятору, какие входы инструкция читает и какие выходы изменяет.
Начните с разбора этих входов и выходов, затем переходите к [опциям][g-asm-operands].

## Мотивирующая проблема

Иногда нужной инструкции нет ни в стандартной библиотеке, ни в виде
операции языка. Счётчик тактов процессора, [барьер][g-memory-barrier] памяти, инструкция
«уснуть до прерывания», восемь сложений за один такт на векторном регистре,
системный регистр маски прерываний — всё это существует только как
конкретные машинные инструкции. Обычный Rust до них не опускается: он
нарочно абстрагирован от того, какие именно инструкции сгенерирует LLVM.

В C для этого есть расширенный ассемблер GCC (`asm volatile (…)`),
[интринсики][g-intrinsic] из `immintrin.h` и `__attribute__((naked))`. У Rust есть ровно те
же три уровня, но каждый обёрнут в `unsafe` и правила, которые делают
обещание программиста проверяемым хотя бы частично:

```rust,ignore
let (lo, hi): (u32, u32);
unsafe {
    core::arch::asm!("rdtsc", out("eax") lo, out("edx") hi);
}
let tsc = (u64::from(hi) << 32) | u64::from(lo);
```

Проблема в том, что встроенный ассемблер — это дыра в модели компилятора.
Компилятор не читает текст инструкций; он верит *операндам* (какие регистры
вы заняли) и *опциям* (трогает ли блок память, стек, флаги). Соврёте в
операнде — компилятор отдаст занятый вами регистр под другое значение.
Соврёте в опции `pure` — он решит, что два ваших `rdtsc` дают одно и то же,
и выкинет второй. Вызовете функцию с [`#[target_feature(enable = "avx2")]`][g-target-feature] на
процессоре без [AVX2][g-sse-avx] — UB уже на первой инструкции. Везде цена ошибки —
неопределённое поведение, которое не ловит ни компилятор, ни [санитайзер][g-sanitizer].

## Что делает Rust

Глава — про три уровня спуска к конкретным инструкциям и про то, как за
каждый отвечать.

- `asm!` ([19.1](01-asm.md)) — отдельные инструкции внутри функции;
  операнды связывают регистры с переменными, опции обещают, чего блок не
  делает.
- `global_asm!` и [naked-функции][g-naked-function] ([19.2](02-naked.md)) — целая функция на
  ассемблере, без [пролога][g-prologue] и эпилога: обработчики прерываний и переключение
  контекста.
- Интринсики `core::arch` ([19.3](03-intrinsics.md)) — безопасная на вид
  обёртка над одной [SIMD][g-simd]-инструкцией; `#[target_feature]` включает наборы,
  которых нет в базовой модели [цели][g-target].
- Выбор реализации в рантайме ([19.4](04-dispatch.md)) —
  `is_x86_feature_detected!` и кэш-указатель на лучшую доступную версию.
- Переносимый SIMD ([19.5](05-portable.md)) — `core::simd` (nightly): тот
  же код для SSE2, AVX2 и NEON, без `unsafe`.
- Инструкции управления ядром на Cortex-M ([19.6](06-cortex.md)) — `wfi` и
  критическая секция через регистр [`PRIMASK`][g-primask].

Общий принцип тот же, что в [главе 16](../ch16/index.md): опасное заперто за
безопасным API, каждый `unsafe` снабжён `// SAFETY`, а то, что глава
обещает про сгенерированный код (`rdtsc`, `lfence`, `paddd`, `vpaddd`),
проверено снятым ассемблером.

## Код главы

Ядро главы — встроенный ассемблер и интринсики x86-64, поэтому [крейт][g-crate]
привязан к архитектуре: под Miri (Miri не исполняет `asm!`) не идёт, а под
Cortex-M компилируется только [модуль][g-module] управления ядром. Всё проверяется:

```console
$ cargo test -p ch19                 # регистры, SIMD, naked-переключение, doc-тесты
$ cargo test -p ch19 --test asm      # обещанные инструкции реально эмитятся
$ cargo test -p ch19-solutions       # задачи A–D
$ cargo build -p ch19 --no-default-features --target thumbv7em-none-eabihf  # 19.6
```

Переносимый SIMD ([19.5](05-portable.md)) требует nightly:
`cargo +nightly test -p ch19 --features nightly --lib`.
