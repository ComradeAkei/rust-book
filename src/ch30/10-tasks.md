# 30.10. Задачи

Заготовки — в `exercises/ch30`, по модулю на задачу; функции с
`todo!()` собираются и паникуют только при вызове. Тесты, общие для
заготовок и решений, — `tests-shared/ch30.rs`. Сами тесты собраны в
профиле dev, а мерить неоптимизированный код — одна из ошибок задачи A;
поэтому замеры идут в отдельной программе `ch30-task`
(`tests-shared/ch30-task.rs`). Тест собирает её с `--release` и
запускает: напрямую, когда нужно время, и под cachegrind, когда нужно
число инструкций, промахов кэша или промахов предсказателя.

```console
$ cargo test -p ch30-exercises            # все задачи
$ cargo test -p ch30-exercises task_c     # одна задача
$ cargo test -p ch30-solutions            # эталон
$ cargo run --release -p ch30-exercises --bin ch30-task -- a all 100
$ cargo run --release -p ch30-exercises --bin ch30-task -- d branchless random 1024
```

На чём стоят проверки задач: число выделений памяти, число инструкций и
промахи моделей cachegrind (раздел [30.4](04-cachegrind.md)) и ассемблер.
Всё это от прогона к прогону не меняется. Время проверяют только тесты
`observed_`, и с большим запасом. Без valgrind опыты под cachegrind
пропускаются с сообщением (путь к valgrind можно задать в `VALGRIND`), а с
`CH30_REQUIRE_VALGRIND` пропуск становится ошибкой. Сборку, замеры и
cachegrind тест запускает по одному, чтобы они не мерили друг друга;
прогон всех задач после сборки идёт около полуминуты. Разборы — в
[приложении E](../appendix-e/ch30.md), но сначала попробуйте сами.

безопасен, потому что текст свой. Что изменится, если текст придёт из
сети от кого угодно?
