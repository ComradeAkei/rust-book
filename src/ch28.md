# 28. Системное программирование под Linux

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** Системные вызовы через std, libc, rustix и nix. Файловые дескрипторы и I/O safety: OwnedFd, BorrowedFd, AsFd. Процессы: fork и его опасность в многопоточной программе, exec, posix_spawn, Command. Сигналы и async-signal-safety, signalfd. mmap и разделяемая память, epoll, обзор io_uring, /proc и /sys. Ядру Linux посвящена отдельная глава 29.

**Как в C.** Те же вызовы на C с errno и ручным закрытием дескрипторов на каждом пути ошибки.

**Железо.** Цена системного вызова и vDSO для clock_gettime. Страницы, page faults при mmap, huge pages.

**Трюки и ловушки.** memfd_create, File::from(OwnedFd), unsafe pre_exec. fork в многопоточном процессе оставляет захваченные чужими потоками мьютексы. Аллокация в обработчике сигнала. EINTR.

**Задачи**

- A. Для 6 операций (println!, File::open, read_to_string, Command::output и других) предскажите список системных вызовов и проверьте через strace.
- B. ls -la на getdents64 через rustix, без std::fs, с правами и владельцами.
- C. Мини-оболочка: конвейеры a | b | c, перенаправления, фоновые задачи. Ctrl-C прерывает только активную задачу через группы процессов.
- D. Поиск строки в файле на несколько гигабайт через mmap против read с буфером, затем с huge pages. Объясните разницу во времени через page faults и промахи TLB. Модуль ядра из прежней версии этой задачи переехал в главу 29.
