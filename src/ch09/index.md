# 9. Трейты

## Мотивирующая проблема

В C у полиморфизма один инструмент: структура с указателями на функции,
а данные конкретного устройства передаются через `void *`. Так устроены
`struct file_operations` в Linux, драйверы в Zephyr и половина HAL
производителей микроконтроллеров. Программа `code/ch09/c/ops.c` опрашивает
два вида датчиков через общий интерфейс:

```c
{{#include ../../code/ch09/c/ops.c}}
```

```console
$ gcc -O2 -Wall -Wextra -fanalyzer -o ops ops.c
$ ./ops
0: poll_twice = 4300
1: poll_twice = 6
2: poll_twice = 20
0: термодатчик
Segmentation fault
```

Ни одного предупреждения ни от GCC с анализатором, ни от clang, а в
программе три ошибки разного рода.

**Таблица заполнена не целиком.** В `counter_ops` забыли поле `name`, и
инициализатор с указанием полей молча обнулил его. Программа упала на
вызове по нулевому указателю, но только когда до него дошло дело: первые
четыре строки она напечатала. На Cortex-M защиты памяти по умолчанию
нет, и вызов по адресу 0 — это переход с нулевым младшим битом, то есть
в состояние ARM, которого у этих ядер нет. Процессор уходит в [HardFault][g-hardfault]
(на M3 и M4 — через [UsageFault][g-faults], если тот включён), и найти по нему
забытое поле таблицы — отдельная работа.

**Контекст не того типа.** Третий датчик собран из таблицы термодатчика
и данных счётчика. `thermo_read` получила `void *`, привела его к
`struct thermo *` и прочитала первое поле счётчика, `total = 10`, как
температуру. Результат 20 правдоподобен, и никакой инструмент его не
заподозрит: `void *` отключает проверку типов совсем.

**Каждый вызов косвенный.** Даже когда в точке вызова известно, какой
датчик опрашивается, `poll_twice` вызывает `read` через таблицу.
Фрагмент `objdump -d -M intel ops` с пояснениями:

```text
    133d:	mov    rax,QWORD PTR [rbx]          ; rax = s->ops
    1340:	mov    rdi,QWORD PTR [rdi+0x8]      ; rdi = s->ctx
    1344:	call   QWORD PTR [rax]              ; s->ops->read(s->ctx)
    1346:	mov    rdi,QWORD PTR [rbx+0x8]
    134a:	mov    ebp,eax
    134c:	mov    rax,QWORD PTR [rbx]          ; s->ops ещё раз
    134f:	call   QWORD PTR [rax]
```

Компилятор не знает, что сделает функция по указателю, и вынужден
считать, что она могла поменять `s->ops`, поэтому перечитывает таблицу
перед вторым вызовом. [Встроить][g-inlining] `thermo_read`, которая сводится к одной
загрузке, он не может. На Cortex-M каждый такой вызов — ещё и загрузка
адреса из таблицы во flash. Скрипт `code/ch09/c/run.sh` проверяет все
эти выводы.

## Что делает Rust

Интерфейс в Rust описывает *трейт* (trait): набор методов, типов и
констант, которые тип обязуется предоставить.

- Реализация трейта — блок `impl Трейт for Тип`, и компилятор требует в
  нём все обязательные методы. Забытый метод — ошибка компиляции, а не
  нулевой указатель. [Обобщённая][g-generic] функция с ограничением `S: Sensor`
  компилируется отдельно для каждого типа, вызовы в ней прямые и
  встраиваются (раздел [9.1](01-traits.md)).
- Трейт может требовать не только методы, но и *ассоциированные типы* и
  *константы*. Адрес регистра, записанный как константа трейта,
  становится операндом инструкции (раздел [9.2](02-associated.md)).
- Трейт может опираться на другие трейты: *супертрейт* — требование к
  типу, а не наследование (раздел [9.3](03-supertraits.md)).
- Кто и для чего вправе реализовать трейт, решают *правило сироты* и
  *когерентность*: у каждой пары «трейт — тип» не больше одной
  реализации во всей программе (раздел [9.4](04-coherence.md)).
- *Маркерные трейты* без методов описывают свойства типа: можно ли его
  копировать байтами, передать в другой поток, известен ли его размер.
  `Send` и `Sync` компилятор выводит сам (раздел [9.5](05-markers.md)).
- Операторы, преобразования, печать и значения по умолчанию — тоже
  трейты стандартной библиотеки, и `derive` пишет их реализации за вас
  (раздел [9.6](06-std-traits.md)).
- Трейт можно [запечатать][g-sealed-trait], чтобы его не реализовал никто снаружи, и
  можно добавить методы чужому типу. А вот имитировать наследование
  через `Deref` не стоит (раздел [9.7](07-tricks.md)).

Указатели на функции в Rust тоже есть, и [таблица методов][g-vtable] появится, когда
она действительно нужна: объекты `dyn Trait` разбирает глава 11. Здесь
речь о статическом полиморфизме, где тип известен при компиляции.

## Код главы

```console
$ cargo test -p ch09 -p ch09-solutions            # примеры и решения
$ cargo +nightly test --doc -p ch09               # коды ошибок в doc-тестах
$ bash code/ch09/c/run.sh                         # ops.c: таблица указателей на функции
$ cargo asm -p ch09 --lib --simplify ch09_poll_thermo
$ cd firmware && cargo run --release -p ch09-systick   # SysTick через трейт Register
```

Числа в тексте получены на rustc 1.97.0 (LLVM 22.1.6) и nightly 1.101.0
(2026-10-21) для `x86_64-unknown-linux-gnu` и трёх [целей][g-target] Cortex-M, GCC
13.3 и clang 18.1. Ассемблер снят командой `cargo asm --simplify` из
release-сборки; для Cortex-M к ней добавлены `--no-default-features
--target <цель>`.
