## B. Регистры UART как типы

Драйвер UART0 PL011 того же кристалла, что в разделе
[6.9](../ch06/09-registers.md) (LM3S6965, машина QEMU `lm3s6965evb`),
только регистры теперь описаны трейтами, как SysTick в разделе
[9.2](02-associated.md). Заготовка `exercises/ch09/src/b_register.rs`
даёт трейты:

```rust
{{#include ../../exercises/ch09/src/b_register.rs:traits}}
```

`Mmio` — настоящая шина через `volatile`, её конструктор `unsafe`. Тесты
подставляют вместо неё журнал обращений. Регистры, базовый адрес 0x4000_C000:

| Регистр | Тип | Смещение | Доступ | После сброса |
|---|---|---|---|---|
| DR | `Dr` | 0x000 | чтение и запись | 0 |
| FR | `Fr` | 0x018 | только чтение | 0x90 |
| IBRD | `Ibrd` | 0x024 | чтение и запись | 0 |
| FBRD | `Fbrd` | 0x028 | чтение и запись | 0 |
| LCRH | `Lcrh` | 0x02C | чтение и запись | 0 |
| CR | `Cr` | 0x030 | чтение и запись | 0x300 |
| ICR | `Icr` | 0x044 | только запись | 0 |

Нужно:

- реализовать `Register`, `Readable` и `Writable` для семи типов по
  таблице;
- переписать методы `Reg<R>` так, чтобы `read` и `is_reset` были только
  у читаемых регистров, `write` и `reset` — у записываемых, `modify` — у
  тех, что и то и другое, а регистр с адресом, не кратным 4, не
  компилировался ни в одном методе:

```rust
{{#include ../../exercises/ch09/src/b_register.rs:reg}}
```

- написать драйвер:

```rust
{{#include ../../exercises/ch09/src/b_register.rs:api}}
```

Делитель частоты PL011 — число `clock / (16 · baud)` с шестью двоичными
знаками после запятой: целая часть идёт в IBRD, дробная, умноженная на
64 и округлённая, — в FBRD. В целых числах это `div = (4 · clock + baud
/ 2) / baud`, `IBRD = div >> 6`, `FBRD = div & 63`; для 12 МГц и 115200
бод получается 6 и 33. Скорость допустима, если IBRD от 1 до 65535, а
при IBRD = 65535 ещё и FBRD = 0; нулевая скорость недопустима. При
ошибке `init` возвращает `BadBaud` и не трогает ни одного регистра. При
успехе она пишет ровно пять раз в таком порядке: CR = 0 (выключить),
IBRD, FBRD, LCRH = `LCRH_8N1_FIFO` (запись LCRH защёлкивает делитель),
CR = `CR_ENABLE`. `write_byte` ждёт, пока сброшен бит TXFF в FR, и
пишет байт в DR. `deinit` возвращает CR, IBRD, FBRD и LCRH к значениям
после сброса, в этом порядке.

Тесты `task_b_init`, `task_b_baud`, `task_b_write_byte`, `task_b_reg` и
`task_b_reset` гоняют драйвер на журнале обращений и сверяют его
дословно; среди скоростей есть частота `u32::MAX`, на которой `4 ·
clock` не помещается в `u32`. Тест `task_b_access` собирает ваш файл
отдельно, как крейт, и дописывает к нему 45 проб: каждый из пяти методов
для каждого из семи регистров должен собираться или не собираться по
таблице (ошибка E0599 или E0277), а регистр по адресу `BASE + 2` — не
собираться ни в одном методе с ошибкой E0080, тогда как `BASE + 4` —
собираться. Последние пробы собираются в объектный файл: проверка
выравнивания срабатывает только при генерации кода. Поэтому файл
должен быть самодостаточным, без ссылок на другие модули крейта.

Тест `task_b_thumb` собирает библиотеку под Cortex-M0 и проверяет, что
`ch09b_init_115200` и `ch09b_write_byte` определены, адреса регистров
встречаются в коде и не встречаются в секциях данных. Посмотрите на код
сами:

```console
$ cargo asm -p ch09-exercises --lib --simplify --target thumbv6m-none-eabi ch09b_init_115200
$ cargo asm -p ch09-exercises --lib --simplify --target thumbv6m-none-eabi ch09b_write_byte
```

## D. Один драйвер для I2C и SPI

Датчик температуры TMP-9 продаётся в двух исполнениях: с I2C и с SPI.
Регистры у них одни:

| Регистр | Адрес | Что |
|---|---|---|
| WHO_AM_I | 0x0F | всегда 0xA9 |
| CTRL | 0x20 | запись 0x01 включает непрерывные измерения |
| STATUS | 0x27 | бит 0 (DRDY) — готово новое измерение |
| TEMP_L, TEMP_H | 0x2A, 0x2B | температура, `i16` little-endian в сотых долях °C; чтение TEMP_H забирает измерение |

Чтение нескольких регистров подряд автоматически переходит к
следующему адресу. По I2C регистр читают записью его номера и чтением
с повторным START в одной транзакции (`write_read`), а пишут одной
записью `[номер, значение]`. По SPI чтение — одна транзакция из записи
байта `0x80 | номер` и чтения, запись — одна транзакция `[номер,
значение]`.

Драйвер нужно написать один на обе шины поверх `embedded-hal` 1.0.
Заготовка `exercises/ch09/src/d_bus.rs` даёт трейт доступа к регистрам
только с типом ошибки:

```rust
{{#include ../../exercises/ch09/src/d_bus.rs:regs}}
```

и интерфейс драйвера:

```rust
{{#include ../../exercises/ch09/src/d_bus.rs:driver}}
```

Нужно спроектировать методы `Regs`, реализовать их для обеих шин и
написать драйвер: конструктор читает WHO_AM_I и при чужом значении
возвращает `Error::WrongId`, ничего не записав, иначе пишет CTRL =
0x01; `temperature` опрашивает STATUS не больше `POLLS` раз и, когда
измерение готово, читает оба байта температуры одной транзакцией, иначе
возвращает `Error::Timeout`; ошибка шины становится `Error::Bus`.

Тесты `task_d_*` подключают драйвер к моделям шины I2C и устройства SPI,
которые реализуют трейты `embedded-hal` и ведут журнал транзакций, и
сверяют журнал дословно: лишняя транзакция, разбитое на два чтение
температуры или чтение без бита 0x80 — ошибка. Модели принимают и
`&mut`-ссылку на себя: `embedded-hal` реализует `I2c` и `SpiDevice` для
`&mut T`, и тест сохраняет шину у себя, чтобы проверить журнал после
ошибки.

и назовите компромиссы. Почему SPI там разделён на `SpiBus` и
`SpiDevice`, а I2C — нет? Зачем `I2c::transaction` принимает срез
операций, а не только `read` и `write`? Почему ошибка — ассоциированный
тип с методом `kind()`, а не общее для всех перечисление? Что теряет
пользователь, когда `new_i2c` возвращает ошибку, и как вернуть ему
шину? Сколько копий `temperature` окажется в прошивке с двумя датчиками,
по одному на каждой шине?
