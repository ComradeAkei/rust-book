# 9.6. Трейты стандартной библиотеки

Многое из того, что в других языках встроено в синтаксис, в Rust —
трейты из `core`: операторы, преобразования, печать, значение по
умолчанию. Свой тип получает эти возможности ровно тогда, когда для
него написана реализация. Разберём их на числе с фиксированной точкой
Q15, которое в обработке сигналов на Cortex-M встречается чаще, чем
`f32`.

## Операторы

```rust
{{#include ../../code/ch09/src/std_traits.rs:q15}}
```

Выражение `a + b` — сокращение для `Add::add(a, b)`, и результат имеет
тип `Add::Output`. Арифметика Q15 *насыщающая*: `0.5 + 0.5` даёт
наибольшее представимое значение 32767, а не переполнение в −32768. У
произведения двух Q15 вдвое больше дробных битов, Q30; сдвиг на 15 с
прибавкой половины младшего разряда возвращает Q15 с округлением.
Насытиться может только −1 · −1 = +1, которого в Q15 нет.

Оператора без реализации нет. Деления для `Q15` никто не писал:

```text
error[E0369]: cannot divide `Q15` by `Q15`
 --> e0369.rs:2:31
  |
2 | pub fn f() -> Q15 { Q15::HALF / Q15::HALF }
  |                     --------- ^ --------- Q15
  |                     |
  |                     Q15
  |
note: `Q15` does not implement `Div`
```

Все реализации короткие и встраиваются. Сложение и умножение с
накоплением, функции для ассемблера:

```rust
{{#include ../../code/ch09/src/std_traits.rs:asm}}
```

```console
$ cargo asm -p ch09 --lib --simplify --no-default-features --target thumbv7em-none-eabihf ch09_q15_add
ch09_q15_add:
	push {r7, lr}
	mov r7, sp
	qadd16 r0, r0, r1
	pop {r7, pc}
$ cargo asm -p ch09 --lib --simplify --no-default-features --target thumbv7em-none-eabihf ch09_q15_mac
ch09_q15_mac:
	push {r7, lr}
	mov r7, sp
	mov.w r3, #16384
	smlabb r1, r2, r1, r3
	movw r3, #32767
	asrs r2, r1, #15
	cmp r2, r3
	it lt
	asrlt r3, r1, #15
	qadd16 r0, r0, r3
	pop {r7, pc}
```

На Cortex-M4 у LLVM нашлись DSP-инструкции. `qadd16` складывает две
пары 16-разрядных половин с насыщением; нужна только младшая, а
старшая половина результата никого не интересует. `smlabb` умножает
младшие половины двух регистров со знаком и прибавляет третий —
`a * b + 0x4000` одной инструкцией. От `clamp` осталась только
проверка сверху: компилятор доказал, что `(a * b + 0x4000) >> 15` не
бывает меньше −32768. Без DSP-расширения выходит иначе:

```console
$ cargo asm -p ch09 --lib --simplify --no-default-features --target thumbv7m-none-eabi ch09_q15_add
ch09_q15_add:
	push {r7, lr}
	mov r7, sp
	sxth r0, r0
	sxth r1, r1
	add r0, r1
	ssat r0, #16, r0
	pop {r7, pc}
$ cargo asm -p ch09 --lib --simplify ch09_q15_add
ch09_q15_add:
	lea eax, [rdi + rsi]
	cwde
	sar eax, 15
	xor eax, -32768
	add di, si
	cmovno eax, edi
	ret
```

У Cortex-M3 нет `qadd16`, но есть `ssat`: сложение в 32 битах и
насыщение до 16. На x86-64 насыщение собрано из флага переполнения:
`cmovno` берёт обычную сумму, если переполнения не было, а иначе
остаётся заготовленное заранее значение 32767 или −32768, смотря по
знаку. На Cortex-M0 нет ни того, ни другого, и `ch09_q15_add` занимает
18 инструкций с тремя сравнениями и условными переходами, по два на
любом пути. Исходник у всех четырёх
целей один, и ни одной интринсики в нём нет.

<div class="box c">

**Как в C.** Перегрузки операторов в C нет, поэтому код DSP на C пишут
вызовами: `q15_add(a, b)`, `q15_mul(a, b)`, а ради `qadd16` берут
интринсики CMSIS вроде `__QADD16`, привязанные к ядру. В Rust `a + b *
c` остаётся формулой, а выбор инструкций — заботой LLVM для каждой
цели.

</div>

## Преобразования

```rust
{{#include ../../code/ch09/src/std_traits.rs:convert}}
```

`From` — преобразование, которое не может не получиться: любой Q15
помещается в `i32`. `TryFrom` возвращает `Result`, и его
ассоциированный тип `Error` говорит, что пошло не так: `Q15::try_from(40_000)`
даёт `Err(OutOfRange(40000))`. Парные `Into` и `TryInto` писать не
нужно, их дают общие реализации из `core` (раздел
[9.4](04-coherence.md)):

```rust
let q: Q15 = 16384i32.try_into().unwrap();
let raw: i32 = q.into();
```

Сравните с `as`: `40_000 as i16` молча даёт −25536. Для чисел из
внешнего мира — АЦП, пакета, регистра — `TryFrom` заставляет решить, что
делать со значением вне диапазона, в том месте, где оно появилось.

## Debug и Display

```rust
{{#include ../../code/ch09/src/std_traits.rs:display}}
```

`Debug` выведен `derive` и показывает устройство значения, для
программиста: `format!("{:?}", Q15::HALF)` даёт `Q15(16384)`. `Display`
выводить нельзя, он пишется руками и показывает смысл, для человека:

| Значение | `{:?}` | `{}` |
|---|---|---|
| `Q15::HALF` | `Q15(16384)` | `0.5000` |
| `Q15::ONE` | `Q15(32767)` | `1.0000` |
| `Q15(-32768)` | `Q15(-32768)` | `-1.0000` |
| `Q15(-8192)` | `Q15(-8192)` | `-0.2500` |
| `Q15(1)` | `Q15(1)` | `0.0000` |

32767/32768 = 0,99997, и с четырьмя знаками это 1.0000. Плавающей
точки в `Display` нет: на Cortex-M0 она стоила бы вызовов программной
эмуляции (раздел [8.9](../ch08/09-tasks.md), задача B).

## AsRef и Borrow

Функции, которой нужны байты, всё равно, в чём они лежат:

```rust
{{#include ../../code/ch09/src/std_traits.rs:asref}}
```

`AsRef<[u8]>` реализуют `&[u8]`, `[u8; N]`, `Vec<u8>`, `str` и `String`,
поэтому `crc8("123456789")`, `crc8(&s)` для `String` и
`crc8(*b"123456789")` дают одно и то же: 0xf4, контрольное значение
CRC-8 с полиномом 0x07. Цена удобства — по копии `crc8` на каждый тип
аргумента. Обычный приём против этого — тонкая обобщённая обёртка, которая
вызывает `as_ref` и передаёт срез необобщённой функции; подробнее о нём в
разделе [10.5](../ch10/05-mono.md).

`Borrow` похож на `AsRef`, но обещает больше: заимствованный вид
сравнивается, упорядочивается и хешируется так же, как исходное
значение. На этом обещании держатся ассоциативные массивы:

```rust
{{#include ../../code/ch09/src/std_traits.rs:borrow}}
```

Ключи — `String`, а `get` принимает `&str`: `BTreeMap<K, V>::get<Q>`
требует `K: Borrow<Q>` и `Q: Ord`. Без этого пришлось бы строить
`String` из `&str` на каждый поиск, то есть выделять память в куче ради
сравнения. `AsRef` такого обещания не даёт и для ключей не годится.

## Default

```rust
{{#include ../../code/ch09/src/std_traits.rs:default}}
```

`Q15` получил `Default` через `derive`, и `Q15::default()` — это
`Q15(0)`. Для `PollConfig` выведенное значение по умолчанию было бы
бессмысленным: период опроса 0 мс. Поэтому реализация ручная, и
запись `PollConfig { retries: 5, ..Default::default() }` берёт остальные
поля из неё.

## Что пишет derive

`#[derive(...)]` — встроенный в компилятор макрос, который пишет
реализации за программиста; свои `derive` пишут процедурными макросами
([глава 24](../ch24/02-syn-quote.md)). Посмотреть результат можно флагом `-Zunpretty=expanded`:

```rust
{{#include ../../code/ch09/expanded/derive.rs}}
```

```rust
{{#include ../../code/ch09/expanded/derive.out.rs}}
```

`Debug` собран из `debug_struct_field2_finish` — готовой функции для
структуры с двумя полями. `Clone` у типа с `Copy` — просто `*self`, а
строки `AssertParamIsClone` проверяют при компиляции, что поля
действительно `Clone`. `PartialEq` сравнивает поле за полем, `Default`
берёт значение по умолчанию у каждого поля. Атрибут
`#[automatically_derived]` подсказывает линтам и rustdoc, что код
сгенерирован. `StructuralPartialEq` и `TrivialClone` — служебные
маркеры: первый разрешает использовать константы типа в образцах
`match`, второй сообщает стандартной библиотеке, что клонирование
сводится к копированию байтов. Тест `rustc_derive_expansion` в
`code/ch09/tests/expand.rs` сверяет снимок с тем, что печатает
закреплённый rustc.

<div class="box trap">

**Ловушка.** `derive` добавляет ограничения на все параметры типа, даже
если поле с этим параметром их не требует. `Reg<R>` из раздела
[9.2](02-associated.md) хранит только `PhantomData<R>`, и
`#[derive(Clone, Copy)]` на нём даёт `impl<R: Clone> Clone for Reg<R>`.
Типы регистров `Clone` не реализуют, и копия `Reg<SystCsr>` не
компилируется:

```text
error[E0382]: use of moved value: `r`
…
note: if all bounds were met, you could clone the value
 --> dr.rs:4:1
  |
3 | #[derive(Clone, Copy)]
  |          ----- derived `Clone` adds implicit bounds on type parameters
4 | pub struct Reg<R>(PhantomData<R>);
  | ^^^^^^^^^^^^^^^-^
  |                |
  |                introduces an implicit `R: Clone` bound
…
  = help: consider manually implementing `Clone` to avoid undesired bounds
```

Выход — написать `impl<R> Clone for Reg<R>` и `impl<R> Copy for
Reg<R>` руками, без ограничений.

</div>
