Заготовки лежат в `exercises/ch05`, тесты, общие для заготовок и решений,
лежат в `tests-shared/ch05.rs`. Проверка:

$ cargo test -p ch05-exercises task_b     # одна задача

cargo собирает тесты. Пока задачи не решены, тесты падают на `todo!()`,
на пустых ответах или на метке `ЗАГОТОВКА` во внешних файлах. Разборы
решений в [приложении E](../appendix-e/ch05.md), но сначала попробуйте
сами.

Тест проверяет равносильность, а не совпадение текста. Рядом с исходной
функцией он ставит две: `stud_имя` с вашей сигнатурой, которая вызывает

## B. Токенизатор без выделения памяти

Напишите в `exercises/ch05/src/b_lexer.rs` лексер упрощённого INI для
конфигурации станции. Типы заданы:

```rust
{{#include ../../exercises/ch05/src/b_lexer.rs:types}}
```

`Lexer<'a>` — итератор с `Item = Result<Token<'a>, LexError>`. Правила
формата:

1. Строки делятся `\n`, `\r` в конце строки отбрасывается, пробелы в
   начале строки пропускаются.
2. Пустые строки и строки, начинающиеся с `#` или `;`, пропускаются.
3. `[имя]` — секция. Имя непустое, из символов `A–Z a–z 0–9 _ . -`.
   После `]` допустимы только пробелы и комментарий.
4. `ключ = значение` — ключ из тех же символов, пробелы вокруг `=`
   допустимы. Лексер выдаёт `Key`, затем `Value`.
5. Значение — остаток строки без пробелов по краям. Комментарий в
   значении начинается с `#` или `;` в начале значения или после пробела:
   `a#b` — значение целиком, `a #b` — значение `a`.
6. Значение в кавычках `"…"` — содержимое кавычек, `#` и `;` внутри —
   его часть. Экранирования нет. После закрывающей кавычки — только
   пробелы и комментарий.
7. Ошибка — строка и столбец с 1, столбец в *символах*, не в байтах. После
   ошибки лексер переходит к следующей строке, так что можно собрать все
   ошибки файла.

| Строка | Ошибка |
|---|---|
| `[uart` | `UnclosedSection`, столбец 1 — `[` |
| `[ua rt]`, `[секция]`, `[]` | `BadName`: первый недопустимый символ или `]` |
| `ba$d=1`, `=1` | `BadName`: `$`, `=` |
| `baud 9600` | `MissingEquals`, столбец 6 — где ждали `=` |
| `name = "abc` | `UnclosedQuote`, столбец 8 — открывающая кавычка |
| `x = "абв" z` | `TrailingGarbage`, столбец 11 — `z` |

Главное требование — ни одного выделения памяти: все строки в лексемах
— срезы исходного текста. Тест подменяет глобальный распределитель
счётчиком, разбирает 2000 секций и проверяет, что счётчик не сдвинулся, а
каждый срез лежит внутри исходного текста. Ещё один тест сверяет лексемы
на 500 случайных конфигурациях со смесью пробелов, кавычек, комментариев
и `\r\n`.

Лексер понадобится дальше: глава [7](../ch07/09-tasks.md) построит на нём
сообщения об ошибках, глава [31](../ch31.md) — фаззинг.

## C. Таблица вариантности

Часть 1. В `exercises/ch05/variance/covariant.rs` напишите функцию,
которая компилируется *только* благодаря ковариантности: где-то
`&'static` или другое длинное время жизни должно молча стать коротким.

Часть 2. В `variance/cell.rs` скопируйте её и оберните в `Cell` тип,
время жизни которого укорачивалось. Файл должен перестать компилироваться,
и тест проверит, что из-за инвариантности `Cell`, а не по другой причине.
В комментарии объясните, какую ошибку памяти предотвращает этот отказ:
напишите, какой вызов `Cell::set` её бы создал.

Часть 3. Для каждого типа из списка определите вариантность по `'a` и
запишите в `VARIANCE` в `exercises/ch05/src/c_variance.rs`:

| № | Тип |
|---|---|
| 1 | `&'a u8` |
| 2 | `&'a mut u8` |
| 3 | `&'a mut &'a u8` |
| 4 | `*const &'a u8` |
| 5 | `*mut &'a u8` |
| 6 | `Cell<&'a u8>` |
| 7 | `fn(&'a u8)` |
| 8 | `fn(fn(&'a u8))` |
| 9 | `Box<dyn Fn(&'a u8)>` |
| 10 | `core::str::Lines<'a>` |

Тест узнаёт правильный ответ у компилятора: для каждого типа он собирает
две пробные функции, `T<'b> → T<'a>` и `T<'a> → T<'b>` при `'b: 'a`.
Первая компилируется только у ковариантного типа, вторая — только у
контравариантного. Попробуйте ответить без компилятора.

## D. Окна `&mut [T]`

`slice.windows(n)` отдаёт перекрывающиеся окна только для чтения:
`[1, 2, 3, 4]` с `n = 2` даёт `[1, 2]`, `[2, 3]`, `[3, 4]`.
`chunks_mut` отдаёт изменяемые куски, но без перекрытия. Изменяемых
перекрывающихся окон в стандартной библиотеке нет, и не случайно.

Часть 1. В `exercises/ch05/windows/iterator.rs` реализуйте
`Iterator for WindowsMut` с `type Item = &'s mut [T]`. Тест ждёт, что
реализация *не* скомпилируется с ошибкой «lifetime may not live long
enough». В комментарии покажите программу из трёх строк, которая
получила бы два `&mut` на один элемент, если бы реализация
компилировалась.

Часть 2. В `exercises/ch05/src/d_windows.rs` реализуйте одалживающий
итератор по образцу раздела [5.6](06-gat.md): трейт `LendingIterator`
с GAT дан, напишите `windows_mut` и `next`. Затем напишите `despike`:
фильтр одиночных выбросов в отсчётах датчика. Если соседи окна из трёх
отсчётов равны, а середина отличается от них больше чем на `threshold`,
середина становится равной соседям. Окна перекрываются, и исправленный
отсчёт должен быть виден следующему окну: из `[10, 10, 99, 10, 10, -50,
10, 11]` с порогом 20 получается `[10, 10, 10, 10, 10, 10, 10, 11]`, два
исправления.

Тест `overlapping_writes` делает сумму с накоплением на месте —
`w[1] += w[0]` в окнах по два — и ждёт `[1, 3, 6, 10]` из
`[1, 2, 3, 4]`. Тест `despike_samples` проверяет и видимость
исправлений — `[0, 50, 0, 50, 0]` должен стать нулями за два исправления,
— и крайние значения `i32`: разность `i32::MAX - i32::MIN` в `i32` не
помещается.
