# 5.2. Структуры со ссылками: разбор без копирования

## Пакет от датчика

Датчик присылает пакет записей «тег, длина, значение» (TLV): байт тега,
байт длины и столько байт значения. Пакет лежит в буфере приёма, куда его
положил контроллер DMA или прерывание UART. На C разбор без копирования
выглядит так:

```c
struct tlv {
    uint8_t tag;
    uint8_t len;
    const uint8_t *value; /* указывает в буфер приёма */
};
```

`value` указывает в буфер, и запись годится, пока буфер не перезаписан
следующим пакетом. Нарушить это легко: сохранить запись «на потом» и
снова запустить приём в тот же буфер — ошибка из введения к главе.

На Rust запись хранит срез, а время жизни буфера становится параметром
структуры:

```rust
{{#include ../../code/ch05/src/tlv.rs:tlv}}
```

- `Tlv<'a>` — запись, которая смотрит в буфер со временем жизни `'a`.
  Длина хранится в самом срезе, отдельное поле не нужно.
- `Records<'a>` — курсор: срез всего пакета и позиция. Тип элемента
  итератора — `Result<Tlv<'a>, TlvError>` с тем же `'a`. Записи связаны
  с буфером, а не с курсором, поэтому переживают его.
- `rest` возвращает `&'a [u8]` с явным временем жизни. По правилу 3 без
  аннотации результат был бы привязан к `&self`, то есть к курсору
  (раздел [5.1](01-elision.md)).
- Пакет, оборванный посреди записи, — ошибка с позицией и числом
  недостающих байт, а не паника и не чтение за концом буфера.

Поиск по тегу не пишет ни одного времени жизни — работают правила
элизии:

```rust
{{#include ../../code/ch05/src/tlv.rs:find}}
```

Ссылка на входе одна, и результат получает её время жизни: значение
смотрит в `buf`, а курсор живёт только внутри функции.

## Что проверяет компилятор

Записи не переживают буфер:

```text
error[E0597]: `rx` does not live long enough
  --> tlv_0.rs:8:21
   |
 7 |     let rx = vec![0x01, 0x02, 0xAA, 0xBB];
   |         -- binding `rx` declared here
 8 |     first = records(&rx).next();
   |                     ^^^ borrowed value does not live long enough
 9 | }
   | - `rx` dropped here while still borrowed
10 | println!("{first:?}");
   |            ----- borrow later used here
```

И не дают изменить буфер, пока живы, — это и есть «DMA пишет следующий
пакет»:

```text
error[E0502]: cannot borrow `rx` as mutable because it is also borrowed as immutable
 --> tlv_1.rs:7:1
  |
6 | let first = records(&rx).next();
  |                     --- immutable borrow occurs here
7 | rx.fill(0); // DMA пишет следующий пакет
  | ^^ mutable borrow occurs here
8 | println!("{first:?}");
  |            ----- immutable borrow later used here
```

Настоящий DMA пишет в память не через `&mut`, а сам, и компилятор о нём
не знает. Чтобы проверка работала и с ним, буфер на время передачи
отдают объекту-владельцу, который держит заимствование, — так устроено
окно DMA в разделе [5.4](04-variance.md).

Тест `zero_copy` подтверждает, что значение — не копия: адрес среза
`name.value` равен адресу седьмого байта `rx`. Курсор к тому моменту уже
уничтожен, а записи живы:

```rust,ignore
let (t, name) = {
    let mut it = records(&rx);
    // ...
    (t, name)
}; // курсора уже нет, записи живы
assert_eq!(name.value.as_ptr(), rx[6..].as_ptr());
```

Тест `sizes` проверяет размеры: `Tlv` занимает три машинных слова
(тег с выравниванием, указатель и длина среза), `Option<Tlv>` — столько
же, потому что ссылка не бывает нулевой и `None` кодируется нулём
(ниша, раздел [6.4](../ch06/04-niches.md)). Время жизни места не
занимает.

<div class="box hood">

**Под капотом.** У `struct Ref<'a, T> { r: &'a T }` есть неявное условие
`T: 'a`: ссылка не может жить дольше ссылок внутри `T`, иначе через неё
можно было бы дотянуться до мёртвых данных. С Rust 2018 компилятор
выводит такие условия из типов полей сам (RFC 2093), и писать `T: 'a` в
структуре почти не приходится. Явно оно нужно там, где типа поля нет, —
например, в `Box<dyn Trait + 'a>` (раздел [5.3](03-static.md)).

</div>

<div class="box trap">

**Ловушка.** Структура не может хранить буфер *и* ссылки в него:

```rust,ignore
pub struct Packet<'a> {
    pub rx: Vec<u8>,
    pub first: &'a [u8], // хочется: в собственный rx
}
```

Собрать такую структуру из локального `rx` не выйдет: E0505 (`rx`
перемещается в структуру, пока на него смотрит `first`) и E0515
(возвращается значение, ссылающееся на локальную переменную).
Перемещение структуры сдвинуло бы `rx`, а Rust перемещает значения
побайтным копированием без участия программиста (глава 3). Выходы: хранить
вместо ссылок смещения, как арена в разделе [4.6](../ch04/06-limits.md),
или держать буфер снаружи и передавать структуре `&'a [u8]`. Типы,
которые обязаны ссылаться на себя, появятся с `Pin` в
[главе 22](../ch22.md).

</div>
