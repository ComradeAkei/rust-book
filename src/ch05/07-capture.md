# 5.7. Что захватывает `impl Trait`

## Скрытый тип и его параметры

`-> impl Iterator<Item = &'c str>` прячет настоящий тип результата —
ниже это `Map<slice::Iter<'c, String>, _>` с функцией `String::as_str`
внутри. Но проверке у
вызывающего надо знать, на что этот тип может ссылаться: пока жив
итератор, должно быть живо всё, что он держит. Список параметров
функции, которые может содержать скрытый тип, называется *захватом*.

С [редакции][g-edition] 2024 скрытый тип захватывает *все* параметры функции, в том
числе все времена жизни. В 2021 времена жизни захватывались, только если
их называли в границах, и типичная ошибка была обратной: E0700, «hidden
type captures lifetime that does not appear in bounds». Обе редакции
сравнивает приложение [B.3](../appendix-b.md).

## Лишний захват

Конфигурация разобрана на строки, функция отдаёт строки одной секции:

```rust
{{#include ../../code/ch05/src/capture.rs:capture}}
```

Имя секции `section_all` использует только для поиска границ, итератор
его не держит. Но по сигнатуре `'n` захвачено, и имя должно жить, пока
жив итератор. Временная строка с именем этого не выдерживает:

```text
error[E0716]: temporary value dropped while borrowed
 --> capture_0.rs:6:31
  |
6 | let vals = section_all(&cfg, &String::from("uart"));
  |                               ^^^^^^^^^^^^^^^^^^^^ - temporary value is freed at the end of this statement
  |                               |
  |                               creates a temporary value which is freed while still in use
7 | assert_eq!(vals.count(), 1);
  |            ---- borrow later used here
  |
note: this call may capture more lifetimes than intended, because Rust 2024 has adjusted the `impl Trait` lifetime capture rules
 --> capture_0.rs:6:12
  |
6 | let vals = section_all(&cfg, &String::from("uart"));
  |            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
help: if you can modify this crate, add a precise capturing bound to avoid overcapturing: `+ use<'c>`
 --> code/ch05/src/capture.rs:51:62
```

Компилятор сам называет причину и лекарство. `use<'c>` в `section`
перечисляет захваченное явно: итератор держит конфигурацию и только её.
Тест вызывает `section` с именем из `format!`, которое умирает в конце
строки, а итератор используется на следующей.

Список в `use<..>` должен содержать все параметры-типы функции: rustc
1.97 на пропуск отвечает «`impl Trait` must mention all type parameters
in scope in `use<...>`». `use<>` значит «не захватывает ничего» — так пишут
функции, которые возвращают итератор по индексам или по копиям.

## Граница `+ 'c`

До `use<..>` (Rust 1.82) обходились границей времени жизни:

```rust
{{#include ../../code/ch05/src/capture.rs:outlives}}
```

Она говорит другое: скрытый тип по-прежнему захватывает `'n`, но живёт
не меньше `'c`. Проверке у вызывающего этого хватает, и тест вызывает
`section_outlives` с временным именем так же, как `section`. Однако
`+ 'c` — требование к скрытому типу, а не список: оно не подойдёт, если
скрытый тип содержит параметр-тип, о котором неизвестно, что он живёт
не меньше `'c`. `fn g<'c, T>(x: &'c u8, t: T) -> impl Sized + 'c { t }`
не компилируется (E0309, «the parameter type `T` may not live long
enough»), а с `+ use<'c, T>` — компилируется. `use<..>` говорит ровно
то, что нужно, и его предлагает сам компилятор.

<div class="box hood">

**Под капотом.** Захват — свойство только проверки. Скрытый тип известен
компилятору целиком, и в машинном коде `impl Iterator` — тот же
`Map<Iter<..>, ..>`, без косвенных вызовов и без упаковки в `Box`.
`async fn` — тоже функция, возвращающая скрытый тип (`impl Future`), и
захватывает все параметры по тем же правилам; разговор о ней — в главе
[22](../ch22/02-state.md).

</div>
