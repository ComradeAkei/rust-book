# 24.3. Спаны, ошибки и гигиена

## Ошибка — тоже токены

Процедурный макрос не может «выдать ошибку» напрямую: на stable у него
нет API диагностики (`proc_macro::Diagnostic` нестабилен, issue #54140),
а значит, и предупреждений. Он может только вернуть токены, и ошибка —
это вызов `compile_error!` с нужным спаном. `syn::Error` хранит текст и
место и умеет превращаться в такие токены:

```rust,ignore
{{#include ../../code/ch24-macros/src/describe.rs:unit}}
```

Второй тест показывает, что получается из ошибки: строка токенов
`::core::compile_error! { "..." }`. Сам макрос отработал успешно — он
вернул код, — а ошибку выдаст компилятор, когда раскроет
`compile_error!`, и укажет на спан его токенов. Derive на перечислении:

```text
{{#include ../../code/ch24/tests/ui/describe_enum.stderr}}
```

`Error::new(span, текст)` указывает на один спан, `Error::new_spanned(узел,
текст)` — на весь узел syn: от первого его токена до последнего. Склеить
два спана в один на stable нельзя (`Span::join` нестабилен, issue
#54725), поэтому syn идёт в обход: первому токену `compile_error!` даёт
спан начала узла, последнему — спан его конца, и компилятор подсвечивает
всё между ними. Так в сообщениях ниже подчёркнуто `byte: u8` целиком, а
не одно `byte`.

## Все ошибки сразу

Если макрос возвращает первую найденную ошибку, пользователь чинит их по
одной за сборку. `syn::Error::combine` собирает несколько ошибок в одну,
и каждая выводится отдельно, со своим спаном. Атрибуты-помощники
`Describe` разбираются с накоплением ([24.4](04-attributes.md)):

```text
{{#include ../../code/ch24/tests/ui/describe_attrs.stderr}}
```

Три ошибки в двух атрибутах структуры и атрибуте поля — за одну сборку.
Среднее сообщение — «expected integer literal» — составил не автор
макроса, а syn: `meta.value()?.parse::<LitInt>()` встретил строку, и его
ошибка уже указывает на неё.

## Куда укажет ошибка в сгенерированном коде

Самые трудные ошибки возникают *после* макроса: он сгенерировал код,
код не прошёл проверку типов. Компилятор показывает спан токена, на
котором проверка споткнулась, — и этот спан выбрал автор макроса.
`quote_spanned!` задаёт спан всем новым токенам шаблона:

```rust,ignore
{{#include ../../code/ch24-macros/src/describe.rs:dump_spans}}
```

`Describe` на структуре, поле которой не реализует `Debug`:

```text
{{#include ../../code/ch24/tests/ui/describe_not_debug.stderr}}
```

Ошибка указывает на поле `raw: Opaque` — на то, что надо исправить.
Подсвечено от имени до типа: токен `raw` в `&self.#member` пришёл из
объявления со своим спаном, остальные токены выражения получили спан
типа, и компилятор показал выражение целиком. Тот же derive, но весь
сгенерированный код — со спаном места вызова (`DescribeCallSite`, так
по умолчанию делает `quote!`):

```text
{{#include ../../code/ch24/tests/ui/describe_not_debug_call_site.stderr}}
```

Текст ошибки тот же, но указывает она на `#[derive(...)]`. В структуре из
двух полей догадаться можно; в регистровой карте из сорока — нет.
Правило: **каждый сгенерированный токен, который может не пройти
проверку, несёт спан той части входа, которая за него отвечает**: вызов
с полем — спан поля, проверка размера — спан обещанного размера,
обращение к имени прерывания — спан имени.

## Проверка при компиляции со спаном

`#[describe(size = 8)]` обещает размер, и derive превращает обещание в
константу:

```rust,ignore
{{#include ../../code/ch24-macros/src/describe.rs:size_check}}
```

`const _: () = assert!(...)` вычисляет компилятор, а паника при
вычислении константы — ошибка E0080. Спан всей проверки — спан литерала
`8`, поэтому ошибка указывает в атрибут:

```text
{{#include ../../code/ch24/tests/ui/describe_size.stderr}}
```

Для обобщённой структуры такая проверка невозможна: размер
`Sample<T>` зависит от `T`, а безымянная константа не может использовать
параметры типа. Derive отказывает сразу и со спаном того же литерала.

<div class="box trick">

**Трюк — проверка размера из derive.** Кадр протокола, блок регистров,
запись во flash — у них размер — часть договора с другой стороной.
`#[describe(size = 8)]` ставит проверку рядом с объявлением, и при
добавлении поля сборка падает с сообщением в атрибуте, а не в тесте,
который запустят позже. Тот же приём годится для смещений
(`offset_of!(Self, crc) == 4`) и выравнивания — и для всего, что
вычисляется в `const`.

</div>

<div class="box c">

**Как в C.** В C11 то же пишут руками:
`_Static_assert(sizeof(struct header) == 8, "header: 8 байт");` — рядом
со структурой, и только если не забыли. Ошибка `_Static_assert`
указывает на сам `_Static_assert`; derive может направить её в любое
место объявления.

</div>

## Гигиена: `call_site` и `mixed_site`

Спан несёт не только место, но и правило разрешения имён. У процедурного
макроса выбор:

- `Span::call_site()` — имя ведёт себя так, будто его написал
  вызывающий: видит его переменные и видно им. Так по умолчанию делают
  `quote!` и все токены, разобранные из строки;
- `Span::mixed_site()` — гигиена `macro_rules!` (раздел
  [23.3](../ch23/03-hygiene.md)): локальные переменные, метки и `$crate`
  разрешаются по месту определения макроса, остальное — по месту вызова;
- `Span::def_site()` — полная гигиена, где *всё* разрешается в крейте
  макроса; нестабилен (issue #54724).

Атрибут `#[traced]` вставляет в начало функции локальную переменную
`name` с именем функции и отмечает вызов в журнале:

```rust,ignore
{{#include ../../code/ch24-macros/src/traced.rs:traced}}
```

Две функции с одинаковым телом, но с разной гигиеной переменной:

```rust,ignore
{{#include ../../code/ch24/src/trace.rs:greet}}
```

```rust,ignore
{{#include ../../code/ch24/src/trace.rs:greet_test}}
```

С `mixed_site` переменная макроса не видна телу, и `name.len()` — это
длина аргумента, 4. С `call_site` переменная перекрыла аргумент, и
`greet_call_site("Ivan")` вернула длину строки `"greet_call_site"` — 15.
Компилятор заметил только неиспользованный аргумент: отсюда
`#[expect(unused_variables)]`, без которого сборка с `-D warnings` упала
бы.

Гигиена `mixed_site` прячет только локальные переменные. Функция или
тип, которые сгенерировал макрос, видны вызывающему при любом спане, и
два вызова макроса с одинаковым вспомогательным `fn helper()` в одном
модуле столкнутся. Помощники прячут в безымянную константу (`const _: ()
= { ... };`) или дают им имена от имени пользователя — как
`__ch24_UART0` у `#[interrupt]` ([24.4](04-attributes.md)). Когда нужны и
гигиена, и хорошая ошибка, спаны комбинируют:
`Span::mixed_site().located_at(field.span())` — разрешение имён от
одного, место в исходнике от другого.

<div class="box trap">

**Ловушка — `call_site` по умолчанию.** `quote!` даёт новым токенам спан
вызова, и переменная `let value = ...` в сгенерированном теле функции
может перекрыть аргумент пользователя с тем же именем. Код компилируется
и делает не то. Все локальные переменные, которые макрос вставляет в код
пользователя, — с `Span::mixed_site()` (задача C).

</div>
