# 23. Декларативные макросы

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** macro_rules!, фрагменты (expr, ident, ty, tt, pat, literal, block, path, lifetime, vis), повторения $(...)*. Гигиена, рекурсия, внутренние правила @internal, TT-muncher и накопители. $crate, #[macro_export], порядок определения, лимит рекурсии.

**Как в C.** Текстовый препроцессор, X-macros, do { } while (0), повторное вычисление аргументов.

**Железо.** Генерация описаний регистров и таблиц обработчиков. Раскрытый макрос не дороже рукописного кода.

**Трюки и ловушки.** Подсчёт аргументов при компиляции. Аналог X-macro: один список, несколько генераций. Захваченный как expr фрагмент уже нельзя сравнить с токенами. Гигиена не распространяется на функции и типы.

**Задачи**

- A. Для 6 вызовов макросов предскажите раскрытие и проверьте через cargo expand.
- B. Макрос в духе bitflags для флагов регистра с операциями |, &, ! и читаемым Debug.
- C. Макрос описания периферии peripheral! { UART0 @ 0x4000_C000 { DR: u32 @ 0x00, FR: u32 @ 0x18 ro } }. Он генерирует volatile-аксессоры, а запись в ro-регистр не компилируется. Проверка на UART машины lm3s6965evb в QEMU.
- D. TT-muncher для конечных автоматов: fsm! { Idle --start--> Running, Running --stop--> Idle } генерирует enum состояний, функцию перехода и строку с графом для Graphviz. Найдите границу, за которой задачу разумнее решать процедурным макросом.
