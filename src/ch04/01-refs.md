# 4.1. Ссылки и правило читателей и писателя

## Два вида ссылок

`&x` берёт разделяемую ссылку на `x`, `&mut x` — уникальную. Тип ссылки
пишется так же: `&Calib` и `&mut Calib`. Через `&T` значение можно только
читать, через `&mut T` — читать и менять:

```rust
{{#include ../../code/ch04/src/refs.rs:rules}}
```

В `readers_then_writer` сначала живут два читателя, `r1` и `r2`, потом
появляется писатель `w`. Это разрешено, потому что после `w` читатели
больше не используются: заимствование длится до последнего использования
ссылки, а не до конца блока (подробнее в разделе
[4.2](02-borrows.md)). После `trim` писатель тоже больше не нужен, и
`&c` в последней строке снова законна.

Правило «много читателей или один писатель» проверяется для каждого
места в памяти, на которое смотрят ссылки. Нарушить его можно тремя
способами, и у каждого свой код ошибки.

Два писателя одновременно — E0499:

```text
error[E0499]: cannot borrow `v` as mutable more than once at a time
 --> e0499.rs:4:13
  |
3 |     let a = &mut v;
  |             ------ first mutable borrow occurs here
4 |     let b = &mut v;
  |             ^^^^^^ second mutable borrow occurs here
5 |     a.push(4);
  |     - first borrow later used here
```

Читатель и писатель одновременно — E0502, пример из введения к главе.

Изменение значения, на которое смотрит ссылка, без всякой второй ссылки:
присваивание самому владельцу — E0506:

```text
error[E0506]: cannot assign to `limit` because it is borrowed
 --> e0506.rs:4:5
  |
3 |     let r = &limit;
  |             ------ `limit` is borrowed here
4 |     limit = 200;
  |     ^^^^^^^^^^^ `limit` is assigned to here but it was already borrowed
5 |     println!("{r}");
  |                - borrow later used here
```

Владелец, пока его значение заимствовано, ограничен так же, как ссылки:
под `&` он может только читать, под `&mut` не может ничего. [Перемещать][g-move]
заимствованное значение тоже нельзя (E0505), иначе ссылка указывала бы на
место, из которого значение ушло. Сами примеры — *doc-тесты* (doctests)
в `code/ch04/src/refs.rs`: примеры кода из документирующих комментариев
`///`, которые `cargo test` собирает и запускает. Пометка
`compile_fail,E0499` и т. д. требует, чтобы пример не собрался, а
*rustdoc*, генератор документации, который и запускает doc-тесты, на
nightly проверяет, что ошибка именно та.

Ещё одно условие — ссылка не переживает значение. Ссылку на локальную
переменную нельзя вернуть из функции и нельзя сохранить в структуре,
которая живёт дольше переменной. Как компилятор это проверяет, разбирает
[глава 5](../ch05/index.md).

<div class="box c">

**Как в C.** `const uint32_t *p` обещает только, что *через `p`* значение
не меняют. Через другой указатель его менять можно, и компилятор обязан
это учитывать: после любой записи через `uint32_t *` значение `*p` надо
перечитать. `&T` в Rust обещает больше: пока ссылка жива, значение не
меняет никто. Ближайший аналог `&mut T` — `T *restrict`, но `restrict`
проверяет только программист, а его нарушение — неопределённое
поведение без диагностики. Раздел [4.5](05-noalias.md) сравнивает их в
машинном коде.

</div>

## Ссылка в машинном коде

Ссылка — это адрес. Ни счётчика читателей, ни флага «занято» в ней нет:
вся проверка прошла при компиляции.

```rust
{{#include ../../code/ch04/src/refs.rs:machine}}
```

```text
$ cargo asm -p ch04 --lib ch04_apply 0
ch04_apply:
	mov eax, esi
	sub eax, dword ptr [rdi]
	imul eax, dword ptr [rdi + 4]
	ret
```

`rdi` — адрес `Calib`, поля читаются по смещениям 0 и 4. Так же выглядела
бы функция на C с `const struct calib *`.

`Option<&T>` занимает те же 8 байт. Ссылка не бывает нулевой, и `None`
кодируется нулём — это [ниша][g-niche] из раздела [6.4](../ch06/04-niches.md):

```text
$ cargo asm -p ch04 --lib ch04_apply_opt
ch04_apply_opt:
	mov eax, esi
	test rdi, rdi
	je .LBB32_2
	sub eax, dword ptr [rdi]
	imul eax, dword ptr [rdi + 4]
.LBB32_2:
	ret
```

Это ровно `if (c) ...` из C. На Cortex-M3 проверка уходит в блок [`it`][g-conditional-execution],
а оба поля читаются одной `ldrd`:

```text
$ cargo asm -p ch04 --lib --target thumbv7m-none-eabi ch04_apply_opt
ch04_apply_opt:
	push {r7, lr}
	mov r7, sp
	cmp r0, #0
	ittt ne
	ldrdne r0, r2, [r0]
	subne r0, r1, r0
	mulne r1, r0, r2
	mov r0, r1
	pop {r7, pc}
```

<div class="box trap">

**Ловушка.** Ссылка обязана быть ненулевой, выровненной и указывать на
допустимое значение *всегда*, а не только когда её разыменовывают.
Компилятор пользуется этим и после появления ссылки считает адрес
ненулевым:

```rust
{{#include ../../code/ch04/src/refs.rs:late_null_check}}
```

```text
$ cargo asm -p ch04 --lib --target thumbv7m-none-eabi ch04_late_null_check
ch04_late_null_check:
	push {r7, lr}
	mov r7, sp
	ldrb r0, [r0]
	bl ch04::refs::log_byte
	movs r0, #0
	pop {r7, pc}
```

`p.is_null()` превратилась в константу `false`: раз `&*p` передана в
функцию как `&u8`, нулём `p` быть не могла. При нулевом `p` программа
прочтёт адрес 0, а на Cortex-M там [таблица векторов][g-vector-table] прерываний, и ошибки
не будет вовсе. В C разыменование нулевого указателя тоже UB, но
`int *p = NULL` законно, и проверка до разыменования работает. На границе
с C (приложение [C](../appendix-c.md)) [сырой указатель][g-raw-pointer] становится
ссылкой только после проверки.

</div>
