# 4.4. Срезы, авторазыменование и приведения

В C между `struct s`, `struct s *` и `struct s **` нужно переходить руками:
`.`, `->`, `(*pp)->`. В Rust точка работает через любое число ссылок и
умных указателей, а `&Vec<u8>` подходит туда, где ждут `&[u8]`. Это
удобно, но скрывает, что именно происходит, и раздел это показывает.

## Срезы

Срез `&[T]` — толстый указатель на часть массива или вектора: адрес
первого элемента и длина (раздел [1.6](../ch01/06-slices-str.md)). `&str` —
то же для UTF-8. Срез заимствует то, во что смотрит, по тем же правилам:
пока жив `&v[2..4]`, вектор `v` нельзя менять целиком, хотя срез касается
двух элементов. Как заимствовать части раздельно, показал раздел
[4.3](03-split.md).

Функция, которой нужны только данные, принимает срез, а не `&Vec<u8>` или
`&[u8; 64]`: тогда её можно вызвать и с вектором, и с массивом, и с куском
буфера DMA. На параметр `&Vec<T>` или `&String` clippy выдаёт
предупреждение `ptr_arg`.

## Авторазыменование в вызове метода

```rust
{{#include ../../code/ch04/src/deref.rs:autoderef}}
```

У `String` есть метод `len`. Чтобы вызвать его на `Box<String>` и на
`&&String`, компилятор перебирает типы получателя: сначала сам тип
выражения, потом `&` и `&mut` от него, потом разыменовывает (`*r`, а для
`Box` и других умных указателей — через трейт `Deref`) и повторяет.
Первый тип, у которого нашёлся метод, побеждает. Для `r: &&String` путь
такой: `&&String` → `&String` → `String`, и у `String` метод есть. У
`Vec<u8>` своего `len` нет, он объявлен у среза `[u8]`, и цепочка
доходит до `Vec<u8>` → `[u8]` через `Deref`.

## Приведения

Авторазыменование работает для получателя метода. Для аргументов функций,
`let` с указанным типом и возвращаемых значений есть *приведения при
разыменовании* (deref coercions): если ожидается `&U`, а дали `&T`, и `T`
через одно или несколько `Deref` превращается в `U`, компилятор вставит
разыменования сам.

```rust
{{#include ../../code/ch04/src/deref.rs:coercion}}
```

`&v` при `v: Vec<u8>` стал `&[u8]`, `&s` при `s: String` — `&str`. В `deep`
понадобилось три шага, и компилятор сделал их все.

Есть и второй вид приведения — от массива к срезу: `&[u8; 4]` → `&[u8]`.
Это не `Deref`, а *безразмерное приведение* (unsized coercion): длина
массива известна из типа и становится полем толстого указателя. Два вида
в одну цепочку не складываются:

```text
error[E0308]: mismatched types
  --> coerce.rs:12:22
   |
12 |     let y = checksum(&a);
   |             -------- ^^ expected `&[u8]`, found `&Box<[u8; 4]>`
   |             |
   |             arguments to this function are incorrect
   |
   = note: expected reference `&[u8]`
              found reference `&Box<[u8; 4]>`
```

Здесь `a: Box<[u8; 4]>`. `Deref` доводит `&Box<[u8; 4]>` до `&[u8; 4]`, а
дальше нужно приведение другого вида. Поэтому в `coercions` написано
`checksum(&*b)`: явное `*b` даёт `[u8; 4]`, а `&[u8; 4]` → `&[u8]` компилятор
делает сам.

## Вызов метода — это вызов функции

```rust
{{#include ../../code/ch04/src/deref.rs:method_call}}
```

`v.push(1)` и `Vec::push(&mut v, 1)` — один и тот же вызов. Ссылку на
получатель компилятор берёт сам: `&self` превращается в `&v`, `&mut self` —
в `&mut v` (двухфазную, раздел [4.2](02-borrows.md)), `self` — в
перемещение. Поэтому по вызову метода не видно, заимствует он или
забирает: это написано в сигнатуре, и редактор показывает её при
наведении.

<div class="box trap">

**Ловушка.** Если у типа нет `Clone`, `r.clone()` при `r: &Raw` не
ошибка: авторазыменование находит `Clone` у самой ссылки (`&T` всегда
`Copy` и `Clone`) и копирует *указатель*.

```text
warning: call to `.clone()` on a reference in this situation does nothing
 --> noop.rs:7:21
  |
7 |     let snapshot = r.clone(); // задумано: копия отсчётов
  |                     ^^^^^^^^
  |
  = note: the type `Raw` does not implement `Clone`, so calling `clone` on `&Raw` copies the reference, which does not do anything and can be removed
  = note: `#[warn(noop_method_call)]` on by default
```

Здесь программист хотел снимок отсчётов, пока DMA пишет следующий
кадр, а получил вторую ссылку на те же данные. Пока тип не меняется
через `&`, разницы не видно; с внутренней изменяемостью (глава
[14](../ch14/05-cells.md)) она становится ошибкой. Предупреждение
`noop_method_call` стоит держать ошибкой: в `code/ch04/src/deref.rs` это
doc-тест с `#![deny(noop_method_call)]`.

</div>

<div class="box c">

**Как в C.** Ближайшее в C — неявное приведение массива к указателю на
первый элемент, при котором длина теряется. Безразмерное приведение в
Rust длину сохраняет: она переходит из типа `[u8; 4]` в поле толстого
указателя. Именно поэтому функция с параметром `&[u8]` знает, сколько
байт ей дали, а `void f(uint8_t buf[64])` в C — нет.

</div>
