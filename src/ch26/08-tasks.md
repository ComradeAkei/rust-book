# 26.8. Задачи

Заготовки — в `exercises/ch26`, тесты, общие для заготовок и решений, —
в `tests-shared/ch26.rs`. Библиотека заготовок — `no_std` и собирается
как есть: функции с `todo!()` паникуют только при вызове. Задача C —
прошивка, своя для каждого, и её проверяет запуск в QEMU.

```console
$ cargo test -p ch26-exercises            # задачи A, B и D
$ cargo test -p ch26-exercises task_d     # одна задача
$ cargo test -p ch26-solutions            # эталон
```

Тесты с префиксом `rustc_` запускают закреплённые rustc и cargo: A
собирает пробы под x86-64 и Cortex-M0, B собирает и запускает вашу
программу, D смотрит ассемблер ваших функций под Cortex-M3 и M0.
Разборы — в [приложении E](../appendix-e/ch26.md), но сначала
попробуйте сами.

## A. Где живёт

нижнем слое он есть — `core`, `alloc` или только `std`, — и можно ли

подключив `alloc`, если нужно. Для каждого ответа сформулируйте
причину: что элементу нужно от среды — память, ОС, инструкции

## B. Hello без libc

Напишите в `exercises/ch26/tiny` программу для Linux x86-64 без `std` и
без libc: `_start`, `write(1, "Hello, world!\n", 14)` и `exit_group(0)`
инструкцией `syscall` (раздел [26.2](02-linux.md)). Ключи компоновки —
в `build.rs`, профиль — в `Cargo.toml` крейта.

Тест `rustc_b_tiny_says_hello_without_libc` собирает крейт в release,
запускает программу и проверяет: вывод — ровно «Hello, world!\n», код
выхода 0, тип ELF — `ET_EXEC`, без `PT_INTERP` и `PT_DYNAMIC`, в файле
нет строки «GLIBC», и он не больше 1 КиБ.

Затем уменьшайте. Сколько байт удалось оставить? Объясните каждый
оставшийся: заголовок ELF, заголовки программы, код, строка, — и что
ещё лежит в файле, если программе это не нужно. Что из этого нужно
ядру, чтобы запустить программу, а что — только инструментам вроде
`objdump`?

## C. Свой код запуска

Прошивка для Cortex-M без `cortex-m-rt`, в которой есть `.data` и
`.bss`:

- таблица векторов на Rust и обработчик сброса, который обнуляет
  `.bss`, копирует `.data` из flash и на Cortex-M4F открывает FPU,
  прежде чем вызвать `main` (раздел [26.4](04-startup.md));
- свой скрипт компоновки: `.data` с VMA в ОЗУ и LMA во flash, `.bss`
  без места в образе, `.uninit`, символы границ для кода запуска и
  проверки выравнивания;
- проверка: `static mut DATA: u32 = 5` и `static mut BSS: u32 = 0`
  после увеличения на единицу должны быть 6 и 1 — *при каждой
  загрузке*. Счётчик загрузок храните в `.uninit` и перезапускайте
  процессор программным сбросом (регистр `AIRCR`, ключ 0x05FA и бит
  `SYSRESETREQ`) дважды. Вывод — через semihosting; можно взять
  `cortex-m-semihosting` или `sh` из `ch26-bare`.

Прошивка должна работать в QEMU на lm3s6965evb (Cortex-M3), а с одним и
тем же кодом запуска — и на micro:bit (Cortex-M0) и mps2-an386
(Cortex-M4F). Что в обработчике сброса это ограничивает? Проверьте, что
ваша проверка ловит ошибки: уберите по очереди цикл обнуления, цикл
копирования и открытие FPU, — на какой загрузке и как проявится каждая?
Эталон — `firmware/ch26-boot`.

## D. Своя memcpy

В `d_mem.rs` напишите `memcpy`, `memmove`, `memset` и двенадцать
функций ARM EABI: `__aeabi_memcpy`, `__aeabi_memmove`, `__aeabi_memset`
и `__aeabi_memclr` с суффиксами `4` и `8` и без. Подписи всех
пятнадцати — в заготовке, первые три:

```rust,ignore
{{#include ../../exercises/ch26/src/d_mem.rs:three}}
```

На голом железе функции экспортируются под своими именами и заменяют
слабые определения из `compiler_builtins` (раздел
[26.5](05-memcpy.md)). Тесты:

- `task_d_memcpy_every_alignment` — все сочетания смещений источника и
  приёмника от 0 до 3 и длины от 0 до 40;
- `task_d_memmove_overlaps_both_ways` — перекрытие в обе стороны;
- `task_d_aeabi_memset_argument_order` — `__aeabi_memset(dest, n, c)`:
  порядок не тот, что у `memset`;
- `rustc_d_no_mem_calls_on_cortex_m3` и `…_m0` — ассемблер ваших
  функций под обе цели: ни одна функция памяти не вызывает себя или
  другую, кроме обёрток `__aeabi_*`, которым можно звать `memcpy`,
  `memmove` и `memset`.

Сначала напишите `memset` и обёртки самым простым циклом и посмотрите,
что скажет последний тест. Почему? Как сделать, чтобы цикл остался
циклом, — для всего крейта, а не одной функции? Затем сделайте `memcpy` и `memset` быстрее побайтовых, где
адреса выровнены.

Проверка на железе — прошивка `firmware/ch26-tasks`: она подключает
решение с возможностью `count` и считает, сколько раз компилятор позвал
ваши функции из функций раздела 26.5:

```console
$ cd firmware && cargo run --release -p ch26-tasks

ch26_clear       memcpy 0  memmove 0  memset 1  результат верен
ch26_fill        memcpy 0  memmove 0  memset 1  результат верен
ptr::copy        memcpy 0  memmove 1  memset 0  результат верен
вызовы пришли в наши функции: 5 из 5
```

Почему до `main` — ноль вызовов, хотя `Reset` из cortex-m-rt копирует
`.data` и обнуляет `.bss`?
