# 26.3. Cortex-M без cortex-m-rt

## Что делал cortex-m-rt

Все прошивки до этой главы начинались с `#[entry]` из `cortex-m-rt`.
Крейт давал пять вещей:

1. таблицу векторов — массив адресов, который процессор читает при
   сбросе и при каждом исключении;
2. обработчик сброса `Reset`: обнулить `.bss`, скопировать `.data`, на
   Cortex-M4F открыть FPU и вызвать `main`;
3. скрипт компоновки `link.x`, который кладёт таблицу по адресу 0, код
   и константы — во flash, переменные — в ОЗУ;
4. атрибуты `#[entry]`, `#[exception]`, `#[interrupt]`, которые
   проверяют сигнатуры и вписывают функции в таблицу;
5. обработчики по умолчанию для исключений, которые программа не
   определила.

Прошивка `firmware/ch26-bare` обходится без него, а заодно и без
`cortex-m` и `cortex-m-semihosting`: в `Cargo.toml` у неё одна
зависимость — крейт этой главы. Код запуска здесь — минимальный: только
то, без чего нельзя вызвать `main`. Полный — задача
[26.C](08-tasks.md).

## Таблица векторов

```rust,ignore
{{#include ../../firmware/ch26-bare/src/lib.rs:vectors}}
```

Первое слово — начальное значение `SP`: процессор сам загрузит его в
регистр при сбросе, ещё до первой инструкции. Второе — адрес `Reset` с
установленным младшим битом: бит Thumb, без него процессор на Cortex-M
не перейдёт по адресу (раздел [12.3](../ch12/03-fnptr.md) показал этот
бит у всех адресов функций). Дальше — 14 обработчиков, у резервных слов
ноль.

`Option<unsafe extern "C" fn()>` — тип, у которого `None` гарантированно
представлен нулём: у указателя на функцию нет нулевого значения, и
компилятор отдаёт его под `None`. Поэтому таблица — `#[repr(C)]`-
структура ровно на 16 слов, а не массив `usize` с приведениями.

`_stack_start` — символ из скрипта компоновки, конец ОЗУ. Объекта по
этому адресу нет, и читать `_stack_start` нельзя: `&raw const` берёт
адрес, не создавая ссылки. Раздел [25.6](../ch25/06-flash.md) так же
читал `__sdata` из `link.x`.

`VECTORS` неизменяемый, и `#[link_section = ".vector_table"]` кладёт его
в свою секцию, а `#[no_mangle]` даёт имя, которое знает скрипт. Сырой
указатель не `Sync`, и `static` с ним не скомпилировался бы без
`unsafe impl Sync`: таблицу никто не меняет, и данных за указателем
никто не разделяет.

## Обработчик сброса

```rust,ignore
{{#include ../../firmware/ch26-bare/src/lib.rs:reset}}
```

`Reset` — обычная функция на Rust, и это допустимо только потому, что
готовить ей нечего. Стек есть: его вершину процессор взял из слова 0. А
`.data` и `.bss` в этой прошивке пусты, и скрипт компоновки это
проверяет (ниже). Компилятор вправе считать, что каждый `static` уже
содержит начальное значение, и обычная функция при непустой `.data`
прочитала бы мусор. Что тогда — раздел [26.4](04-startup.md).

Точку входа связывает компоновщик: `Reset` зовёт внешнюю функцию
`ch26_main`, а определяет её макрос `entry!` в прошивке:

```rust,ignore
entry!(main);
```

Он раскрывается в `#[no_mangle] fn ch26_main() -> !`, которая вызывает
`main` через указатель типа `fn() -> !` — так проверяется сигнатура.
Тот же приём у `#[entry]` из cortex-m-rt: имя `main` он переименовывает,
чтобы его нельзя было вызвать второй раз.

```rust,ignore
{{#include ../../firmware/ch26-bare/src/lib.rs:fault}}
```

Один обработчик на все исключения: номер текущего исключения процессор
держит в регистре `IPSR` — 3 для HardFault, 11 для SVCall, 15 для
SysTick.

## Скрипт компоновки

```text
{{#include ../../firmware/ch26-bare/ch26.ld}}
```

- `INCLUDE memory.x` — общая карта памяти прошивок: `FLASH` с адреса 0
  на 256 КиБ, `RAM` с 0x2000_0000 на 16 КиБ. Её кладёт рядом
  `build.rs`, как в прошивках с cortex-m-rt.
- `ENTRY(Reset)` — точка входа в заголовке ELF. Процессору она не
  нужна, он берёт адрес из таблицы, но по ней QEMU и gdb знают, откуда
  начинать, а компоновщик — с чего собирать граф используемых секций.
- `EXTERN(VECTORS)` и `KEEP` — таблицу никто не вызывает, и без них
  компоновщик выбросил бы её как мусор (`--gc-sections` rustc передаёт
  по умолчанию).
- `.vector_table ORIGIN(FLASH)` — таблица ровно по адресу 0. `ASSERT`
  после `SECTIONS` проверяет это на случай правки скрипта.
- `/DISCARD/` выбрасывает таблицы раскрутки ARM: при `panic = "abort"`
  они не нужны.
- Блоки `GUARD` — секция-ловушка для `.data` и `.bss` и проверка, что
  она пуста. Зачем — раздел [26.4](04-startup.md).

Скрипт `build.rs` кладёт в `OUT_DIR` под именем `link.x`, и ключ
`-Tlink.x` из `firmware/.cargo/config.toml` находит его, а не скрипт
cortex-m-rt: прошивка от того крейта не зависит.

## Вывод без cortex-m-semihosting

```rust,ignore
{{#include ../../firmware/ch26-bare/src/sh.rs:sh}}
```

Semihosting (раздел [0.6](../ch00/06-qemu.md)) — инструкция `bkpt 0xAB`
с номером операции в `r0` и аргументом в `r1`. `SYS_WRITE0` печатает
строку C, и `put` режет текст на куски по 63 байта и дописывает ноль.
`SYS_EXIT` с причиной `ApplicationExit` завершает QEMU с кодом 0, с
другой — с кодом 1. `options(readonly)`: операция читает память по
указателю, но не пишет.

Числа печатают свои `hex` и `dec`, без `core::fmt`. И не только ради
размера: `core::str::from_utf8(…).unwrap()` в них подтянул бы `Debug`
для `Utf8Error` и вместе с ним `core::fmt` — несколько килобайт ради
паники, которой не бывает. Поэтому цифры превращает в `&str`
`from_utf8_unchecked` с проверкой ASCII в отладочной сборке.

## Запуск

```rust,ignore
{{#include ../../firmware/ch26-bare/src/main.rs:main}}
```

```console
$ cd firmware && cargo run --release -p ch26-bare
ch26-bare: без cortex-m-rt, без .data и .bss
SP в main: 0x20003fd8
слово 0: 0x20004000, слово 1: 0x000002c3
VECTORS по адресу 0x00000000, Reset по адресу 0x000002c3
$ llvm-size target/thumbv7m-none-eabi/release/ch26-bare
   text	   data	    bss	    dec	    hex	filename
   2460	      0	      0	   2460	    99c	target/thumbv7m-none-eabi/release/ch26-bare
```

Слово 0 — конец ОЗУ, 0x2000_4000; `SP` в `main` на 40 байт ниже: кадры
`Reset`, `ch26_main` и самой `main`. Слово 1 — адрес `Reset` с битом
Thumb. Таблица по адресу 0 — это объект `VECTORS`, поэтому `main` читает
её через указатель на `VECTORS`, а не из числа 0: у указателя,
сделанного из числа, нет provenance для объекта Rust (раздел
[16.4](../ch16/04-provenance.md)).

Вся прошивка — 2460 байт flash и ни байта ОЗУ под данные. Та же печать
через `hprintln!` из `cortex-m-semihosting` в `ch00-hello` занимает
27 КиБ: там `core::fmt`. На Cortex-M0 и Cortex-M4F вывод тот же, кроме
адресов: run-demos.sh запускает прошивку на всех трёх ядрах.

<div class="box c">

**Как в C.** Таблица векторов в C — массив `void (*const vectors[])(void)
__attribute__((section(".isr_vector")))`, где первое слово — приведённый
к указателю на функцию адрес стека: тип врёт ради одного слова. В Rust
таблица — структура, у которой первое поле — указатель на данные, а
остальные — `Option` указателей на функции, и нули резервных слов — это
`None`, а не `(void*)0`.

</div>

<div class="box trap">

**Ловушка.** На Cortex-M4F (thumbv7em-none-eabihf) `ch26-bare` работает,
хотя FPU никто не открывал. Это везение, а не корректность: в прошивке
просто нет инструкций FPU. Цель с аппаратной плавающей точкой разрешает
компилятору пользоваться регистрами `s0`–`s31` где угодно, и первая же
такая инструкция при закрытом FPU — UsageFault NOCP, а при выключенном
UsageFault — HardFault (задача [0.D](../ch00/07-tasks.md)). Код запуска для M4F обязан открыть FPU до
вызова Rust — это часть задачи C.

</div>
