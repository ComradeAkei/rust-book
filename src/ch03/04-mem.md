# 3.4. Обмен вместо перемещения

## Забрать, оставив замену

Из раздела 3.3: переместить значение из-под `&mut` нельзя, владелец
остался бы с дырой. Но часто именно это и нужно. Приёмник кадров хранит
состояние, и переход между состояниями должен *забрать* буфер из старого
состояния и положить в новое. Копировать байты ради этого не хочется.

Выход — обмен: забрать значение и одновременно положить на его место
другое. Владелец ни в какой момент не остаётся с дырой. В модуле
`core::mem` три функции для этого:

```rust
pub fn replace<T>(dest: &mut T, src: T) -> T;   // положить src, вернуть старое
pub fn take<T: Default>(dest: &mut T) -> T;     // то же с T::default()
pub fn swap<T>(x: &mut T, y: &mut T);           // обменять два значения
```

Конечный автомат приёмника на них:

```rust
{{#include ../../code/ch03/src/mem_fns.rs:replace}}
```

`mem::replace(self, Rx::Idle)` возвращает старое состояние по значению, и
`match` разбирает его, забирая буфер в `buf`. На короткое время в `*self`
лежит `Idle`, затем туда записывается новое состояние. Буфер переходит из
`Body` в `Done`, не копируясь: перемещается тройка указатель, ёмкость,
длина. `take_frame` делает то же через `mem::take`: у `Rx` есть
`Default`, и на месте остаётся `Rx::Idle`.

У `Option` есть свои методы с тем же смыслом: `opt.take()` забирает
значение и оставляет `None`, `opt.replace(x)` кладёт `Some(x)` и
возвращает старое. Поле `Option<T>` — обычный способ хранить то, что
можно забрать: как поле-указатель в C, которое может быть `NULL`.

<div class="box c">

**Как в C.** `mem::take` для буфера — это знакомая пара строк:

```c
uint8_t *buf = rx->buf;
rx->buf = NULL;     /* иначе rx_free освободит буфер второй раз */
```

Вторую строку в C забывают, и получается двойное освобождение. В Rust
её не написать нельзя: `mem::take` одна операция, а забрать поле без
замены компилятор не даст.

</div>

## Обмен

`mem::swap` меняет местами два значения одного типа. Сколько это стоит,
зависит от размера типа. Двойной буфер, в одну половину которого пишет
DMA, а вторую обрабатывает программа:

```rust
{{#include ../../code/ch03/src/mem_fns.rs:swap}}
```

`Box<[u8; 512]>` — указатель, поэтому `ch03_flip` меняет местами два
указателя, а 512 байт данных остаются на месте (rustc 1.97.0, x86_64):

```text
$ cargo asm -p ch03 --lib ch03_flip 0
ch03_flip:
	mov rax, qword ptr [rdi]
	mov rcx, qword ptr [rdi + 8]
	mov qword ptr [rdi], rcx
	mov qword ptr [rdi + 8], rax
	ret
```

Без `Box` обмен обязан переставить все байты, и для массивов по 512 байт
это 128 инструкций `movups`: 16 раз по 32 байта из каждого массива
(сокращено):

```text
$ cargo asm -p ch03 --lib ch03_flip_inline
ch03_flip_inline:
	movups xmm0, xmmword ptr [rdi]
	movups xmm1, xmmword ptr [rdi + 16]
	movups xmm2, xmmword ptr [rsi]
	movups xmm3, xmmword ptr [rsi + 16]
	movups xmmword ptr [rdi], xmm2
	movups xmmword ptr [rdi + 16], xmm3
	movups xmmword ptr [rsi], xmm0
	movups xmmword ptr [rsi + 16], xmm1
	...
	movups xmmword ptr [rsi + 480], xmm0
	movups xmmword ptr [rsi + 496], xmm1
	ret
```

То же правило верно для `replace`, `take` и любого перемещения:
перемещается представление значения, и у большого значения оно большое.
Раздел 3.5 разбирает, во что это обходится на Cortex-M.

## ManuallyDrop

`ManuallyDrop<T>` — обёртка того же размера, что `T`, которая отключает
автоматический вызов деструктора. Когда и вызывать ли его, решает код
вручную.

```rust
{{#include ../../code/ch03/src/mem_fns.rs:manually_drop}}
```

Поля `Driver` объявлены в порядке «тактирование, шина», а уничтожаются в
порядке «шина, тактирование»: журнал `["bus", "clock"]`. Вызов
`ManuallyDrop::drop` небезопасен: компилятор больше не следит, что
деструктор поля выполнится ровно один раз, и после него поле нельзя
трогать. Поэтому рядом с `unsafe` стоит комментарий `SAFETY`, который
объясняет, почему условия соблюдены. Такие комментарии — правило этой
книги (чек-лист в [приложении C](../appendix-c.md#граница-и-документация)),
и их наличие умеет проверять [линт][g-lint] `clippy::undocumented_unsafe_blocks`.

Если нужен только другой порядок уничтожения полей, проще переставить
объявления: порядок полей задан языком (раздел 3.2). `ManuallyDrop`
нужен там, где порядок зависит от данных во время работы, где поле
уничтожается раньше структуры, и в объединениях: поле `union` с
деструктором обязано быть обёрнуто в `ManuallyDrop` (раздел
[6.6](../ch06/06-unions.md)). Задача [3.B](07-tasks.md#b-страж-области)
строит на `ManuallyDrop` страж, который вызывает [замыкание][g-closure] при выходе
из области видимости.

## forget и утечки

```rust
{{#include ../../code/ch03/src/mem_fns.rs:forget}}
```

`mem::forget(a)` забирает значение и не вызывает деструктор: журнал
`["конец", "b"]`, имени `a` в нём нет. Функция безопасная. Утечка не
нарушает безопасность памяти: ничего не освобождено дважды, никто не
читает освобождённое, ресурс просто не вернули. Отсюда важное следствие:
**язык не гарантирует, что деструктор выполнится**. Небезопасный код не
вправе полагаться на `Drop` ради безопасности памяти. Раздел 3.6
показывает, где эта граница проходит на практике.

<div class="box hood">

**Под капотом.** Узнать, есть ли у типа код уничтожения, можно функцией
`mem::needs_drop::<T>()`. Её вычисляет компилятор. Коллекции, которые
сами управляют памятью, пользуются ею, чтобы не обходить в деструкторе
элементы, которым уничтожение не нужно; пример такого деструктора есть в
документации функции. Тест модуля проверяет:

- `needs_drop::<[u8; 512]>()` — ложь: байты уничтожать не нужно;
- `needs_drop::<Box<[u8; 512]>>()` — истина: надо освободить память;
- `needs_drop::<ManuallyDrop<Noisy>>()` — ложь, и размер у неё тот же,
  что у `Noisy`.

</div>
