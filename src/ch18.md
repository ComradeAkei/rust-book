# 18. FFI с C

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** extern "C" и unsafe extern "C" блоки, repr(C), типы из core::ffi (c_int, c_char, CStr, CString) и литералы c"...". Владение через границу: кто освобождает память. Непрозрачные дескрипторы, обратные вызовы, extern "C-unwind", вызов функций с переменным числом аргументов. bindgen, cbindgen, крейт cc, #[link], статическая и динамическая линковка.

**Как в C.** Строки с завершающим нулём, errno, соглашения о владении, записанные только в документации.

**Железо.** Детали System V AMD64 и AAPCS: передача структур и возврат больших структур через скрытый указатель. Выравнивание стека: 16 байт на x86_64, 8 байт на границах вызовов по AAPCS. Вызов Rust из C-кода производителя МК и CMSIS.

**Трюки и ловушки.** Трамплин для замыканий. Option<extern "C" fn> и `Option<NonNull<T>>` как указатели, допускающие null. Rust enum нельзя принимать из C: неизвестное значение даёт UB. CString::new(s).unwrap().as_ptr() возвращает висячий указатель.

**Задачи**

- A. Найдите ошибки в 6 FFI-объявлениях: неверный тип, нет repr(C), висячий указатель, enum на входе.
- B. Вызовите qsort_r из glibc, передав Rust-замыкание как компаратор через трамплин и контекст. Что случится, если замыкание запаникует?
- C. Rust-библиотека для C с непрозрачным дескриптором кольцевого буфера. Заголовок через cbindgen, тесты на C под valgrind и ASan.
- D. Оберните реальную C-библиотеку (zlib или libsqlite3) через bindgen в безопасный API. Сформулируйте инварианты обёртки и найдите место, где безопасность нельзя получить без накладных расходов.
