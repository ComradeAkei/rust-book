# 12. Замыкания

Повторите [перемещение](../ch03/01-ownership.md),
[заимствование](../ch04/01-refs.md) и [методы трейта](../ch09/01-traits.md).
[Замыкание][g-closure] — значение, которое можно вызвать как функцию и которое
может помнить данные из места своего создания. Например, обработчик
«прибавить отсчёт к моей сумме» должен помнить, к какой именно сумме.
В каждом примере разделяйте два события: создание замыкания, когда
оно получает доступ к данным, и его вызов, когда выполняется тело.

## Мотивирующая проблема

Всякий C-интерфейс с обратным вызовом устроен одинаково: указатель на
функцию и рядом `void *ctx`, который библиотека не читает, а только
передаёт обратно. Так работают `qsort_r`, `pthread_create`,
`atexit`-подобные реестры, обработчики событий в драйверах и в любом
фреймворке на C. Программа `code/ch12/c/callback.c` — маленький реестр
обработчиков событий в этом стиле:

```c
{{#include ../../code/ch12/c/callback.c}}
```

```console
$ gcc -O2 -Wall -Wextra -o callback callback.c
$ ./callback
sizeof(struct handler) = 24
событий: 63 (ожидалось 3)
в сессии: 1
среднее: 6
```

GCC и clang с `-Wall -Wextra` молчат. А программа ошибается дважды, и у
приёма четыре свойства, за которые платит каждый его пользователь.

**Тип контекста не проверяет никто.** `on_average` подписан с
контекстом `&hits`, а ждёт `struct average *`. `void *` принимает любой
адрес, и компилятору не с чем сравнить. `on_average` пишет восьмибайтную
сумму поверх четырёхбайтного счётчика и соседней памяти, и счётчик трёх
событий показывает 63. Заметит это только [санитайзер][g-sanitizer]:

```console
$ gcc -O1 -g -fsanitize=address -o callback-asan callback.c
$ ./callback-asan mixup
==23051==ERROR: AddressSanitizer: global-buffer-overflow on address 0x55cb87bba5a0 …
READ of size 8 at 0x55cb87bba5a0 thread T0
    #0 0x55cb87bb25ab in on_average callback.c:67
0x55cb87bba5a4 is located 0 bytes after global variable 'hits' … of size 4
```

**[Время жизни][g-lifetime] контекста не проверяет никто.** `start_session` подписывает
обработчик на переменную своего кадра и возвращается. Подписка осталась,
кадра нет, и следующий `emit` пишет в стек, который уже занят чем-то
другим. Без санитайзера программа печатает то же, что и без ошибки:

```console
$ ./callback-asan session
==23053==ERROR: AddressSanitizer: stack-use-after-return on address 0x7f6baab00060 …
READ of size 4 at 0x7f6baab00060 thread T0
    #0 0x55608eeef565 in on_count callback.c:61
    #1 0x55608eeef48c in emit callback.c:37
    #2 0x55608eeefee7 in session callback.c:161
Address 0x7f6baab00060 is located in stack of thread T0 at offset 32 in frame
    #0 0x55608eeef75e in start_session callback.c:77
```

**Кто освобождает контекст — отдельный договор.** Контекст в куче
должен освободить тот, кто отписывает обработчик, а знать, как именно,
он может только из третьего указателя: `destroy`, как `GDestroyNotify` в
GLib. Подписка занимает 24 байта, а забытый `destroy` — утечка, о которой
[LeakSanitizer][g-lsan] скажет только при выходе из программы.

**Вызов через указатель не [встраивается][g-inlining].** `apply` — библиотечная
функция, которая не знает, что за `f` ей передали, и зовёт её на каждый
отсчёт. `scale_all` делает то же самое, но операция видна внутри цикла:

```console
$ gcc -O3 -o callback-o3 callback.c
$ ./callback-o3 bench
через указатель: 1.37 нс на элемент
своя копия:       0.08 нс на элемент
```

С `-O3` GCC [векторизует][g-vectorization] `scale_all` (`pmullw` и `paddw`, восемь
отсчётов за инструкцию), а в `apply` остаётся `call r13` на каждый
отсчёт. Разница — в семнадцать раз. Атрибут `noipa` в примере не даёт
GCC подсмотреть `f` из места вызова, как не подсмотрит он и в libc. А
clang 18 с `-O2` без этого атрибута сам строит `apply.specialized.1` —
копию `apply`, в которой `scale` встроена, — потому что тело `apply` и
место вызова лежат в одном файле. Это ровно то, что Rust делает с
[обобщённой][g-generic] функцией всегда. Скрипт `code/ch12/c/run.sh` проверяет все
эти выводы, а время печатает для сведения.

## Что делает Rust

*Замыкание* (closure) — функция вместе со своим контекстом, и контекст в нём
типизирован, привязан к времени жизни того, что захвачено, и
уничтожается вместе с замыканием.

- Замыкание захватывает переменные по ссылке, по изменяемой ссылке или
  по значению, и компилятор выбирает самый слабый способ, которого
  хватает телу. Под капотом это анонимная структура с полем на каждый
  захват, и её размер — размер захваченного (раздел
  [12.1](01-capture.md)).
- Что замыкание делает со своим состоянием, выражают три [трейта][g-trait]: [`Fn`][g-fn-traits]
  читает, `FnMut` меняет, `FnOnce` забирает. Их реализует компилятор по
  телу замыкания (раздел [12.2](02-traits.md)).
- Функция и замыкание без захвата — [типы нулевого размера][g-zst] и приводятся к
  указателю на функцию; такой указатель годится для таблицы во flash и
  для передачи в C (раздел [12.3](03-fnptr.md)).
- Замыкание можно вернуть из функции как `impl Fn` без кучи или как
  `Box<dyn Fn>`, если тип нужно стереть (раздел [12.4](04-return.md)).
- В обобщённую функцию замыкание встраивается целиком; через `&mut dyn
  FnMut` остаётся косвенный вызов, как в C (раздел
  [12.5](05-codegen.md)).
- `Copy`, [`Send`][g-send-sync] и `Sync` замыкание получает от захваченного, а
  асинхронные замыкания дают [future][g-future], который [заимствует][g-borrowing] состояние
  замыкания (раздел [12.6](06-auto.md)).

## Код главы

```console
$ cargo test -p ch12 -p ch12-solutions            # примеры и решения
$ cargo +nightly test --doc -p ch12               # коды ошибок в doc-тестах
$ cargo +nightly test -p ch12 --features nightly --test nightly
$ bash code/ch12/c/run.sh                         # callback.c и nested.c
$ cargo run --release -p ch12 --example bench     # калибровка тремя способами
$ cargo asm -p ch12 --lib --simplify ch12_map_dyn
$ cd firmware && cargo run --release -p ch12-closures
```

Числа в тексте получены на rustc 1.97.0 (LLVM 22.1.6) и nightly 1.101.0
(2026-10-21) для `x86_64-unknown-linux-gnu` и трёх [целей][g-target] Cortex-M, GCC
13.3, clang 18.1, glibc 2.39 и binutils 2.42, прошивки — в QEMU 8.2.2.
Время снято на виртуальной машине с процессором Intel Xeon и меняется от
запуска к запуску на 10–20 %. Ассемблер снят командой `cargo asm
--simplify` из release-сборки; для Cortex-M к ней добавлены
`--no-default-features --target <цель>`.
