# 12.1. Синтаксис и захват

## Запись

Замыкание — выражение: параметры между вертикальными чертами, затем
тело. Типы параметров и результата можно указать, а можно оставить
выводу, и фигурные скобки нужны, только если тело длиннее одного
выражения или указан тип результата:

```rust
{{#include ../../code/ch12/src/capture.rs:syntax}}
```

Вывод типов для замыкания — не обобщение. Тип параметра без аннотации
определяется по первому вызову и дальше не меняется:

```rust,ignore
let id = |x| x;
let a = id(1u8);
let b = id(1u16);
```

```console
error[E0308]: mismatched types
4 | let b = id(1u16);
  |         -- ^^^^ expected `u8`, found `u16`
note: expected because the closure was earlier called with an argument of type `u8`
```

Обобщённой бывает функция, а замыкание — значение одного конкретного
типа с одним методом вызова. Если нужна функция, которая работает с
любым `T`, это `fn id<T>(x: T) -> T`.

## Три способа захвата

Тело замыкания может пользоваться переменными окружающей функции. То,
чем оно пользуется, замыкание *захватывает*, и захватить можно тремя
способами:

```rust
{{#include ../../code/ch12/src/capture.rs:modes}}
```

Способ выбирает компилятор, и выбирает самый слабый, которого хватает
телу:

| Что тело делает с переменной | Захват | Как поле структуры |
|---|---|---|
| только читает | по ссылке | `&T` |
| изменяет | по изменяемой ссылке | `&mut T` |
| перемещает из неё значение не-`Copy`-типа | по значению | `T` |

`len` читает `name` и держит `&String`; `bump` увеличивает `count` и
держит `&mut u32`; `take` возвращает `name` и поэтому забирает строку
себе. Захват по ссылке — обычный заём, и правила заимствования из
главы 4 действуют на него без исключений. Пока `bump` жив и ещё будет
вызван, читать `count` нельзя:

```console
error[E0503]: cannot use `count` because it was mutably borrowed
3 | let mut bump = || count += 1;
  |                -- ----- borrow occurs due to use of `count` in closure
  |                |
  |                `count` is borrowed here
4 | let seen = count;
  |            ^^^^^ use of borrowed `count`
5 | bump();
  | ---- borrow later used here
```

А после `let take = || name;` строки у функции уже нет, даже если `take`
ни разу не вызвали: значение переехало в замыкание при его создании.

```console
error[E0382]: borrow of moved value: `name`
3 | let take = || name;
  |            -- ---- variable moved due to use in closure
  |            |
  |            value moved into closure here
4 | let len = name.len();
  |           ^^^^ value borrowed here after move
```

Оба примера лежат в doc-тестах `code/ch12/src/capture.rs` с кодами
ошибок.

## Замыкание — это структура

У каждого замыкания свой тип, у типа нет имени, и устроен он как
структура с полем на каждый захват. Тело становится методом этой
структуры. Для `bump` компилятор строит примерно вот что:

```rust
{{#include ../../code/ch12/src/capture.rs:desugar}}
```

Настоящий метод называется `call_mut` и принадлежит трейту `FnMut`
(раздел [12.2](02-traits.md)); в nightly его можно реализовать и
руками, это сделано в `code/ch12/tests/nightly.rs`. Вызов `bump()` —
вызов этого метода, а `count += 1` в теле — запись через поле-ссылку.
Отсюда размер замыкания: это размер его структуры.

```rust
{{#include ../../code/ch12/src/capture.rs:sizes}}
```

| Замыкание | Поля | x86-64 | Cortex-M3 |
|---|---|---|---|
| `nothing` | — | 0 | 0 |
| `by_ref` | `&i32` | 8 | 4 |
| `by_value` | `i32` | 4 | 4 |
| `two_refs` | `&mut u8`, `&u64` | 16 | 8 |

Замыкание без захвата — тип нулевого размера, как пустая структура:
его нет в памяти, а передать его в функцию — значит не передать ничего
(раздел [12.5](05-codegen.md)). Захват по ссылке стоит указатель, даже
если сама переменная меньше указателя: `by_ref` вдвое больше `x` на
x86-64. А `by_value` — ровно `i32`.

<div class="box c">

**Как в C.** Структура замыкания — это и есть `ctx` из введения, только
её объявляет компилятор, а не программист. Поле за полем она совпадает
с тем, что пришлось бы собрать руками: `struct { int *count; }` для
`bump`. Разница в том, что эту структуру нельзя перепутать с другой
(тип у каждого замыкания свой) и нельзя пережить то, на что она
ссылается (поля — заёмы с временем жизни).

</div>

## Точный захват

С редакции 2021 замыкание захватывает не переменную, а *путь* к тому,
чем пользуется тело: поле, поле поля, разыменование ссылки. Тело,
которому нужны `p.a` и `p.b`, захватывает две ссылки на поля, а не
ссылку на `p`:

```rust
{{#include ../../code/ch12/src/capture.rs:precise}}
```

`precise_sizes()` возвращает `[16, 8, 16]` на x86-64 и `[8, 4, 16]` на
Cortex-M3. `fields` держит две ссылки, а `whole`, где тело само берёт
`&p`, — одну. `copied` с `move` копирует только два поля по 8 байт, а не
всю структуру со стобайтовым журналом.

Точный захват нужен не ради байт, а ради заимствования. Изменяемая
ссылка на одно поле и замыкание, которое читает другое, живут
одновременно:

```rust
{{#include ../../code/ch12/src/capture.rs:disjoint}}
```

В редакции 2018 замыкание захватывало `st` целиком, и тот же код давал
`E0502: cannot borrow *st as immutable because it is also borrowed as
mutable`. Doc-тест с атрибутом `edition2018` проверяет и это. Перевод
крейта на новую редакцию (`cargo fix --edition`) вставляет в такие
замыкания строку `let _ = &st;`, которая возвращает захват целиком
там, где от него зависел порядок деструкторов.

Путь обрывается там, где дальше идти нельзя или опасно: на
разыменовании сырого указателя, на поле объединения, на поле
`#[repr(packed)]`-структуры, где ссылка могла бы оказаться
невыровненной, и для `move`-замыкания на разыменовании ссылки — оно
перемещает саму ссылку. Если у структуры есть `Drop`, перемещать из неё
поля по отдельности нельзя, и `move`-замыкание забирает её целиком.

## `move`

`move` перед списком параметров заставляет замыкание захватить всё по
значению, что бы ни делало тело. Это нужно, когда замыкание должно
пережить кадр, в котором создано: его возвращают из функции (раздел
[12.4](04-return.md)) или отдают другому потоку. Какие трейты
реализует замыкание, `move` не меняет: это решает тело (раздел
[12.2](02-traits.md)).

С типами, которые не `Copy`, `move` ведёт себя ожидаемо: значение
переезжает. С `Copy`-типами он копирует, и копия живёт своей жизнью:

```rust
{{#include ../../code/ch12/src/capture.rs:move-copy}}
```

`move_copy()` возвращает `(0, 3)`: счётчик дошёл до трёх внутри
замыкания, а переменная `n` функции осталась нулём.

<div class="box trap">

**Ловушка.** Ни rustc, ни clippy (и с `pedantic`, и с `nursery`) не
предупреждают: `n` объявлена `mut`, и это нужно, потому что тело
изменяет её копию; тело читает результат, поэтому присваивание не
«мёртвое». В C такой ошибки не бывает — там нельзя забыть `&` у
`ctx`, не получив ошибку типов. Если замыкание с `move` должно менять
что-то снаружи, захватывайте ссылку явно (следующий приём) или
`Cell`; если не должно — уберите `mut` у переменной, и копия станет
неизменяемой.

</div>

Чтобы `move`-замыкание взяло одно по значению, а другое по ссылке,
в него перемещают саму ссылку:

```rust
{{#include ../../code/ch12/src/capture.rs:move-ref}}
```

Ссылка — `Copy`, её копия указывает на тот же массив, и `above` держит
указатель и `u16`: 16 байт на x86-64, 8 на Cortex-M3.
