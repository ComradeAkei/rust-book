# 12.2. `Fn`, `FnMut` и `FnOnce`

## Три способа вызвать

Вызов замыкания — вызов метода его структуры, а метод может взять
`self` тремя способами. Поэтому *трейтов вызова* три — `FnOnce`, `FnMut` и
`Fn`, — и различаются они только приёмником:

```rust,ignore
pub trait FnOnce<Args> {
    type Output;
    fn call_once(self, args: Args) -> Self::Output;
}
pub trait FnMut<Args>: FnOnce<Args> {
    fn call_mut(&mut self, args: Args) -> Self::Output;
}
pub trait Fn<Args>: FnMut<Args> {
    fn call(&self, args: Args) -> Self::Output;
}
```

`FnOnce` забирает замыкание целиком и может распорядиться захваченным
как угодно, в том числе отдать его наружу; после вызова замыкания нет.
`FnMut` берёт его по изменяемой ссылке и может менять состояние, но не
забирать. `Fn` берёт по общей ссылке и не требует изменяемого доступа к полям
замыкания. Запись `Fn(u32) -> u32` — сокращение для `Fn<(u32,), Output = u32>`: аргументы приходят
одним кортежем.

Для того, кто принимает замыкание, граница — это обещание, что он с ним
сделает:

```rust

```

Трейты вложены друг в друга: всякий тип с `Fn` реализует и `FnMut`, а
всякий с `FnMut` — и `FnOnce`. Поэтому граница `FnOnce` пропускает любое
замыкание, а `Fn` — меньше всего:

| Граница | Что может функция | Какие замыкания подходят |
|---|---|---|
| `F: FnOnce()` | вызвать один раз | любые |
| `F: FnMut()` | вызывать сколько угодно, но по одному вызову за раз | все, кроме отдающих захваченное |
| `F: Fn()` | вызывать через `&F` из нескольких мест сразу, а если `F: Sync` — и из разных потоков | те, которым для вызова хватает общей ссылки |

Общая ссылка не означает, что вызов вообще не имеет побочных эффектов:
он может, например, печатать в журнал или менять значение через `Cell`
(это [внутренняя изменяемость](../ch14/05-cells.md)). Семейство трейтов
описывает способ доступа к замыканию, а не математическую «чистоту»
функции. Это видно и в [сигнатуре `Fn::call`](https://doc.rust-lang.org/std/ops/trait.Fn.html):
получатель — `&self`.

Правило для своих функций: требуйте самый слабый трейт, которого хватает.
`Option::map` и `unwrap_or_else` зовут замыкание не больше раза и берут
`FnOnce`; `Iterator::map` и `retain` зовут много раз подряд и берут
`FnMut`; `Fn` нужен, когда замыкание лежит в общем доступе, как
обработчик в `Arc` у нескольких потоков.

## Трейты выбирает тело

Программист трейты замыканию не назначает. Компилятор смотрит, что тело
делает с захваченным, и реализует все трейты, которые это позволяет:

```rust
{{#include ../../code/ch12/src/traits.rs:which}}
```

Не смешивайте захват и отдачу захваченного. `move || s.len()`
получает строку `s` во [владение][g-ownership] при создании, но при вызове только
читает её и может делать это снова. `move || s` получает её тем же
способом, а при вызове отдаёт наружу; второй раз отдавать уже нечего.
`move` отвечает на вопрос «как сохранить данные внутри замыкания»,
а семейство `Fn` — «какой доступ к ним нужен телу при вызове».

Для нового примера задайте вопросы именно в этом порядке:

1. **Что попало внутрь при создании?** Ссылка на строку или сама строка?
   На этот вопрос влияет `move`.
2. **Что тело делает при вызове?** Читает захваченное, меняет его или
   перемещает наружу? По этому ответу выбираются трейты вызова.

Например, эти две строки различаются только телом:

```rust
let text = String::from("АЦП");
let length = move || text.len();
assert_eq!(length(), 6);
assert_eq!(length(), 6); // строка всё ещё внутри length

let text = String::from("АЦП");
let take = move || text;
assert_eq!(take(), "АЦП"); // строка перешла из take к вызывающему
```

Оба замыкания владеют своей строкой. `length` реализует все три
трейта, а `take` — только `FnOnce`. Повторный `take()` дал бы E0382:
первый вызов уже потребил замыкание. Число `6` — длина трёх русских
букв в байтах UTF-8, не число букв.

`which()` возвращает `(42, 44, 3, *b"TC01")`. `moved` — `move`-замыкание,
и всё же `Fn`: тело только читает свою копию `base`. `gives` отдаёт
захваченный массив, но массив — `Copy`, тело отдаёт копию, и замыкание
остаётся `Fn`. Стоит телу переместить из захваченного значение
не-`Copy`-типа, как останется один `FnOnce`, и функция, которая хочет
звать дважды, его не примет:

```console
error[E0525]: expected a closure that implements the `FnMut` trait, but this closure only implements `FnOnce`
3 | let f = move || {
  |         ^^^^^^^ this closure implements `FnOnce`, not `FnMut`
4 |     let owned = s;
  |                 - closure is `FnOnce` because it moves the variable `s` out of its environment
...
7 | call_twice_mut(f);
  | -------------- - the requirement to implement `FnMut` derives from here
  | |
  | required by a bound introduced by this call
```

Компилятор указывает и на строку, которая сделала замыкание одноразовым,
и на границу, которой оно не подошло. Два других правила вытекают прямо
из приёмников. `FnMut` вызывается через `&mut self`, поэтому замыкание,
которое меняет состояние, нельзя вызвать через неизменяемую привязку:

```console
error[E0596]: cannot borrow `bump` as mutable, as it is not declared as mutable
3 | let bump = || count += 1;
  |               ----- calling `bump` requires mutable binding due to mutable borrow of `count`
4 | bump();
  | ^^^^ cannot borrow as mutable
```

А `FnOnce` вызывается через `self`, и вызов перемещает замыкание, как
перемещает значение любой вызов по значению:

```console
error[E0382]: use of moved value: `f`
4 | let a = f();
  |         --- `f` moved due to this call
5 | let b = f();
  |         ^ value used here after move
note: closure cannot be invoked more than once because it moves the variable `s` out of its environment
3 | let f = move || s;
  |                 ^
```

Все три примера — doc-тесты с кодами ошибок в
`code/ch12/src/traits.rs`.

## Пересылка через ссылку

Функция с границей `F: FnMut` забирает замыкание по значению. Если
замыкание нужно и после вызова, отдают ссылку: стандартная библиотека
реализует трейты вызова для ссылок.

```rust,ignore
impl<A: Tuple, F: ?Sized + Fn<A>> Fn<A> for &F
impl<A: Tuple, F: ?Sized + FnMut<A>> FnMut<A> for &mut F
impl<A: Tuple, F: ?Sized + FnOnce<A>, Al: Allocator> FnOnce<A> for Box<F, Al>
```

```rust

```

`forward()` возвращает 10: `add` дважды ушло в `for_each_byte` как `&mut
add`, накопило 6 и после этого вызвано напрямую. Тип `F` в первых двух
вызовах — `&mut {closure}`, и вызов через него — вызов через ссылку, которую
оптимизатор убирает, когда `for_each_byte` встроена.

С рекурсией этот приём ломается. Обобщённая функция, которая передаёт
себе `&mut f`, на каждом уровне получает новый тип: `F`, `&mut F`, `&mut
&mut F`, и каждому нужна своя копия функции. [Мономорфизация][g-monomorphization] не
кончается, и компилятор останавливается на пределе глубины (128 по
умолчанию):

```console
error: reached the recursion limit while instantiating `visit_generic::<&mut &mut &mut &mut &mut &mut &mut &mut &mut &mut ...>`
4 |         visit_generic(depth - 1, &mut f);
  |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

Выход — один раз стереть тип и рекурсировать уже по `&mut dyn FnMut`:

```rust

```

Копия `visit` одна на все замыкания, а вызов `f(depth)` идёт через
таблицу (раздел [12.5](05-codegen.md)). Тест зовёт `visit(3, &mut |d|
seen = seen * 10 + d)` и получает 3210.

## `FnOnce` и деструкторы

Если замыкание [владеет][g-ownership] захваченным значением, оно уничтожается
по обычным правилам владения (глава 3, раздел 3.2): при завершении вызова
через `FnOnce`, если тело не отдало его дальше или не уничтожило раньше,
либо вместе с замыканием, если его так и не вызвали. Сам трейт `FnOnce`
не требует владения данными: замыкание может захватывать и ссылки.
Уничтожение захваченной ссылки не уничтожает данные, на которые она смотрит.

```rust
{{#include ../../code/ch12/src/traits.rs:once-drop}}
```

После `once_drop` журнал равен `[1, 1, 0, 0]`: оба деструктора
отработали по разу, один внутри вызова, другой при `drop(never)`. Для
обработчиков с ресурсом это и есть третий указатель `destroy` из
введения, только вызывает его компилятор.

Замыкание в куче вызывается так же. `Box<dyn FnOnce()>` реализует
`FnOnce` (так стало в Rust 1.35, до этого приходилось писать обёртку
`FnBox`): вызов перемещает тело из кучи и освобождает память.

```rust
{{#include ../../code/ch12/src/traits.rs:boxed-once}}
```

`deferred()` возвращает `[1, 6]`: строка «три» в UTF-8 занимает 6 байт.
Очередь отложенных действий, команды для другого потока, обработчик
завершения — всё это `Vec<Box<dyn FnOnce() + Send>>` или канал таких
коробок, и освобождать контексты вручную в этом коде не нужно.

<div class="box check">

**Проверь себя.** Какие трейты вызова реализует `|| v.len()`, а какие —
`move || v`, если `v: Vec<u8>`? Почему `Option::map` берёт `FnOnce`, а не
`Fn`, и что потеряли бы пользователи, если бы граница была строже? Что
произойдёт с захваченной строкой, если `Box<dyn FnOnce()>` положили в
`Vec` и `Vec` уничтожили, не вызвав замыкание?

<details>
<summary>Ответы и объяснения</summary>

`|| v.len()` только читает вектор: это `Fn`, `FnMut` и `FnOnce`.
`move || v` отдаёт некопируемый вектор наружу: это только `FnOnce`.
`Option::map` вызывает обработчик не больше одного раза, поэтому ему
подходит и обработчик, который отдаёт захваченное. Граница `Fn`
запретила бы такой случай без пользы для `map`.
При уничтожении `Vec<Box<dyn FnOnce()>>` уничтожатся коробки, затем
замыкания и их захваченные строки. Тела замыканий при этом не вызовутся.

</details>

</div>
