# 8.1. Модули и видимость

## Дерево модулей

Крейт — это дерево *модулей* (modules). Корень — файл `src/lib.rs` или
`src/main.rs`, остальные модули объявляются словом `mod`: либо сразу с
телом в фигурных скобках, либо строкой `mod name;`, и тогда компилятор
ищет тело в файле `name.rs` рядом с родителем (или в `name/mod.rs`, как
в старом коде). В корне `code/ch08` так подключены четыре файла:

```rust
// code/ch08/src/lib.rs
pub mod atomic;
pub mod generated;
pub mod symbols;
pub mod visibility;
```

В отличие от `#include`, `mod` не вставляет текст. Файл модуля
компилируется один раз как часть крейта, и порядок объявлений ничего не
значит: функция может вызвать другую, объявленную ниже или в соседнем
модуле, без прототипов. Путь к элементу пишется от корня (`crate::`),
от родителя (`super::`) или от текущего модуля (`self::`), а `use`
вводит короткое имя.

Читайте путь `crate::station::bus::transfer` слева направо:
`crate` — корень текущего крейта, `station` и `bus` — вложенные модули,
`transfer` — нужная функция. `use` сокращает запись пути в текущем
месте; он не копирует функцию и сам по себе не делает её публичной.

правила:

## Правила

Всё, что не помечено, *приватно*. Приватный элемент виден в модуле, где
он объявлен, и во всех его потомках. Потомки видят приватное предков,
предки приватное потомков — нет. Так `bus::reset_all` вызывает
приватный метод `Sample::reset`: метод объявлен в `station`, а `bus`
лежит внутри `station`.

Пометки расширяют круг:

| Пометка | Где видно |
|---|---|
| нет | этот модуль и его потомки |
| `pub(super)` | модуль-родитель и его потомки |
| `pub(in crate::a::b)` | модуль `crate::a::b` и его потомки; путь должен вести к предку |
| `pub(crate)` | весь крейт |
| `pub` | везде, куда виден сам родитель |

Последняя оговорка важна. `bus::transfer` объявлена `pub`, но модуль
`bus` — `pub(crate)`, и путь `station::bus::transfer` снаружи крейта не
пройдёт: видимость пути — минимум по всем его звеньям. Обратное тоже
верно: `pub use` открывает элемент по новому пути, не трогая старого.
Так устроена стандартная библиотека: `HashMap` объявлен в приватном
модуле `std::collections::hash::map`, а пользователь пишет
`std::collections::HashMap`.

`pub(in …)` в `reset_all` требует абсолютного пути, и он должен вести к
модулю-предку. Поскольку `station` лежит в `visibility`, путь —
`crate::visibility::station`; короткий `crate::station` дал бы ошибку
E0433, «не найден модуль».

У полей структуры и методов своя видимость, независимо от видимости
типа. `Sample` объявлен `pub`, но из трёх полей открыто только
`sensor`. Литерал структуры требует доступа ко всем полям, поэтому
снаружи `Sample` можно создать только через `Sample::new` — и
инвариант «`calibrated` меняется только вместе с `raw`» держит сам
модуль.

## Как выглядят нарушения

[Doc-тесты][g-doctest] в начале `visibility.rs` собираются как отдельный крейт, то
есть смотрят на `ch08` снаружи. Каждый помечен `compile_fail` с кодом
ошибки, а на nightly [rustdoc][g-rustdoc] сверяет и код:

```rust,ignore
// E0603: модуль `bus` объявлен pub(crate), снаружи его нет
ch08::visibility::station::bus::transfer();
```

```text
error[E0603]: module `bus` is private
 --> v1.rs:2:32
  |
2 |     ch08::visibility::station::bus::transfer();
  |                                ^^^  -------- function `transfer` is not publicly re-exported
  |                                |
  |                                private module
```

| Обращение снаружи крейта | Ошибка |
|---|---|
| `station::bus::transfer()` | E0603: module `bus` is private |
| `s.calibrated` | E0616: field `calibrated` of struct `Sample` is private |
| `s.raw` (`pub(crate)`) | E0616: field `raw` of struct `Sample` is private |
| `s.reset()` | E0624: method `reset` is private |
| `Sample { sensor: 7, raw: 100, calibrated: false }` | E0451: fields `raw` and `calibrated` of struct `Sample` are private |

Для другого крейта `pub(crate)` ничем не отличается от приватного, и
сообщение говорит просто «private». Внутри крейта `raw` открыт, а
`calibrated` и `bus::scale` по-прежнему закрыты:

```rust
{{#include ../../code/ch08/src/visibility.rs:inside}}
```

<div class="box c">

**Как в C.** Единица приватности в C — файл: `static` на функции или
глобальной переменной делает её невидимой для компоновщика из других
файлов. Вложенных уровней нет, а «всё остальное» видно всей программе
под одним плоским именем. Поля структуры в C приватными не бывают.
Ближайшая замена — непрозрачный тип: в заголовке `struct sample;` без
тела и функции, принимающие `struct sample *`. Цена — объект можно
создать только по указателю, обычно в куче, и каждый доступ к полю
становится вызовом функции через границу файла. Приватное поле в Rust
не стоит ничего: `Sample` занимает те же 6 байт, что и с открытыми
полями, лежит на стеке, а `is_calibrated` [встраивается][g-inlining].

</div>

## Видимость и символы

Видимость — проверка компилятора, а не свойство машинного кода. Что
остаётся от неё в объектном файле, видно в отладочной сборке, где
функции не встроены. Крейт делится на [единицы кодогенерации][g-codegen-unit], и вызовы
между ними идут через символы, поэтому глобальны почти все функции.
Различие — в *видимости символа* (ELF symbol visibility):

```console
$ readelf -sW ch08-*.rcgu.o | grep visibility | grep -v UND
GLOBAL DEFAULT  <ch08::visibility::station::Sample>::is_calibrated
GLOBAL DEFAULT  <ch08::visibility::station::Sample>::new
GLOBAL DEFAULT  <ch08::visibility::station::Sample>::calibrate
GLOBAL DEFAULT  ch08::visibility::raw_of
GLOBAL DEFAULT  ch08::visibility::station::recalibrate
GLOBAL HIDDEN   <ch08::visibility::station::Sample>::reset
GLOBAL HIDDEN   ch08::visibility::station::bus::scale
GLOBAL HIDDEN   ch08::visibility::station::bus::transfer
GLOBAL HIDDEN   ch08::visibility::station::bus::reset_all
```

(Из строк `readelf` здесь оставлены привязка, видимость и имя, а имена
разобраны: в файле они в схеме v0, раздел [8.7](07-symbols.md).) Всё, что доступно другим крейтам, получает
видимость `DEFAULT`. Всё, что не выходит за пределы крейта, — `HIDDEN`:
символ участвует в компоновке, но не попадёт в таблицу экспорта
разделяемой библиотеки. Среди скрытых и `bus::transfer`, объявленная
`pub`: компилятор считает *действующую* видимость по всему пути, как и
проверка.

В release-сборке библиотеки этих функций нет вовсе. Маленькие
необобщённые функции rustc помечает как встраиваемые между крейтами и
отдаёт в метаданных, а машинный код для них появится в том крейте,
который их вызовет. В `libch08.rlib` из release остались только
функции с `#[inline(never)]`, [обобщённые][g-generic] конкретизации, которые нужны
самому крейту, и символы с фиксированными именами:

```console
$ nm -C target/release/libch08.rlib
0000000000000000 T ch08::symbols::checksum::<[u8; 4]>
0000000000000000 T ch08::symbols::checksum::<&[u8]>
0000000000000000 T <ch08::symbols::Uart>::send
0000000000000000 T ch08::symbols::both
0000000000000000 D ch08::generated::CALIB
0000000000000000 D ch08::generated::SENSORS
0000000000000000 T ch08_bump
0000000000000000 T station_reset
0000000000000000 T station_version
```

<div class="box hood">

**Под капотом.** Аналог `static` из C в Rust выбирает компилятор, а не
программист: функция становится локальной (`LOCAL`), если её вызывают
только из той же единицы кодогенерации. Сколько их будет, задаёт
[профиль][g-profile] (`codegen-units`: 256 для инкрементальной отладочной сборки, 16
для release), поэтому одна и та же приватная функция бывает то
`LOCAL`, то `GLOBAL HIDDEN`. Листинг выше снят с инкрементальной
сборки, а с `CARGO_INCREMENTAL=0`, как в CI, у `ch08` получается одна
единица, и все строки `GLOBAL HIDDEN` становятся `LOCAL`. Полагаться на
это нельзя, а нужно и не
бывает: от столкновений имён защищает [манглинг][g-mangling] (раздел
[8.7](07-symbols.md)), а не видимость символа.

</div>

<div class="box trick">

**Трюк.** Слово `pub` внутри модуля, который сам не `pub`, легко
поставить по привычке. [Линт][g-lint] `unreachable_pub` (по умолчанию выключен)
находит такие места и предлагает видимость, которая действует на деле,
например `pub(crate)`: тогда видимость
элемента видна из его объявления, без поиска по дереву модулей. А
`dead_code` замечает, что `pub fn` в приватном модуле никто не зовёт,
— для него такая функция не экспортирована.

</div>

<div class="box check">

**Проверь себя.** Можно ли из модуля `station` вызвать
`bus::reset_all`? А из корня крейта `ch08`? Почему `bus::scale` нельзя
вызвать из `raw_of`, хотя `raw_of` лежит в том же крейте?

</div>
