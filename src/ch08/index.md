# 8. Модули, крейты и сборка

## Мотивирующая проблема

Программа на C собирается в три этапа, и ни один из них не знает о
других. Препроцессор подставляет текст заголовков и вырезает куски кода
по `#ifdef`. Компилятор видит одну единицу трансляции и о соседних знает
только то, что объявлено в заголовках. Компоновщик склеивает объектные
файлы по именам символов в одном плоском пространстве имён на всю
программу. Две программы из `code/ch08/c` показывают, что теряется на
стыках.

**Опечатка выключает код.** Драйвер [UART][g-uart] умеет принимать байты через
DMA, если определён макрос конфигурации:

```c
{{#include ../../code/ch08/c/ifdef.c}}
```

```console
$ gcc -Wall -Wextra -Wundef -o ifdef ifdef.c
ifdef.c: In function 'main':
ifdef.c:12:5: warning: "CONFIG_UART_DAM" is not defined, evaluates to 0 [-Wundef]
   12 | #if CONFIG_UART_DAM
      |     ^~~~~~~~~~~~~~~
$ ./ifdef
UART: приём опросом
```

Макрос называется `CONFIG_UART_DMA`, а проверяется `CONFIG_UART_DAM`.
Для препроцессора это просто другое имя, которое никто не определил, и
`#ifdef` молча выбирает ветку `#else`. Флаг `-Wundef` ловит опечатку
только в `#if`, где неопределённое имя участвует в выражении, а в
строке 7 с `#ifdef` её не видит ни GCC, ни clang. Прошивка соберётся,
пройдёт тесты на стенде с медленным UART и потеряет байты на
настоящей скорости.

**Два файла выбрали одно имя.** Драйвер UART считает принятые байты, а
[модуль][g-module] журнала, написанный другим человеком, завёл буфер под тем же
именем:

```c
{{#include ../../code/ch08/c/uart.c}}
```

```c
{{#include ../../code/ch08/c/log.c}}
```

```c
{{#include ../../code/ch08/c/main.c}}
```

С GCC 10 и новее глобальная переменная без инициализатора — обычное
определение, и компоновщик отвергает второе:

```console
$ gcc -O2 -Wall -Wextra -o def uart.c log.c main.c
/usr/bin/ld: /tmp/ccw6Cat8.o:(.bss+0x0): multiple definition of `rx_count'; /tmp/cczBvSuR.o:(.bss+0x0): first defined here
collect2: error: ld returned 1 exit status
```

Это хороший исход. Старый код часто собирают с `-fcommon`, потому что
без него он не компонуется, и тогда оба `rx_count` становятся *общими
символами* (common symbols) и сливаются в один объект размером с
больший из них:

```console
$ gcc -O2 -Wall -Wextra -fcommon -o common uart.c log.c main.c
$ ./common
rx_count = 3
rx_count = 16961
```

Ни одного предупреждения. Журнал записал строку `"AB"` в память
счётчика: байты `41 42 00 00` в little-endian — это 0x4241, то есть
16961. Заметить слияние может только сам компоновщик, если его
попросить:

```console
$ gcc -O2 -fcommon -Wl,--warn-common -o warn uart.c log.c main.c
/usr/bin/ld: /tmp/ccxc7dq4.o: warning: common of `rx_count' overriding smaller common from /tmp/ccoul63T.o
```

Скрипт `code/ch08/c/run.sh` проверяет все эти выводы, а `ifdef.c` —
ещё и с clang 18.

У обеих проблем общий корень: имена в C не принадлежат никому. Макрос
конфигурации — строка, которую никто не объявлял. Глобальная переменная
видна всей программе, если не написать `static`, и защищена от тёзок
только префиксами вроде `uart_` и дисциплиной команды.

## Что делает Rust

- Код делится на *модули*, вложенные друг в друга, и у каждого элемента
  есть видимость: от «только этот модуль» до «весь мир». Нарушение
  видимости — ошибка компиляции, а не соглашение (раздел
  [8.1](01-modules.md)).
- Единица компиляции — *крейт*, а не файл. Крейт сообщает соседям свой
  интерфейс через метаданные, а не через текст заголовков, и версии
  зависимостей фиксирует Cargo (раздел [8.2](02-crates.md)).
- Условная компиляция пишется атрибутом `#[cfg(...)]`, а не
  препроцессором. Cargo знает все допустимые имена и значения, и
  опечатка вроде `feature = "dam"` даёт предупреждение с подсказкой
  (раздел [8.3](03-cfg.md)).
- Варианты сборки описываются *возможностями* (features). Cargo
  объединяет их по всему дереву зависимостей, поэтому они обязаны только
  добавлять код (раздел [8.4](04-features.md)).
- Код, который нужно сгенерировать до компиляции, пишется на Rust в
  `build.rs` (раздел [8.5](05-build-rs.md)).
- Один крейт можно собрать как библиотеку для Rust, как статический
  архив для C или как разделяемую библиотеку (раздел
  [8.6](06-crate-types.md)).
- Имена символов включают путь модуля и хеш крейта, поэтому
  `uart::reset` и `dma::reset` не столкнутся никогда. Имя без
  декорирования приходится запрашивать явно, и в [edition][g-edition] 2024 это
  `unsafe` (раздел [8.7](07-symbols.md)).
- Куда в памяти микроконтроллера попадут данные, решают тип и атрибуты:
  неизменяемый `static` лежит во flash, [атомики][g-atomic] — в ОЗУ, а секция
  `.uninit` переживает перезагрузку (раздел [8.8](08-sections.md)).

## Код главы

```console
$ cargo test -p ch08 -p ch08-solutions            # примеры, опыты с cargo и решения
$ cargo +nightly test --doc -p ch08               # коды ошибок видимости в doc-тестах
$ bash code/ch08/c/run.sh                         # ifdef.c и rx_count в двух файлах
$ cd firmware && cargo run --release -p ch08-sections --bin target   # одна функция на M0 и M3
$ cd firmware && cargo run --release -p ch08-sections --bin boot     # .uninit после сброса
```

Рядом с крейтом `code/ch08` лежат отдельные [рабочие пространства][g-workspace] для
опытов, которым нужен сам cargo: `typo` (опечатки в `cfg`), `unify`
([унификация][g-feature-unification] возможностей) и `ffi` ([типы крейтов][g-crate-type]), а в `dup` — исходники
опыта со столкновением имён. Тест `code/ch08/tests/cargo.rs` собирает
их закреплённым [тулчейном][g-toolchain] и сверяет результат с текстом.

Числа в тексте получены на rustc 1.97.0 (LLVM 22.1.6) и nightly 1.101.0
(2026-10-21) для `x86_64-unknown-linux-gnu`, `thumbv6m-none-eabi` и
`thumbv7m-none-eabi`, GCC 13.3, clang 18.1 и GNU ld 2.42. Ассемблер снят
командой `cargo asm --simplify` из release-сборки.
