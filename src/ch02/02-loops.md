# 2.2. Циклы и метки

## loop со значением

Циклов три: `loop` (бесконечный), `while` и `for`. Выйти из `loop` можно
только через `break`, и у `break` бывает значение: оно становится
значением всего цикла. Так записывается повтор с ограничением числа
попыток:

```rust
{{#include ../../code/ch02/src/loops.rs:retry}}
```

`match` в теле решает три случая: успех — выйти с числом попыток, шина
занята и попытки ещё есть — повторить, всё остальное — выйти с ошибкой.
[Охранное условие][g-match-guard] `if attempts < max` (раздел [2.3](03-match.md)) делает
вторую ветку условной, и когда попытки кончились, `Busy` достаётся
последней ветке. Значение `loop` возвращается из функции как хвостовое
выражение. Параметр `impl FnMut() -> ...` — [замыкание][g-closure], которое функция
вызывает сколько угодно раз; в тестах это заглушка шины, подробно
замыкания разобраны в главе 12.

`while` и `for` всегда имеют значение `()`, и `break` со значением в них
не компилируется (E0571): цикл может закончиться и без `break`, и тогда
значения не было бы. Цикла `do { } while` нет; как его записать, показывает
приложение [A.4](../appendix-a.md#a4-управление-потоком).

## for и итераторы

`for` перебирает [итератор][g-iterator], а не счётчик. Цикла вида
`for (i = 0; i < n; i++)` в Rust нет: его место занимают `for i in 0..n` и,
чаще, перебор самой коллекции. Компилятор разворачивает `for` в `loop` и
`match` по результату `next()`:

```rust
{{#include ../../code/ch02/src/loops.rs:for_desugar}}
```

Обе функции дают один и тот же машинный код, причём буквально: LLVM
заметил это и оставил одну копию, а второе имя сделал псевдонимом.
`cargo asm` по имени `ch02_sum_for` ничего не находит, а в полном
листинге видна строка

```text
$ cargo asm -p ch02 --lib --everything | grep 'ch02_sum_for ='
ch02_sum_for = ch02_sum_desugared
```

<div class="box hood">

**Под капотом.** Слияние одинаковых функций делает *проход LLVM* (LLVM
pass — один шаг оптимизатора над IR) `MergeFunctions`, который rustc
включает по умолчанию. Тело `ch02_sum_desugared` на x86_64 — цикл по
восемь элементов за итерацию на [SSE2][g-sse-avx] (`paddd` в двух
регистрах `xmm`) и скалярный хвост:

```text
.LBB36_8:
	add eax, dword ptr [rcx]
	add rcx, 4
	cmp rcx, rdx
	jne .LBB36_8
```

[Проверки границ][g-bounds-check] среза в цикле нет: итератор хранит указатель на текущий
элемент и указатель на конец и сравнивает их. Индексный цикл
`for i in 0..xs.len() { s += xs[i] }` здесь тоже обошёлся бы без проверок,
потому что LLVM видит связь `i < xs.len()`, но так бывает не всегда
(раздел [1.6](../ch01/06-slices-str.md)). Итераторы подробно — глава 13.

</div>

## Метки

`break` и `continue` относятся к ближайшему циклу. Чтобы выйти из
внешнего или перейти к его следующей итерации, циклу дают метку:

```rust
{{#include ../../code/ch02/src/loops.rs:labels}}
```

Кадр, в котором встретился байт `ERR`, пропускается целиком:
`continue 'frames` бросает и внутренний цикл, и недосчитанную сумму
`sum`. Метка пишется как [время жизни][g-lifetime] (`'frames`), но это отдельное
пространство имён, и путаницы не возникает.

<div class="box c">

**Как в C.** В C `break` выходит только из ближайшего цикла или `switch`,
и выход из двух циклов сразу пишут через `goto` или через флаг, который
проверяют в каждом цикле. Отдельная ловушка — `break` внутри `switch`
внутри цикла: он выходит из `switch`, а не из цикла. В Rust `break` в
ветке `match` относится к циклу, потому что `match` — не цикл.

</div>
