# 2.1. Всё есть выражение

## Блок как значение

В C есть выражения и есть инструкции, и инструкции значения не имеют. В
Rust инструкций мало: `let`, выражение с точкой с запятой и объявления
внутри блока (вложенные `fn`, `struct`, `use`). Всё остальное, включая
блок `{ ... }`, `if`, `match` и `loop`, — выражения. Значение
блока — его последнее выражение, если после него нет `;`:

```rust
{{#include ../../code/ch02/src/exprs.rs:block}}
```

Переменные `x16` и `rounded` нужны только чтобы посчитать делитель, и
блок не выпускает их наружу: после `let div = { ... };` их уже нет в
области видимости. На C ту же изоляцию дают вложенные `{ }`, но значение
из них приходится выносить через переменную, объявленную снаружи.
Последняя строка насыщает 32-битный результат до ширины регистра
делителя (раздел [1.7](../ch01/07-casts.md)).

Точка с запятой превращает выражение в инструкцию, и значением становится
`()`. Лишняя `;` в конце функции — частая ошибка новичка, и компилятор
находит её сам:

```text
error[E0308]: mismatched types
 --> e1.rs:1:25
  |
1 | pub fn twice(x: u32) -> u32 {
  |        -----            ^^^ expected `u32`, found `()`
  |        |
  |        implicitly returns `()` as its body has no tail or `return` expression
2 |     x * 2;
  |          - help: remove this semicolon to return this value
```

Этот пример — doc-тест `compile_fail,E0308` в `code/ch02/src/exprs.rs`:
если он вдруг скомпилируется, тесты упадут.

## if — выражение

У `if` с веткой `else` есть значение, и обе ветки обязаны иметь один тип:

```rust
{{#include ../../code/ch02/src/exprs.rs:if_expr}}
```

`if` без `else` имеет тип `()`, поэтому его значение использовать нельзя.
Цепочка `else if` — это `if`, вложенный в `else`, а не отдельная
конструкция, как и в C.

<div class="box c">

**Как в C.** Тернарный оператор `c ? a : b` есть только для выражений, а
вычислить значение из нескольких инструкций C не умеет. GCC и clang
поддерживают для этого расширение *statement expression* `({ int t = f();
t * t; })`, им пользуются макросы ядра Linux. В Rust это обычный блок, а
`if` заменяет тернарный оператор. Как и `?:`, такое выражение часто
компилируется вообще без перехода: в `cmov` на x86_64 и в инструкции под
`it` на Cortex-M3 (пример с `match` — `ch02_adc_delay` в разделе
[2.5](05-lowering.md)).

</div>

## Тип !

У выражений `return`, `break`, `continue`, `panic!(...)` и у `loop` без
`break` значения нет вовсе: управление из них не возвращается. Их тип —
`!` (*never*), и он приводится к любому другому типу. Поэтому ветка
`match`, которая выходит из функции или переходит к следующей итерации,
не мешает остальным веткам иметь тип `u32`:

```rust
{{#include ../../code/ch02/src/exprs.rs:never}}
```

Оператор `?` в последней строке цикла — тоже скрытый `return`: если
`checked_mul` или `checked_add` вернёт `None`, функция сразу вернёт
`None`. Подробно `?` разобран в главе 7.

Функцию, которая никогда не возвращается, объявляют с типом результата
`!`. В прошивках из главы 0 так объявлены `main` (раздел
[0.6](../ch00/06-qemu.md)) и обработчик паники: микроконтроллеру некуда
вернуться из `main`, и компилятор проверяет, что тело действительно не
завершается. `debug::exit` сообщает QEMU код завершения, но сама
возвращает `()`, поэтому последний `loop {}` там нужен именно для этой
проверки.

## Блок с меткой

`break` со значением работает не только в `loop`, но и в блоке с меткой.
Это выход из середины вычисления с результатом, без вспомогательной
функции и без флагов:

```rust
{{#include ../../code/ch02/src/exprs.rs:labeled_block}}
```

<div class="box c">

**Как в C.** Здесь в C написали бы `goto out;` с меткой перед общим
выходом. Блок с меткой делает то же, но значение выходит вместе с
управлением, а перепрыгнуть через объявление переменной или войти в блок
снаружи нельзя. Вторая причина для `goto` в C — освобождение ресурсов на
общем выходе (`goto cleanup`) — в Rust не нужна: ресурсы освобождают
деструкторы, об этом [глава 3](../ch03/index.md).

</div>
