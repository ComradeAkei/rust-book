# 2.4. if let, while let, let else и цепочки условий

Полный `match` нужен не всегда. Часто интересна одна форма значения, а на
всё остальное ответ один и тот же. Для таких случаев есть короткие
конструкции, и все они сводятся к `match` с двумя ветками.

## if let

`if let образец = выражение { ... } else { ... }` — это `match` с
образцом и веткой `_`:

```rust
{{#include ../../code/ch02/src/iflet.rs:if_let}}
```

Образец среза проверяет и длину команды, и каждый байт, а `d @
b'0'..=b'7'` заодно ограничивает номер канала. Одно отличие от `match`
всё-таки есть: временные значения в условии `if let` живут меньше, чем в
`match`, и с edition 2024 ещё меньше. Это разобрано в разделе
[2.6](06-temporaries.md).

## while let

`while let` повторяет тело, пока значение подходит к образцу. Со
срезовым образцом получается разбор потока записей «тег, длина, данные»
(TLV) без единого индекса:

```rust
{{#include ../../code/ch02/src/iflet.rs:while_let}}
```

Каждая итерация отрезает от `buf` разобранную запись: `buf` — изменяемая
переменная типа `&[u8]`, и `buf = tail` двигает начало среза, не трогая
данных.

## let else

`let образец = выражение else { ... };` разбирает значение и привязывает
переменные до конца блока, а если образец не подошёл, выполняет `else`.
Ветка `else` обязана уйти из блока: `return`, `break`, `continue` или
паника. Получается ранний выход без лишнего уровня вложенности:

```rust
{{#include ../../code/ch02/src/iflet.rs:let_else}}
```

Если `else` может завершиться обычным образом, программа не
компилируется: переменным из образца нечего было бы присвоить.

```text
error[E0308]: `else` clause of `let...else` does not diverge
 --> le.rs:2:27
  |
2 |       let [x, ..] = xs else {
  |  ___________________________^
3 | |         0
4 | |     };
  | |_____^ expected `!`, found integer
  |
  = note: expected type `!`
             found type `{integer}`
  = help: try adding a diverging expression, such as `return` or `panic!(..)`
  = help: ...or use `match` instead of `let...else`
```

<div class="box c">

**Как в C.** `let else` — это привычное `if (!ok) return -EINVAL;` в
начале функции, только проверка и извлечение значения сделаны одним
действием, и забыть проверку перед использованием нельзя.

</div>

## Цепочки условий

Edition 2024 разрешает соединять `let`-условия и обычные условия через
`&&` в одном `if` или `while`. Переменные из ранних звеньев видны в
поздних:

```rust
{{#include ../../code/ch02/src/iflet.rs:chains}}
```

До цепочек то же писали вложенными `if let` или через `match` по
кортежу. Цепочки стабильны с Rust 1.88 и только в edition 2024. В
крейте edition 2021 тот же код не соберётся:

```text
error: let chains are only allowed in Rust 2024 or later
 --> ch.rs:4:8
  |
4 |     if let Some((key, value)) = line.split_once('=')
  |        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

Связка `||` между `let`-условиями не разрешена: непонятно, какие
переменные были бы привязаны, если сработала только одна сторона.

## matches!

Последнее звено цепочки — макрос `matches!(значение, образец)`. Он
возвращает `bool`: подошло ли значение к образцу. Образец может быть
с охранным условием: `matches!(reply, Some(n) if n > 0)`. Это `match` с
ветками `образец => true` и `_ => false`, и компилируется он так же: в
разделе [2.5](05-lowering.md) `matches!` с четырьмя символами
превращается в одну проверку бита.
