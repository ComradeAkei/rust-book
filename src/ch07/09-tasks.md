## B. Иерархия ошибок конфигурации

Лексер из задачи 5.B разбирает текст на лексемы. Постройте поверх него
загрузку конфигурации станции в `exercises/ch07/src/b_config.rs`:

```ini
[uart]
baud = 57600

[sensor.1]
period_ms = 100

[sensor.7]   ; давление
period_ms = "250"
```

Правила:

- секции — `[uart]` и `[sensor.N]`, где `N` от 1 до 65535;
- в `[uart]` единственный ключ `baud` из списка `BAUDS`, без секции или
  ключа скорость равна `DEFAULT_BAUD`;
- в `[sensor.N]` обязательный ключ `period_ms` из диапазона `PERIOD_MS`;
- повтор ключа заменяет прежнее значение, повтор датчика — ошибка;
- первая ошибка прекращает разбор.

Тип `ConfigError` спроектируйте сами: три уровня (ввод-вывод, синтаксис
с позицией, семантика), контекст (путь к файлу, номер строки) и
цепочка `source` без сторонних крейтов. Тесты требуют, чтобы он
реализовал `Error + Send + Sync + 'static` и занимал не больше 40 байт.
`report` печатает сообщение и все причины, как в разделе
[7.3](03-error-trait.md). Звенья цепочки и их сообщения:

| Звено | Сообщение | Причина |
|---|---|---|
| файл не прочитан | `не удалось прочитать <путь>` | `io::Error` |
| ошибка разбора файла | `<путь>: конфигурация отвергнута` | ошибка `parse` |
| ошибка лексера | `синтаксическая ошибка` | позиция |
| позиция | `строка <N>, столбец <M>: <что>` | нет |
| смысловая ошибка | `ошибка в строке <N>` | что именно |

Что именно не так со смыслом:

| Ситуация | Сообщение | Причина |
|---|---|---|
| ключ до первой секции | `ключ <k> вне секции` | нет |
| неизвестная секция | `неизвестная секция [<имя>]` | нет |
| неизвестный ключ | `неизвестный ключ <k> в секции [<имя>]` | нет |
| значение не число | `значение <k> не число` | `ParseIntError` |
| период вне диапазона | `<k> = <v> вне допустимого диапазона` | нет |
| скорость не из списка | `скорость <v> не поддерживается` | нет |
| датчик повторён | `датчик <id> описан дважды` | нет |
| у датчика нет периода | `в секции [sensor.<id>] нет ключа period_ms` | нет |

Ошибки лексера пишутся так: `нет закрывающей ]`, `недопустимое имя`,
`нет знака =`, `нет закрывающей кавычки`, `лишние символы в конце
строки`. Номер строки смысловой ошибки — строка ключа или, для
повтора датчика и отсутствующего периода, строка заголовка секции.
Лексемы главы 5 позиции не несут. Подумайте, как восстановить номер
строки, не меняя лексер.

Отчёт для файла, где у датчика период `7ms`:

```text
ошибка: station.ini: конфигурация отвергнута
  причина: ошибка в строке 2
  причина: значение period_ms не число
  причина: invalid digit found in string
```

Отдельный тест проверяет, что ни одно звено не повторяет в своём
сообщении текст причины.


Требования:

- буфер — массив `CAP` байт внутри структуры, выделений памяти нет;
- `write` копирует данные в буфер и сбрасывает его, когда он полон;
  приёмник может принять за раз меньше, чем ему дали;
- `flush` отправляет всё, при ошибке отправленная часть удаляется из
  буфера, остальное остаётся;
- `finish` сбрасывает буфер и возвращает приёмник, а при ошибке —
  `Unsent` с приёмником, ошибкой и числом неотправленных байт;
- если `Buffered` уничтожается без `finish`, деструктор старается
  сбросить данные, но **никогда не паникует** — ни при ошибке
  приёмника, ни во время раскрутки, ни после того, как запаниковал сам
  приёмник.

Последнее требование тест проверяет в отдельных процессах: паника при
живом `Buffered` с отказавшим приёмником и приёмник, который паникует
в `send` посреди сброса. Ни в одном случае процесс не должен
завершиться через abort.

Вопрос к отчёту: почему `finish` принимает `self` по значению, и что
мешает просто [переместить][g-move] приёмник из `self` в типе с `Drop`?
Сравните своё решение с `std::io::BufWriter`: что он делает в `drop`
при ошибке и после паники внутреннего писателя?
