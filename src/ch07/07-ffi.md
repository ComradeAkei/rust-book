# 7.7. Паника и граница FFI

## Раскрутка не должна уйти в C

C-код ничего не знает о раскрутке Rust. Его кадры могут держать
захваченный мьютекс, выделенную память, наполовину изменённую
структуру, и при раскрутке через них ничего из этого не будет
освобождено и восстановлено — ровно та ситуация, что с `longjmp` во
введении. Поэтому ABI `extern "C"` в Rust объявлен «нераскручиваемым»:
паника, которая дошла до границы такой функции, завершает процесс.

Опыт из `code/ch07/src/bin/panics.rs` — обратный вызов, который мог бы
передаваться в C-библиотеку (сортировка, обработчик сигнала, коллбэк
драйвера):

```rust
{{#include ../../code/ch07/src/bin/panics.rs:ffi}}
```

```console
$ cargo run -q -p ch07 --bin panics -- ffi-c

thread 'main' (18199) panicked at code/ch07/src/bin/panics.rs:82:9:
отрицательный отсчёт -1
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

thread 'main' (18199) panicked at /rustc/2d8144b7880597b6e6d3dfd63a9a9efae3f533d3/library/core/src/panicking.rs:225:5:
panic in a function that cannot unwind
stack backtrace:
   …
thread caused non-unwinding panic. aborting.
```

`catch_unwind` вокруг вызова не помог: паника не дошла до него. Строки
`drop a` в выводе тоже нет — деструкторы `ffi_c` не выполнились,
процесс завершился сигналом SIGABRT.

<div class="box hood">

**Под капотом.** Откуда берётся вторая паника, видно в ассемблере
`callback_c` (часть строк подготовки сообщения опущена):

```text
panics::callback_c:
	sub rsp, 24
	mov dword ptr [rsp + 4], edi
	test edi, edi
	js .LBB24_1
	add rsp, 24
	ret
.LBB24_1:
	…
	call qword ptr [rip + core::panicking::panic_fmt@GOTPCREL]
	ud2
	call qword ptr [rip + core::panicking::panic_cannot_unwind@GOTPCREL]
```

Последняя строка — посадочная площадка, которую компилятор добавил ко
всей функции `extern "C"`. Раскрутка от `panic_fmt` попадает в неё, и
`panic_cannot_unwind` начинает «нераскручиваемую» панику: печатает
`panic in a function that cannot unwind` и вызывает `abort`. Удвоения
`x` на пути без паники в листинге нет: `ffi_c` не использует результат,
и оптимизатор выбросил вычисление.

</div>

## extern "C-unwind"

Если раскрутка через границу действительно нужна, ABI объявляют
`extern "C-unwind"`. Соглашение о вызовах то же, что у `"C"`, но паника
проходит через границу и ловится выше:

```console
$ cargo run -q -p ch07 --bin panics -- ffi-c-unwind

thread 'main' (18201) panicked at code/ch07/src/bin/panics.rs:90:9:
отрицательный отсчёт -1
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
поймали: true
drop a
main завершился
```

Когда это нужно: C++-код вызывает Rust и хочет поймать ошибку как
исключение, или Rust вызывает C-библиотеку, собранную с `-fexceptions`,
которая передаёт управление обратно в Rust через коллбэк. Если между
кадрами Rust оказываются кадры C без таблиц раскрутки или с ресурсами,
которые надо освободить, раскрутка через них — неопределённое
поведение. Правило по умолчанию простое: обратный вызов для C ловит
панику сам и превращает её в код ошибки.

```rust,ignore
extern "C" fn on_sample(x: i32) -> i32 {
    match std::panic::catch_unwind(|| process(x)) {
        Ok(v) => v,
        Err(_) => -1, // C ждёт код ошибки, а не раскрутку
    }
}
```

Так граница остаётся непроницаемой в обе стороны, и решение о том, что
делать с отказом, принимает C-сторона по своим правилам. Подробно FFI
разбирается в главе 18.

<div class="box ref">

**Справка: история.** До Rust 1.81 раскрутка через `extern "C"` была
неопределённым поведением: на практике она иногда проходила сквозь
C-кадры, иногда портила их. Rust 1.71 добавил ABI `"C-unwind"`, а
1.81 сделал `extern "C"` гарантированно завершающим процесс при
панике — то, что вы видели в опыте. Старые статьи и ответы, где
«паника через FFI — UB», описывают прежнее поведение.

</div>

<div class="box trap">

**Ловушка.** `panic = "abort"` в профиле сборки не делает FFI-границу
безопаснее, а делает её неважной: паника всё равно завершит процесс.
Но если ваш крейт — библиотека, профиль задаёт не он, а итоговый
бинарник. Обратные вызовы библиотеки обязаны быть корректными при
любой стратегии паники.

</div>
