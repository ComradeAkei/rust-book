# 7.6. Раскрутка под капотом

## Таблицы вместо кода

Раскрутка стека из раздела [7.5](05-panic.md) должна найти каждый кадр,
восстановить сохранённые в нём регистры и вызвать деструкторы живых
переменных. На x86_64 Linux Rust делает это так же, как исключения
C++: по схеме Itanium C++ ABI, которую называют «исключениями нулевой
цены». Нулевая она для пути без ошибки: всё, что нужно раскрутке,
лежит в таблицах, а в коде функции нет ни одной лишней инструкции.

<div class="box ref">

**Справка: CFA и CFI.** Чтобы снять кадр стека, нужно знать, где он
начинается и где лежат регистры вызывающего. *CFA* (Canonical Frame
Address) — значение указателя стека до инструкции `call`, которая
вызвала функцию. *CFI* (Call Frame Information) — таблица из формата
отладочной информации DWARF: для каждого адреса внутри функции она
говорит, как вычислить CFA («`rsp` + 16») и где сохранён каждый
регистр вызывающего («`rbx` по адресу CFA − 16»). Таблица хранится
сжато, как программа для маленькой виртуальной машины. В исполняемом
файле она лежит в секции `.eh_frame`, а для быстрого поиска по адресу
есть отсортированный индекс `.eh_frame_hdr`. Этой же таблицей
пользуются gdb, `perf` и печать трассировки стека, поэтому GCC кладёт
`.eh_frame` и в обычные C-программы: у `errno.c` из введения это
184 байта.

</div>

## Посадочная площадка

Функция из `code/ch07/src/unwind.rs` держит значение с деструктором и
вызывает функцию, которая может запаниковать:

```rust
{{#include ../../code/ch07/src/unwind.rs:guarded}}
```

<div class="box hood">

**Под капотом.** `ch07_guarded` на x86_64, вывод `cargo asm` без
`--simplify`, служебные строки секции опущены:

```text
ch07_guarded:
	.cfi_startproc
	.cfi_personality 155, DW.ref.rust_eh_personality
	.cfi_lsda 27, .Lexception3
	push rbx
	.cfi_def_cfa_offset 16
	.cfi_offset rbx, -16
	mov rbx, rdi
	mov edi, edx
	call rsi
	inc dword ptr [rbx]
	pop rbx
	.cfi_def_cfa_offset 8
	ret
	.cfi_def_cfa_offset 16
	inc dword ptr [rbx]
	mov rdi, rax
	call _Unwind_Resume@PLT
```

Путь без паники — строки от `push rbx` до `ret`: сохранить `rbx`,
вызвать `f`, выполнить `drop` (встроенный `inc dword ptr [rbx]`),
вернуться. Те же инструкции получились бы и без всякой раскрутки.

После `ret` лежит *посадочная площадка* (landing pad). Обычным
выполнением до неё не дойти. Если `f` запаникует, раскрутка передаст
сюда управление с указателем на объект исключения в `rax`. Площадка
вызывает деструктор (тот же `inc`) и продолжает раскрутку вызовом
`_Unwind_Resume`.

Директивы `.cfi_*` превращаются в запись таблицы `.eh_frame`:
«после `push rbx` CFA = `rsp` + 16, `rbx` сохранён по адресу
CFA − 16». `.cfi_personality` называет *функцию личности*
`rust_eh_personality`, которая решает, что делать с кадром, а
`.cfi_lsda` указывает на таблицу этой функции в секции
`.gcc_except_table`:

```text
.Lexception3:
	.byte	255
	.byte	255
	.byte	1
	.uleb128 .Lcst_end3-.Lcst_begin3
.Lcst_begin3:
	.uleb128 .Ltmp711-.Lfunc_begin37
	.uleb128 .Ltmp712-.Ltmp711
	.uleb128 .Ltmp713-.Lfunc_begin37
	.byte	0
	.uleb128 .Ltmp712-.Lfunc_begin37
	.uleb128 .Lfunc_end37-.Ltmp712
	.byte	0
	.byte	0
.Lcst_end3:
```

Это таблица мест вызова (call-site table). Первая запись: «вызов в
диапазоне от `.Ltmp711` до `.Ltmp712` — при раскрутке перейти на
`.Ltmp713`, действие 0 (только очистка)». `.Ltmp711`–`.Ltmp712`
окружают `call rsi`, `.Ltmp713` — посадочная площадка. Вторая запись
покрывает остаток функции: площадки нет, раскрутка проходит кадр
насквозь. Метки видны с `cargo asm --keep-labels`, таблица — с
`--everything`. Номера меток меняются от любой правки крейта.

</div>

## Две фазы раскрутки

Паника в `f` вызывает `_Unwind_RaiseException` из `libgcc_s` (или
`libunwind`). Дальше всё делается по таблицам.

1. **Поиск.** Раскрутчик идёт по кадрам вверх, не меняя их: по
   `.eh_frame_hdr` находит запись CFI для адреса возврата, вычисляет
   кадр вызывающего и спрашивает функцию личности, есть ли здесь
   обработчик. Обработчик в Rust один — `catch_unwind`, и `std` сама
   ставит его в начало каждого потока: поэтому паника главного потока
   превращается в код выхода 101, а паника другого потока — в `Err` из
   `join`.
2. **Очистка.** Раскрутчик проходит те же кадры второй раз и в каждом,
   где таблица мест вызова указывает площадку, передаёт ей управление.
   Площадка вызывает деструкторы и возвращает управление раскрутчику
   через `_Unwind_Resume`. В кадре с обработчиком раскрутка
   заканчивается.

Отсюда цена паники: двоичный поиск в таблице для каждого кадра, дважды,
интерпретация программы CFI, вызовы функции личности. Это на порядки
дороже обычного `ret`, и поэтому паникой нельзя заменять `Result` в
нормальной работе. Зато пока паники нет, всё это лежит на диске и
ничего не стоит.

## Где площадок нет

Та же функция для Cortex-M3:

```text
thumbv7m:
ch07_guarded:
	push {r4, r6, r7, lr}
	add r7, sp, #8
	mov r4, r0
	mov r0, r2
	blx r1
	ldr r1, [r4]
	adds r1, #1
	str r1, [r4]
	pop {r4, r6, r7, pc}
```

Площадки нет: для `thumbv7m-none-eabi` стратегия паники — `abort`, и
`drop` при панике выполняться не должен. Так же выглядит x86_64-код с
`panic = "abort"`.

Площадки нет и тогда, когда вызываемая функция заведомо не выпускает
раскрутку наружу. `ch07_guarded_nounwind` вызывает указатель на
`extern "C" fn`, а такая функция при панике завершает процесс сама
(раздел [7.7](07-ffi.md)):

```text
ch07_guarded_nounwind:
	push rbx
	mov rbx, rdi
	mov edi, edx
	call rsi
	inc dword ptr [rbx]
	pop rbx
	ret
```

## Во что раскрутка обходится

«Нулевая цена» относится только к инструкциям на пути без ошибки. Плата
есть, и она в другом.

- **Размер.** `.eh_frame`, `.eh_frame_hdr` и `.gcc_except_table` плюс
  код площадок. Сколько это в реальной программе и сколько из этого
  убирает `panic = "abort"`, измеряет задача [7.C](09-tasks.md). Ответ
  неожиданный.
- **Упущенные оптимизации.** Площадка — ещё одна точка, где значения
  должны быть живы и в своих местах. Компилятор не может переставить
  запись в память через вызов, который может раскрутиться, если эту
  память увидит деструктор.
- **Время паники.** Поиск по таблицам для каждого кадра, см. выше.

<div class="box c">

**Как в C.** `longjmp` из введения дешевле раскрутки: он просто
восстанавливает регистры из `jmp_buf`. Именно поэтому он ничего не
знает о кадрах между `setjmp` и `longjmp`, и `free` с `unlock` в них не
выполняются. GCC умеет вызывать очистку при раскрутке и в C: атрибут
`__attribute__((cleanup(f)))` у переменной и флаг `-fexceptions`. Так
написан, например, `g_autoptr` в GLib и `__free` в ядре Linux, но
`longjmp` и эта очистка друг о друге не знают.

</div>

<div class="box trap">

**Ловушка.** Нельзя стирать `.eh_frame` из бинарника ради размера
(`strip -R .eh_frame` или скрипт компоновщика), если программа может
паниковать с раскруткой. Раскрутчик не найдёт записи для кадра и
завершит процесс, а трассировки стека при панике и в gdb станут
бесполезными. Если раскрутка не нужна, правильный путь —
`panic = "abort"`, и тогда таблицы делает ненужными сам компилятор.

</div>
