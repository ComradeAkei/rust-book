# 15. Коллекции и аллокация

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** Vec как (ptr, cap, len), стратегия роста, with_capacity, shrink_to_fit. String и &str. HashMap: SwissTable, SipHash-1-3, защита от HashDoS, сторонние быстрые хешеры. BTreeMap, VecDeque как кольцевой буфер, BinaryHeap. #[global_allocator], GlobalAlloc, Layout, арены. Коллекции без кучи на МК (heapless).

**Как в C.** realloc и висячие указатели, самописные хеш-таблицы в каждом проекте.

**Железо.** Локальность данных: `Vec<T>` против `Vec<Box<T>>` и LinkedList, аппаратная предвыборка. Как malloc в glibc переходит на mmap для больших блоков. Куча на МК и фрагментация.

**Трюки и ловушки.** retain, drain, entry API у HashMap. Отсортированный Vec с binary_search часто быстрее BTreeMap. String не индексируется по символам. Порядок обхода HashMap меняется от запуска к запуску.

**Задачи**

- A. Предскажите capacity Vec после последовательности push, reserve и shrink_to_fit и число реаллокаций.
- B. Аллокатор-счётчик через #[global_allocator]: число аллокаций и пиковое потребление. Примените его к решениям из предыдущих глав.
- C. Bump-аллокатор для построения синтаксического дерева. Сравните с системным malloc по времени, памяти и числу системных вызовов по strace.
- D. Подберите коллизии для наивной хеш-функции, затем для FNV-1a, и покажите деградацию HashMap. Объясните, почему с SipHash и случайным ключом такая атака не работает.
