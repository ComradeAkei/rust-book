# 10.1. Обобщённые функции и типы

## Параметр типа

Наименьший элемент [среза][g-slice], для любого типа, который можно сравнивать и
копировать:

```rust
{{#include ../../code/ch10/src/generic.rs:min-of}}
```

`T` — *параметр типа*. В угловых скобках после имени функции он
объявлен, а после двоеточия перечислены *ограничения*: `PartialOrd`
разрешает `<` и `>`, `Copy` — достать значение из среза [образцом][g-pattern] `&x`, не
забирая его. Вызов пишется как обычно, `min_of(&[3u8, 1, 2])`, и `T`
компилятор выводит из аргумента: здесь `u8`.

Главное отличие от макроса из введения: тело функции проверяется один
раз, по ограничениям, и до того, как функцию кто-нибудь вызовет. Если
убрать `PartialOrd`, ошибка будет в самой функции:

```text
error[E0369]: binary operation `<` cannot be applied to type `T`
 --> e0369.rs:5:14
  |
5 |         if x < m {
  |            - ^ - T
  |            |
  |            T
  |
help: consider further restricting type parameter `T` with trait `PartialOrd`
  |
1 | pub fn min_of<T: Copy + std::cmp::PartialOrd>(v: &[T]) -> Option<T> {
  |                       ++++++++++++++++++++++
```

Внутри функции о `T` известно только то, что написано в ограничениях, и
ничего больше: ни размер, ни поля, ни операторы. Зато тип, который
ограничениям не отвечает, отвергается в месте вызова, а не внутри тела:

```text
error[E0277]: can't compare `Point` with `Point`
  --> e0277.rs:10:20
   |
10 |     let p = min_of(&[Point { x: 1, y: 2 }]);
   |             ------ ^^^^^^^^^^^^^^^^^^^^^^^ no implementation for `Point < Point` and `Point > Point`
   |             |
   |             required by a bound introduced by this call
   |
   = help: the trait `PartialOrd` is not implemented for `Point`
note: required by a bound in `min_of`
  --> code/ch10/src/generic.rs:41:0
help: consider annotating `Point` with `#[derive(PartialOrd)]`
   |
 4 + #[derive(PartialOrd)]
 5 | struct Point {
   |
```

Сравните с тремя ошибками GCC внутри `DEFINE_SORT`: там компилятор
сообщает, какая строка тела не собралась, а здесь — какое обещание
нарушил вызывающий. Сигнатура обобщённой функции — договор в обе
стороны: тело не может требовать от `T` больше, чем в ограничениях, а
вызывающий обязан дать тип, который им отвечает.

<div class="box c">

**Как в C.** Макрос `DEFINE_SORT` и шаблоны C++ проверяются после
подстановки: ошибка в аргументе всплывает внутри тела, а тело, которое
никто не развернул, может быть сколь угодно неверным. `void *` и
`qsort` проверяют типы ещё меньше: никак. Обобщение Rust проверяется
дважды и в двух местах — тело по ограничениям, вызов по ограничениям, — и
после этого подстановка уже не может сломаться. Ближе всего к этому
концепты C++20, но в C++ их можно не писать, а в Rust ограничения —
единственный способ что-то сделать с `T`.

</div>

## Обобщённый тип

Параметры бывают и у структур. Наименьшее и наибольшее значение потока
отсчётов:

```rust
{{#include ../../code/ch10/src/generic.rs:minmax}}
```

`MinMax<T>` — не тип, а семейство типов: `MinMax<i16>`, `MinMax<f32>`,
`MinMax<&str>`. Блок `impl<T: PartialOrd + Copy> MinMax<T>` объявляет
свой параметр `T` и даёт методы всем членам семейства, у которых `T`
отвечает ограничениям. Блок `impl MinMax<i16>` параметров не объявляет и
относится только к одному типу: метод `span` есть у `MinMax<i16>` и нет
у `MinMax<f32>`. Размах двух `i16` возвращается как `u16`: разность
`4000 - (-300)` в `i16` поместилась бы, а `i16::MAX - i16::MIN` = 65535
уже нет. `abs_diff` считает её без переполнения, тест проверяет оба
случая.

[Раскладка][g-layout] `MinMax<T>` — как у структуры с двумя полями типа `T`, по
правилам главы 6: `MinMax<i16>` занимает 4 байта, `MinMax<f64>` — 16.
Никакого заголовка с типом или размером в значении нет, тип известен
при компиляции.

## Turbofish

Обычно параметры выводятся из аргументов. Когда аргументов нет, тип
приходится назвать:

```rust
{{#include ../../code/ch10/src/generic.rs:turbofish}}
```

`zeroed()` без подсказки компилятор не примет: `T` неоткуда взять.

```text
error[E0283]: type annotations needed
 --> e0283.rs:2:9
  |
2 |     let z = ch10::generic::zeroed();
  |         ^   ----------------------- type must be known at this point
  |
  = note: the type must implement `Default`
note: required by a bound in `ch10::generic::zeroed`
 --> code/ch10/src/generic.rs:97:0
help: consider giving `z` an explicit type
  |
2 |     let z: /* Type */ = ch10::generic::zeroed();
  |          ++++++++++++
```

Подсказать можно двумя способами: типом переменной, `let z: [u16; 4] =
zeroed();`, или явным аргументом в самом вызове, `zeroed::<[u16; 4]>()`.
Запись `::<>` прозвали *turbofish*. Двоеточия нужны, потому что в
выражении `zeroed<u32>()` знак `<` разбирался бы как «меньше». Turbofish
встречается постоянно: `"42".parse::<u8>()`, `iter.sum::<u32>()`,
`collect::<Vec<_>>()`, где `_` просит компилятор вывести остальное
самому. В `parse_list::<u8>("1, 2,3")` вызывающий выбирает тип чисел, и
от него зависит, что считать ошибкой: `"1,300"` для `u8` — ошибка, для
`u16` — нет.

<div class="box hood">

**Под капотом.** Обобщённая функция в библиотеке не компилируется в
машинный код вовсе. В `.rlib` хранится её [промежуточное представление][g-ir]
[MIR][g-mir], а код появляется там, где функцию вызвали с конкретными типами: в
[крейте][g-crate] вызывающего. Поэтому `min_of::<u8>` и `min_of::<f32>` — две
разные функции, и в каждой `<` — одна инструкция сравнения своего типа.
Сколько таких копий окажется в прошивке и как их посчитать, разбирает
раздел [10.5](05-mono.md).

</div>

<div class="box trap">

**Ловушка.** `PartialOrd` — частичный порядок: у `f32` есть NaN, который
не меньше, не больше и не равен ничему. `min_of(&[2.0, f32::NAN, 1.0])`
вернёт 1,0, а `min_of(&[f32::NAN, 1.0])` — NaN: первый элемент стал
начальным минимумом, и ни одно сравнение `x < NaN` не сработало.
Результат зависит от порядка элементов. Если такое недопустимо,
требуйте `Ord`: у `f32` его нет, и вызывающему придётся явно решить, что
делать с NaN, например через `f32::total_cmp`.

</div>

<div class="box check">

**Проверь себя.** Почему `MinMax::of(&[1u8, 2]).unwrap().span()` не
скомпилируется и какая ошибка будет? Что выведет компилятор для `T` в
`min_of(&["б", "а"])` и почему это работает без `Copy` у `str`? Зачем
`MinMax<T>` из `derive` получает `Clone` и `Copy` с ограничениями
`T: Clone` и `T: Copy`, а не безусловно?

</div>
