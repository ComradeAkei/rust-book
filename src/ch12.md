# 12. Замыкания

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** Синтаксис, захват по ссылке, по изменяемой ссылке и по значению, move. Fn, FnMut, FnOnce и их иерархия. Замыкание как анонимная структура, указатели на функции, возврат замыканий. Точный захват полей и асинхронные замыкания.

**Как в C.** Указатель на функцию плюс void *context в каждом API с обратными вызовами.

**Железо.** Размер замыкания равен размеру захваченного. Замыкание без захвата имеет нулевой размер и приводится к fn-указателю. Переданное в обобщённую функцию замыкание встраивается целиком.

**Трюки и ловушки.** Обобщённый трамплин extern "C" fn tramp<F: FnMut()>(ctx: *mut c_void) для передачи замыкания в C (подробно в главе 18). move копирует Copy-значения, и изменение внутри замыкания не видно снаружи.

**Задачи**

- A. Предскажите size_of для 8 замыканий с разными захватами, с move и без.
- B. Регистратор обработчиков событий без кучи: массив &mut dyn FnMut(Event) против обобщённого варианта. Объясните, кто владеет состоянием в каждом.
- C. Комбинаторы парсеров (map, and_then, many) на замыканиях и разбор ими ответов AT-команд модема. Проверьте, что итоговый парсер встроился без косвенных вызовов.
- D. Постройте пример, где одна строка в теле замыкания делает его не Send и ломает компиляцию thread::spawn далеко от места изменения. Объясните, как выводятся auto traits замыкания.
