## A. Каталог неопределённого поведения

Шесть фрагментов, по одному на пункт перечня из
[раздела 16.2](../ch16/02-invariants.md). Для каждого Miri обязан
сообщить об ошибке; скрипт проверяет, что процесс завершается с ненулевым
кодом.

- **Выход за границы** (`a_bounds`): `*v.get_unchecked(5)` на [срезе][g-slice] длины
  3. Под Miri первой срабатывает [проверка предусловия][g-ub-checks] в самой `std`: она
  включена в отладочной сборке, а `cargo miri test` собирает отладочную.
  Сообщение — «unsafe precondition(s) violated: slice::get_unchecked
  requires that the index is within the slice», затем аварийный останов.
  С `--release` этой проверки нет, и Miri сообщает своё: «`assume` called
  with `false`» — `get_unchecked` передал оптимизатору обещание «индекс в
  границах», и оно ложно. Обычный запуск в release падает с SIGILL:
  с постоянным индексом обещание заведомо ложно, и LLVM поставил на его
  место `ud2`. С индексом, известным только во время работы, такое чтение
  на x86 часто попадает в ту же страницу и «работает», возвращая мусор;
  Miri знает точные границы выделения и ловит сразу.
- **Use-after-free** (`a_use_after_free`): `Box::from_raw` роняет
  выделение, затем читают по сохранённому указателю. Miri: «memory
  access failed: alloc… has been freed, so this pointer is dangling».
- **Недопустимое значение** (`a_invalid_bool`): байт 2 читают как `bool`.
  Miri: «constructing invalid value of type bool: encountered 0x02, but
  expected a boolean» — в самой строке чтения, значение использовать не нужно.
- **Нарушение алиасинга** (`a_aliasing`): две живые `&mut` из одного
  [сырого указателя][g-raw-pointer]. [Stacked Borrows][g-stacked-borrows]: «attempting a write access using
  <…> …, but that tag does not exist in the borrow stack for this
  location» на записи `*a = 1` — создание `b` сняло метку `a` со стека.
  Tree Borrows: «write access through <…> … is forbidden» на записи
  `*b = 2` — запись через `a` сделала соседа `b` недействительным. Это UB
  в обеих моделях, в отличие от задачи D.
- **Неинициализированная память** (`a_uninit`):
  `MaybeUninit::uninit().assume_init()` для `u32`. [Линт][g-lint] `invalid_value` и
  [clippy][g-clippy] `uninit_assumed_init` предупреждают ещё при компиляции (их
  пришлось `#[allow]`), а Miri сообщает: «constructing invalid value of
  type u32: encountered uninitialized memory, but expected an integer».
- **Невыровненный доступ** (`a_misaligned`): `u32` читают по адресу,
  смещённому на 1 байт. Miri: «accessing memory based on pointer with
  alignment 1, but alignment 4 is required». На x86 невыровненное чтение
  исполняется аппаратно и незаметно. На Cortex-M0 оно даёт [HardFault][g-hardfault], на
  M3 и M4 одиночный `ldr` его допускает, а `ldrd` и `ldm` — нет (раздел
  [6.7](../ch06/07-packed.md)); на многих RISC это исключение. Miri
  моделирует строгий случай.

«Молчащих» пунктов в этом каталоге нет: все шесть ловятся без
дополнительных флагов. Пункт про гонку данных в каталог не вошёл — для
него нужен второй поток, и его разбирают в [главе 14](../ch14/index.md).

## B. split_first_mut вручную

```rust
{{#include ../../solutions/ch16/src/b_split.rs:solution}}
```

Пустой срез — `None` (иначе `p.add(1)` ушёл бы за границу нулевого
выделения). Иначе `p` — адрес `s[0]`, `p.add(1)` — начало хвоста. Ключ в
`// SAFETY`: отрезки `[0,1)` и `[1,len)` не пересекаются, поэтому две
`&mut` на них — не алиасинг, а значит обе модели это принимают. Тест
`b_splits_head_and_tail` пишет и в голову, и в хвост, пока обе ссылки
живы; под Miri (SB и TB) он проходит — доказательство, что
непересечение не «на глаз», а по правилам абстрактной машины.

Почему без `unsafe` нельзя: заёмщик рассуждает по индексам синтаксически
и не знает, что `0` и `1..` не пересекаются; `&mut s[0]` и `&mut s[1..]`
для него — два заёма одного `s`, и он запрещает второй. Факт
непересечения приносит программист — и отвечает за него в `// SAFETY`.

## C. Unsound-API и его исправление

Ошибочный вариант обещает `'static` поверх чужого [времени жизни][g-lifetime]:

```rust
{{#include ../../solutions/ch16/tests/ub.rs:c_unsound}}
```

Безопасная программа `c_unsound_dangles` не содержит ни одного `unsafe` и
всё равно получает use-after-free: берёт `'static`-ссылку внутрь
временной `String` и пользуется ею после выхода из блока. Miri ловит
висячую ссылку, как только её передают в `len()`: «constructing invalid
value of type &str: encountered a dangling reference (use-after-free)».
Виновата не программа и не вызывающий — виновата
**сигнатура**: `transmute` выдал обещание (`'static`), которого функция
сдержать не может. Чинить вызывающего бессмысленно: API остаётся
миной для следующего. Честная замена не лжёт о времени жизни и обходится
вовсе без `unsafe`:

```rust
{{#include ../../solutions/ch16/src/c_sound.rs:solution}}
```

`view(&self) -> &str` связывает результат с `&self`: компилятор сам не
даст использовать срез после того, как `StrBuf` исчез. [Soundness][g-soundness] — это
свойство API, а не наличие ключевого слова: здесь его дала как раз
*убранная* `unsafe`-операция.

## D. Tree Borrows принимает, Stacked Borrows отвергает

```rust
{{#include ../../solutions/ch16/src/d_models.rs:diverge}}
```

При обычном запуске функция возвращает 3. Разница — в последней записи
через `p`:

- **Stacked Borrows.** `let p: *mut u8 = r` кладёт на стек ячейки метку
  SharedReadWrite. `let r2 = &mut *r` — это Unique-retag: он снимает со
  стека всё, что выше `r`, включая метку `p`. Запись `*p = 3` идёт по
  снятой метке — Miri сообщает «tag … does not exist in the borrow stack
  for this location».
- **Tree Borrows.** Метки образуют дерево: `p` и `r2` — соседние потомки
  `r`, а не элементы одного стека. Запись через `r2` не вычёркивает `p`,
  и последняя запись через `p` законна.

Для автора `unsafe`-кода вывод прост: пока единственной модели нет, этот
приём непереносим, и сегодняшний оптимизатор рассуждает ближе к Stacked
Borrows. Правильный `unsafe` держится в пределах того, что принимают обе
модели (как `split_first_mut` задачи B); программа из задачи D живёт в
`#[ignore]`-тесте именно потому, что в примеры её пускать нельзя.

<div class="box check">

**Ответы к «проверь себя» из [16.8](../ch16/08-tasks.md).**

1. Невыровненное чтение на x86 исполняет процессор, лишь чуть медленнее;
   на ARM без поддержки невыровненного доступа — исключение. Miri берёт
   строгий случай, потому что язык обещает корректность на всех [целях][g-target].
2. Заёмщик видит `s[0]` и `s[1..]` как два заёма одного `s` и не выводит
   их непересечение из индексов; это приносит программист под `unsafe`.
3. Ошибка в сигнатуре: `transmute` обещает `'static`, невыполнимое для
   заёмной строки. Починка вызывающего не трогает обещание, поэтому API
   остаётся unsound для любого следующего вызывающего.
4. Метку сырого указателя снимает Unique-retag при `&mut *r`; Tree
   Borrows ведёт дерево, где соседний потомок метку не вычёркивает.
