# 26. no_std: программа без операционной системы

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** core, alloc и std. #![no_std], #![no_main], #[panic_handler], точка входа. Скрипт линковщика: MEMORY, SECTIONS, ENTRY. Стартовый код: копирование .data и обнуление .bss. Глобальный аллокатор в no_std, тестирование no_std-кода на хосте.

**Как в C.** crt0, -nostdlib, -ffreestanding, скрипты линковщика от производителя.

**Железо.** На x86_64 Linux: _start без libc, системные вызовы через инструкцию syscall (номер в rax, аргументы в rdi, rsi, rdx), выравнивание стека. На Cortex-M: таблица векторов, начальный SP, Reset handler.

**Трюки и ловушки.** Вывод через semihosting в QEMU до появления UART. Компилятор вызывает memcpy и memset даже в no_std, их даёт compiler_builtins. Раскрутка стека в no_std недоступна без дополнительных усилий.

**Задачи**

- A. Для 10 типов и функций определите, где они живут: core, alloc или только std, и почему.
- B. Статический бинарник для x86_64 Linux без std и libc: _start, write и exit через syscall. Минимизируйте размер и объясните, из чего состоит каждый оставшийся байт ELF.
- C. Собственный стартовый код для Cortex-M без cortex-m-rt: таблица векторов, Reset handler, копирование .data, обнуление .bss, свой скрипт линковщика. Запуск в QEMU lm3s6965evb с выводом через semihosting.
- D. Найдите, откуда в no_std-прошивке берётся вызов memcpy, и замените его своей реализацией. Покажите, почему наивный memcpy на Rust может вызвать сам себя: LLVM узнаёт в цикле идиому memcpy.
