# 16.1. Пять возможностей unsafe

`unsafe` даёт ровно пять новых возможностей — и ничего сверх них. Оно не
выключает проверки заимствования, не разрешает гонки и не делает код
быстрее само по себе. Оно лишь разрешает то, что без него компилятор
отвергает:

1. разыменовать сырой указатель;
2. вызвать `unsafe fn` (или `unsafe`-операцию);
3. обратиться к `static mut`;
4. реализовать `unsafe trait`;
5. прочитать поле `union`.

Всё остальное внутри `unsafe`-блока проверяется ровно как снаружи.

## 1. Сырой указатель

Создать *сырой указатель* (raw pointer), `*const T` или `*mut T`, и
прочитать его адрес можно в безопасном коде;
разыменовать — только в `unsafe`.

```rust
{{#include ../../code/ch16/src/abilities.rs:raw}}
```

Вне `unsafe` разыменование не компилируется:

```rust
let x = 5;
let p = &x as *const i32;
let _v = *p; // error[E0133]: dereference of raw pointer is unsafe
```

## 2. Вызов unsafe fn

`unsafe fn` обещает корректный результат только при соблюдении
предусловия, записанного в её документации под заголовком `# Safety`.
Вызвать её без `unsafe` нельзя — это тоже E0133.

```rust
{{#include ../../code/ch16/src/abilities.rs:unsafe_fn}}
```

**Ловушка.** Заголовок секции предусловий — обязательно английский

## 3. static mut

`static mut` — одна изменяемая ячейка на всю программу. В edition 2024
взять на неё ссылку запрещено (слишком легко получить две `&mut`);
берут сырой указатель через `&raw mut` и работают через него.

```rust
{{#include ../../code/ch16/src/abilities.rs:static_mut}}
```

Это годится на счётчик прерываний в однопоточной прошивке, но не на
общий доступ из нескольких потоков — там нужен `AtomicU32` или
`Mutex` ([глава 14](../ch14/index.md)). Ссылку на `static mut` компилятор
не даст взять даже внутри `unsafe`:

```rust
static mut C: u32 = 0;
let _r = unsafe { &C }; // error: creating a shared reference to mutable static
```

## 4. unsafe trait

Трейт объявляют `unsafe`, когда от корректности его реализации зависит
безопасность чужого кода. Классический пример — `Send` и `Sync` из
[главы 14](../ch14/index.md): компилятор верит реализатору, что тип и
правда можно передать между потоками. Здесь — маркер «тип можно побайтно
обнулить».

```rust
{{#include ../../code/ch16/src/abilities.rs:unsafe_trait}}
```

И реализация, и вызов такого трейта опираются на обещание реализатора;
нарушил — UB в коде, который этому обещанию поверил.

## 5. Поле union

Все поля `union` лежат по одному адресу, и компилятор не знает, какое
записано последним. Поэтому чтение поля — `unsafe`: читающий отвечает за
то, что битовое представление годится для выбранного типа.

```rust
{{#include ../../code/ch16/src/abilities.rs:union}}
```

<div class="box c">

**Как в C.** Все пять возможностей в C доступны всегда и без всякой
пометки: указатели разыменовывают где угодно, `union` читают любым
полем, глобальные изменяемые переменные — норма. Цена — ровно та, что в
[мотивирующей проблеме](index.md): UB размазано по всей программе. Rust
не убирает эти инструменты, а сужает область, где их можно применить, до
`unsafe`-блока, который видно в коде и который берут на карандаш при
ревью.

</div>

<div class="box ref">

**Как в стандартной библиотеке.** На этих пяти возможностях построено
всё остальное: `Vec` разыменовывает сырой указатель на буфер, `Mutex`
читает `UnsafeCell` через сырой указатель, `MaybeUninit` — это `union` из
пустого поля `uninit: ()` и поля `value: ManuallyDrop<T>`. Безопасный
API стандартной библиотеки — это тонкая корректная оболочка вокруг
`unsafe`, и [16.6](06-api.md) показывает, как такую оболочку писать.

</div>
