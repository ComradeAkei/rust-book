# 20.1. Потоки: spawn, join, move

Поток запускают функцией `thread::spawn`: она берёт [замыкание][g-closure] и исполняет
его на новом потоке операционной системы, а возвращает `JoinHandle<T>` —
ручку, через которую можно дождаться результата.

```rust
{{#include ../../code/ch20/src/spawn.rs:spawn}}
```

Ключевое слово `move` переносит захваченные переменные во владение потока.
Это не стилистика, а необходимость: поток может пережить кадр, который его
запустил, поэтому одалживать у кадра по ссылке нельзя — данные либо
переносят (`move`), либо делят через `Arc` ([20.3](03-shared.md)). После
`spawn` исходная переменная `data` недоступна, и компилятор это гарантирует
— двух владельцев одного вектора в разных потоках не возникнет.

Если захваченная переменная сама имеет тип `&T`, `move` переносит только
эту ссылку: он не копирует `T` и не продлевает время его жизни. Поэтому
добавить `move` к замыканию с [заимствованными][g-borrowing] локальными данными иногда
недостаточно; ниже для этого понадобится `thread::scope`.

`join` дожидается завершения потока и возвращает `Result<T>`: `Ok` с
результатом замыкания или `Err`, если поток паниковал. Тип `T` несёт сам
`JoinHandle`, поэтому результат приходит уже нужного типа:

```rust
{{#include ../../code/ch20/src/spawn.rs:many}}
```

Здесь важен порядок: мы собираем результаты через `join` по очереди запуска,
а не по готовности, — поэтому `squares` отдаёт `[0, 1, 4, 9, 16]` в том же
порядке, в каком потоки были созданы, хотя закончились они как попало.

<div class="box c">

**Как в C.** `thread::spawn` — это `pthread_create`, `join` —
`pthread_join`. Но в C замыкания нет: в поток передают `void *arg`, и
привести его обратно к нужному типу — ручная работа без проверки. Возврат
результата в C — тоже через `void *`, а забытый `pthread_join` оставляет
зомби-поток. В Rust замыкание захватывает переменные с их типами, `join`
возвращает типизированный результат, а уроненный `JoinHandle` не оставляет
зомби: поток просто открепляется (detach). Только происходит это молча —
`JoinHandle` не помечен `#[must_use]`, и `thread::spawn(|| …);` без `join`
компилируется без единого предупреждения.

</div>

<div class="box trap">

**Ловушка — `'static`.** `thread::spawn` требует, чтобы замыкание было
`'static`: оно может пережить вызвавшую функцию, поэтому не вправе
одалживать её локальные переменные. Отсюда вечное `move` и `Arc` для общих
данных. Если параллелизм временный и потоки точно завершатся здесь же, это
ограничение снимает `thread::scope` ([20.4](04-scoped.md)).

</div>

<div class="box hood">

**Под капотом.** `thread::spawn` создаёт настоящий поток ОС (на Linux —
через `clone`), со своим стеком (по умолчанию несколько мегабайт, настраивается
через `Builder::stack_size`). Это не зелёные потоки из [19.2](../ch19/02-naked.md)
и не задачи async: у каждого — свой стек ядра, и переключает их планировщик
ОС, а не наша `switch`. Создать и дождаться потока стоит десятки
микросекунд — десятки и сотни тысяч тактов (пустой `spawn` с `join` в
контейнере сборки книги — около 100 мкс), поэтому на короткую работу их не
плодят поштучно, а берут из пула.

</div>
