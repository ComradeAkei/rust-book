```rust

```

Условия:

- таблица для каждого типа строится при компиляции и одна на тип:
  `SensorRef::new` ничего не выделяет и не заполняет во время работы;
- `SensorRef` не переживает объект, на который указывает, и
  копируется, как `&dyn Sensor`;
- `SensorBox::new` кладёт объект в кучу, `Drop` зовёт деструктор из
  таблицы и возвращает память с размером и выравниванием из неё; тип
  нулевого размера `Box` не выделяет, и `SensorBox` не должен
  освобождать то, чего не выделял;
- `unsafe` — только там, где без него нельзя, с комментарием `SAFETY:`
  у каждого блока.

Тест `task_b_calls` проверяет вызовы, имена, размеры и то, что у
`Thermo` нет деструктора. `task_b_one_table_per_type` сравнивает адреса
таблиц двух объектов одного типа и разных типов. `task_b_box_drop`
считает вызовы деструктора и проверяет тип нулевого размера и тип с
выравниванием 32. `task_b_same_code` собирает крейт в release для
x86-64 и Cortex-M3 и сравнивает ассемблер двух функций:

```rust
{{#include ../../exercises/ch11/src/b_vtable.rs:compare}}
```

Их тела должны совпасть инструкция в инструкцию, а в теле
`ch11_b_read_dyn` должен найтись переход по слову 3 таблицы:
`jmp qword ptr [rsi + 24]` и `ldr r1, [r1, #12]`.


`run` одна на все три вида элементов: срез `Box<dyn Op>`, срез
перечислений и срез `OpK<K>`. Тест `task_c_kinds` сверяет перестановку
с условием, `task_c_forwarding` — пересылку и `run`, `task_c_sums` —
суммы всех трёх видов для 2, 8 и 64 типов, по порядку и вперемешку.
`task_c_calls` собирает крейт в release и проверяет, что в
`ch11_c_run_dyn` остался вызов через таблицу, а в `ch11_c_run_static`
вызовов нет. Время меряет пример:

```console
$ cargo run --release -p ch11-exercises --example c_bench
```

Он строит по 65 536 элементов каждого вида и печатает лучшее из пяти
время на элемент для всех шести сочетаний числа типов и порядка.
Третий аргумент оставляет один замер, и его можно прогнать под
счётчиками процессора или под моделью предсказателя `valgrind`:

```console
$ cargo build --release -p ch11-exercises --example c_bench
$ perf stat -e branches,branch-misses target/release/examples/c_bench 65536 200 8/shuffled/dyn
$ valgrind --tool=callgrind --branch-sim=yes --toggle-collect='*best*' \
      target/release/examples/c_bench 4096 2 8/shuffled/dyn
```

`perf` нужен доступ к счётчикам, а в виртуальных машинах их часто нет.
`--toggle-collect` ограничивает подсчёт функцией замера `best`, без
построения массивов.
