# 23.7. Задачи

Все задачи решаются кодом: заготовки — в `exercises/ch23`, тесты, общие
для заготовок и решений, — в `tests-shared/ch23.rs`. Образцы макросов в
заготовках уже разбирают свой вход и порождают нужные типы, но с
заглушками внутри: тесты компилируются и падают, пока задача не решена.

```console
$ cargo test -p ch23-exercises            # все задачи
$ cargo test -p ch23-exercises b_         # одна задача
$ cargo test -p ch23-solutions            # эталон
```

Макросы задач B–D экспортированы (`#[macro_export]`) и раскрываются в
чужом крейте — в тестах. Поэтому всё, что они порождают, пишется полными
путями от `::core` и `$crate` ([23.3](03-hygiene.md)). В `const fn` нельзя
`todo!()`, поэтому заглушки там — `panic!("не решено: ...")`. Разборы — в
[приложении E](../appendix-e/ch23.md), но сначала попробуйте сами.

## B. Флаги регистра

Макрос в духе крейта bitflags: тип-обёртка над целым и по константе на
флаг, с операциями над множествами битов. Вход и константы флагов
заготовка уже разбирает:

```rust
{{#include ../../exercises/ch23/src/b_flags.rs:skeleton}}
```

Допишите методы — `const fn`, чтобы их можно было звать в константах, —
операторы `|`, `&`, `!`, `|=`, `&=` и `Debug`. Требования тестов:

- `all()` — объединение объявленных флагов; `!` и `complement` —
  дополнение *в пределах* объявленных флагов, а не всех битов целого:
  `!Cr::TXE` — это `UARTEN | LBE | RXE`, без зарезервированных битов
  регистра;
- `from_bits` возвращает `None`, если в числе есть необъявленные биты;
  `from_bits_truncate` их отбрасывает; `from_bits_retain` хранит как есть
  — регистр вправе вернуть зарезервированные биты;
- `Debug` печатает `Cr(UARTEN | TXE | RXE)`, пустое множество —
  `Cr(empty)`, а необъявленные биты — числом: `Cr(TXE | 0x4)`;
- тип — просто целое: `size_of::<Cr>()` равен 4, у `Status: u8` — 1;
- макрос работает в модуле `hostile`, где вызывающий объявил свои
  `Option`, `Result` и модули `core` и `fmt`.

Операторы — методы трейтов, а методы трейтов в `const` не вызвать;
поэтому константы собирают через `const fn union`. Прошивка
`firmware/ch23-periph` описывает этим макросом регистры FR и CR
настоящего UART0 и печатает их через `Debug`.

## C. Описание периферии

Макрос `peripheral!` описывает блок регистров и порождает доступ к ним:

```rust,ignore
peripheral! {
    UART0 @ 0x4000_C000 { DR: u32 @ 0x00, FR: u32 @ 0x18 ro }
}
```

Каждый регистр — метод, который возвращает типизированный `Reg<T, A>`:
тип значения и право доступа — параметры типа, и у `Reg<u32, RO>` просто
нет метода `write`. Типы прав, трейты и `Reg` даны:

```rust
{{#include ../../exercises/ch23/src/c_periph.rs:skeleton_reg}}
```

Заготовка макроса разбирает вход, но всем регистрам даёт право `RW`, а
методы регистров и `steal` — заглушки:

```rust
{{#include ../../exercises/ch23/src/c_periph.rs:skeleton}}
```

Допишите: `read`, `write` и `modify` (volatile), выбор права по слову
`ro`, `wo` или `rw` (без слова — `RW`), `steal` по адресу `BASE` и
проверку при компиляции, что смещение регистра кратно его выравниванию.
Тесты `c_*` проверяют права через `TypeId`, чтение и запись по смещениям
на блоке обычной памяти (`UART0::at`) и узкие регистры `u8` и `u16`.
Doc-тесты модуля проверяют отказы: запись в `ro` и чтение из `wo` — E0599,
смещение 0x02 у `u32` — E0080, неизвестное слово `rx` — ошибка разбора.

Подсказки из разделов главы: после `$ty:ty` нельзя поставить `@`
([23.1](01-rules.md)); выбор по необязательному слову — внутреннее
правило, как `@or` у `config!` ([23.2](02-repeat.md)); указатель на
устройство из числа-адреса — `core::ptr::with_exposed_provenance_mut`
([16.4](../ch16/04-provenance.md)).

Проверка на железе — прошивка `firmware/ch23-periph` для lm3s6965evb,
где UART0 описан вашим макросом:

```rust

```


```console
$ cd firmware && cargo run --release -p ch23-periph
CR после сброса: Cr(TXE | RXE)
uart0: hello from peripheral!
CR: Cr(UARTEN | TXE | RXE)
FR: Fr(RXFE | TXFE)
FR, передатчик: Fr(TXFE)
```

Строка `uart0: ...` ушла в UART0 — QEMU выводит его в стандартный вывод,
— а остальные напечатаны через semihosting. После сброса PL011 держит
включёнными TXE и RXE, но не сам UART (UARTEN); прошивка включает его и
пишет строку, опрашивая TXFF. Стандартный ввод QEMU отдаёт в приёмник
того же UART0: если на вводе что-то есть, вместо `RXFE` будет `RXFF`.
Поэтому `firmware/run-demos.sh` сверяет только биты передатчика.

## D. Конечный автомат

TT-muncher, который превращает описание автомата в код:

```rust,ignore
fsm! {
    pub enum Link { Idle, Dialing, Online, Failed }
    pub enum LinkEvent { Dial, Ack, Timeout, Hangup, Reset }
    Idle --Dial--> Dialing,
    _ --Reset--> Idle,
    Dialing --Ack--> Online,
    Dialing | Online --Timeout--> Failed,
    Online --Hangup--> Idle,
}
```

Заготовка разбирает перечисления и порождает их вместе со списком
`STATES`, но переходы пока не разбирает:

```rust
{{#include ../../exercises/ch23/src/d_fsm.rs:skeleton}}
```

Допишите правила, которые съедают переходы по одному: `a --e--> b`,
`a | b --e--> c` и `_ --e--> c` — «из любого состояния». Сгенерировать
нужно:

- `const fn next(self, event) -> Option<Self>`; конкретный переход важнее
  `_`, где бы `_` ни стоял (тест `d_transitions`: `Reset` из каждого
  состояния, хотя `_ --Reset-->` записан вторым);
- `TRANSITIONS` — таблица: конкретные переходы в порядке записи, затем
  переходы из `_` с `None` в источнике (тест `d_table`, шесть записей);
- `DOT` — граф для Graphviz, где переход из `_` раскрыт в рёбра из каждого
  состояния (тест `d_dot` сравнивает строку целиком;
  `dot -Tsvg` рисует её как есть);
- ошибку компиляции на два перехода из одного состояния по одному
  событию.

Ветки `match` по одной макрос выдать не может ([23.4](04-recursion.md)) —
копите их в накопителях и выдавайте разом. Doc-тесты модуля проверяют
отказы: опечатка в имени состояния — E0599 с указанием на имя в переходе,
повтор пары «состояние, событие» — E0080.

Вторая часть задачи — вопрос: **где граница**, за которой автомат
разумнее описывать процедурным макросом ([глава 24](../ch24/index.md))? Найдите её
измерением, а не на глаз: сколько переходов выдерживает ваш макрос без
`#![recursion_limit]`, как растёт время компиляции с числом переходов
(`RUSTC_BOOTSTRAP=1 rustc -Ztime-passes` показывает время раскрытия
отдельно), какие ошибки пользователя `macro_rules!` не может указать
точно и какие проверки ему недоступны вовсе.
