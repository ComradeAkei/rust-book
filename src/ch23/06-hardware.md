# 23.6. Макросы для железа

В прошивке макросы делают три работы: держат описания в одном месте
(коды ошибок, регистры, прерывания), генерируют из описания код, который
иначе пришлось бы писать руками и сверять глазами, и прячут повторяющийся
`unsafe` за проверенной оболочкой. Все три — в этом разделе, вместе с
ответом на вопрос, во что это обходится.

## X-macro: один список — несколько генераций

Коды ошибок протокола станции телеметрии нужны в трёх местах: как
перечисление в прошивке, как текст для журнала и как заголовок для
C-стороны провода. Список — один:

```rust
{{#include ../../code/ch23/src/hardware.rs:xmacro_list}}
```

`station_errors!` сам ничего не генерирует: он принимает *имя* другого
макроса и отдаёт ему список — ровно как `STATION_ERRORS(X)` в C отдаёт
список макросу `X`. Первый генератор строит перечисление с текстами и
разбором кода с провода:

```rust
{{#include ../../code/ch23/src/hardware.rs:xmacro_enum}}
```

Второй — заголовок для C из того же списка:

```rust
{{#include ../../code/ch23/src/hardware.rs:xmacro_header}}
```

`C_HEADER` — строковая константа, склеенная при компиляции:

```c
/* сгенерировано из station_errors! */
#define STATION_ERR_Ok 0 /* нет ошибки */
#define STATION_ERR_Timeout 1 /* тайм-аут */
#define STATION_ERR_Crc 2 /* ошибка CRC */
#define STATION_ERR_Overrun 3 /* переполнение приёмника */
#define STATION_ERR_Framing 4 /* ошибка кадра */
```

Добавить код — одна строка в `station_errors!`, и перечисление, тексты,
`from_code` и заголовок обновятся вместе (тесты `xmacro_enum` и
`xmacro_header`). Чего не хватает до C-версии из введения — `TIMEOUT`
вместо `Timeout`: менять регистр букв и склеивать идентификаторы
`macro_rules!` не умеет. В C склейку даёт `##`; в Rust это работа
процедурного макроса ([глава 24](../ch24/index.md)) или крейта `paste`, который и есть
процедурный макрос.

<div class="box c">

**Как в C.** Перечисление и таблица текстов в C-версии тоже не разойдутся,
но проверить, что коды уникальны и что `error_text[code]` не выходит за
массив, может только программист: `[code] = text` с повтором кода молча
перезапишет строку (GCC предупреждает лишь с `-Woverride-init`, которое
входит в `-Wextra`). В Rust повтор значения у варианта `#[repr(u8)]`
перечисления — ошибка E0081, а `from_code` возвращает `Option`.

</div>

## Таблица обработчиков

Таблица прерываний — массив указателей на функции, где номер прерывания
— индекс. Ошибка в C классическая: обработчик вписан не в ту строку, и
при прерывании UART вызывается обработчик таймера. Макрос строит
перечисление источников, массив и диспетчер из одного списка:

```rust
{{#include ../../code/ch23/src/hardware.rs:handlers}}
```

Длина `HANDLERS` — длина массива номеров, как в `count!` из
[23.2](02-repeat.md); номер служит индексом, поэтому `const`-блок
требует, чтобы номера шли подряд с нуля. Пропуск номера (`0` и `2`) на
rustc 1.97 — E0080 «evaluation panicked: номера идут подряд с нуля»,
повтор (`0` и `0`) — ещё и E0081 «discriminant value `0` assigned more than
once» от `#[repr(u8)]`-перечисления (проверено на копиях макроса). Тест
`handler_table` вызывает диспетчер для трёх источников и смотрит, какой
обработчик оставил след в атомике `LAST`.

Настоящая таблица векторов Cortex-M устроена так же, только лежит в
секции `.vector_table` и читается процессором, а не диспетчером
([8.8](../ch08/08-sections.md)). Крейт cortex-m-rt кладёт туда
начальный указатель стека и системные исключения, а массив
`__INTERRUPTS` с обработчиками прерываний периферии (960 байт в прошивке
из [7.8](../ch07/08-nostd.md)) приходит из крейта устройства, который
генерирует по файлу SVD внешняя программа svd2rust, — к такой генерации
вернётся [глава 24](../ch24/07-tasks.md).

## Регистры и цена раскрытия

Регистры удобно описывать списком «имя, смещение» и получать функции
доступа с правильными адресами. `mmio!` делает функции чтения и записи
для UART0 машины lm3s6965evb, а рядом — та же отправка байта, написанная
руками:

```rust
{{#include ../../code/ch23/src/hardware.rs:mmio}}
```

Стоит ли макрос чего-нибудь в коде? Тест `rustc_macro_is_free` собирает
библиотеку под thumbv7m-none-eabi (`cargo rustc --release -- --emit asm`)
и сравнивает функции. Вот рукописная (rustc 1.97):

```text
ch23_hand_send:
	push	{r7, lr}
	mov	r7, sp
	movw	r1, #49176
	movt	r1, #16384
.LBB5_1:
	ldr	r2, [r1]
	lsls	r2, r2, #26
	bpl	.LBB5_4
	ldr	r2, [r1]
	lsls	r2, r2, #26
	itt	mi
	ldrmi	r2, [r1]
	lslsmi.w	r2, r2, #26
	bpl	.LBB5_4
	ldr	r2, [r1]
	lsls	r2, r2, #26
	bmi	.LBB5_1
.LBB5_4:
	uxtb	r0, r0
	str	r0, [r1, #-24]
	pop	{r7, pc}
```

А макросная — одна строка:

```text
ch23_macro_send = ch23_hand_send
```

Тела совпали инструкция в инструкцию, и LLVM слил две функции в одну,
оставив псевдоним, — как функции с typestate и с голыми записями в
[10.7](../ch10/07-typestate.md) (проход MergeFunctions,
[10.5](../ch10/05-mono.md)).
Разбор тела: `movw`/`movt` собирают адрес FR, 0x4000_C018 (16384 = 0x4000,
49176 = 0xC018); `lsls #26` сдвигает бит 5, TXFF, в знаковый флаг N, и
`bpl` выходит из ожидания, когда буфер не полон; цикл опроса развёрнут
втрое, и каждое `ldr` — отдельное volatile-чтение; `str r0, [r1, #-24]`
пишет байт в DR по адресу 0x4000_C018 − 24 = 0x4000_C000. Макрос
раскрылся до проверки типов, и к генерации кода от него не осталось
ничего, кроме обычных функций.

## `unsafe` внутри макроса

`mmio!` содержит `unsafe`, и это нормально: адреса фиксированы в
описании, а вызывающий получает безопасные функции. Опасно другое —
подставить в `unsafe`-блок *выражение вызывающего*. Макрос для
«выдать буфер один раз» (как `cortex_m::singleton!`) в двух вариантах:

```rust
{{#include ../../code/ch23/src/hardware.rs:unsafe_trap}}
```

В `take_once_bad!` выражение `$init` стоит внутри `unsafe { ... }`, и
вызывающий выполняет там что угодно, не написав слова `unsafe`.
Doc-тест модуля `hardware.rs` компилирует разыменование сырого указателя
`take_once_bad!(u32 = *p)` — без единого `unsafe` в вызывающем коде. В
`take_once!` инициализатор вычисляется до блока, в переменную `init`, и
тот же вызов не компилируется:

```text
error[E0133]: dereference of raw pointer is unsafe and requires unsafe block
 --> f1.rs:3:36
  |
3 |     let _ = ch23::take_once!(u32 = *p);
  |                                    ^^ dereference of raw pointer
```

Ошибка указывает на `*p` в аргументе — туда, где вызывающий и должен
написать `unsafe`. Метапеременная `$ty` внутри блока безопасна: тип не
выполняет кода. Ровно так устроен `cortex_m::singleton!` в cortex-m 0.7.9:
`let expr = $expr;` перед `unsafe`, и в его документации лежит такой же
doc-тест `compile_fail`.

<div class="box trap">

**Ловушка — метапеременная в `unsafe`.** Правило: в `unsafe`-блоке
макроса не должно быть ни одной метапеременной-выражения. Clippy знает
это правило: линт `macro_metavars_in_unsafe` включён по умолчанию и
срабатывает на `take_once_bad!` — но только там, где экспортированный
макрос *раскрыт*. В крейте, который макрос лишь определяет, линт молчит;
тест `take_once_bad_is_flagged_by_clippy` вызывает макрос под
`#[expect(clippy::macro_metavars_in_unsafe)]`, и если линт замолчит,
`cargo clippy -D warnings` упадёт на невыполненном ожидании. Для
неэкспортированных макросов линт по умолчанию выключен.

</div>

<div class="box ref">

**Справка — атомики на Cortex-M0.** `take_once!` выдаёт буфер через
`AtomicBool::swap` — атомарное чтение-изменение-запись. На ARMv6-M
(thumbv6m) таких инструкций нет ([21.4](../ch21/04-hardware.md)), и
вызов `take_once!` там не
скомпилируется: E0599, «no method named `swap` found». Библиотека главы
при этом собирается и для thumbv6m — сам макрос без вызова не
проверяется. Поэтому `cortex_m::singleton!` берёт вместо атомика
критическую секцию (`critical_section::with`): на M0 она запрещает
прерывания, и обычных чтения и записи хватает.

</div>

<div class="box check">

**Проверка.** Тесты `xmacro_enum`, `xmacro_header`, `handler_table`,
`take_once_gives_once`, `take_once_second_time_none` и
`take_once_bad_is_flagged_by_clippy`; doc-тесты E0133 для `take_once!` и
успешная компиляция `take_once_bad!` с `*p`; `rustc_macro_is_free` —
псевдоним функций в ассемблере thumbv7m. Код без `std` собирается на три
цели Cortex-M.

</div>
