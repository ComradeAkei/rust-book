# 23.2. Повторения

Макрос, который принимает фиксированное число аргументов, мало чем лучше
функции. Сила `macro_rules!` — в **повторениях** (repetitions): образец
`$( ... ) разделитель оператор` совпадает с последовательностью
одинаковых кусков, а подстановка повторяет свой кусок столько же раз.

| Оператор | Сколько раз | Разделитель |
|---|---|---|
| `*` | ноль или больше | любой токен, кроме скобок и самих операторов, или без него |
| `+` | один или больше | так же |
| `?` | ноль или один | не бывает |

```rust
{{#include ../../code/ch23/src/repeat.rs:sum}}
```

`sum!(1, 2, 3,)` раскрывается в `0 + 1 + 2 + 3`: внутри подстановки
`$(+ $x)*` повторяется по `$x`, а `0` впереди делает правильным и пустой
вызов `sum!()`. Хвост `$(,)?` — по желанию запятая после последнего
элемента, как в литерале массива; без него `sum!(1, 2, 3,)` не совпал бы
ни с одним правилом. У `bits!` оператор `+`: маска хотя бы из одного бита,
и `bits!()` — ошибка «unexpected end of macro invocation», а не тихий
ноль (doc-тест в `code/ch23/src/repeat.rs`). `bits!(0, 8, 9)` — это
`UARTEN | TXE | RXE` регистра CR из главы 6, 0x301 (тест `sum_and_bits`).

## Правила подстановки

Повторение в подстановке «знает», сколько раз крутиться, по
метапеременным внутри него. Отсюда два правила.

**Глубина.** Метапеременная стоит в подстановке внутри стольких же
повторений, во скольких захвачена. Захваченную во вложенном повторении
нельзя вставить во внешнее — там их много, и непонятно, какую:

```text
error: variable `reg` is still repeating at this depth
 --> rp2.rs:3:23
  |
3 |         [$(stringify!($reg)),*]
  |                       ^^^^
```

Наоборот можно: захваченное снаружи доступно во вложенном повторении и
просто копируется на каждой итерации.

**Длина.** Метапеременные, которые повторяются вместе, должны повторяться
одинаковое число раз. Макрос «застёжка» из модульной документации
`repeat.rs`:

```rust,ignore
macro_rules! zip {
    ([$($a:expr),*] [$($b:expr),*]) => { [$(($a, $b)),*] };
}
let _ = zip!([1, 2] [3]);
```

```text
error: meta-variable `a` repeats 2 times, but `b` repeats 1 time
 --> e3.rs:2:44
  |
2 |     ([$($a:expr),*] [$($b:expr),*]) => { [$(($a, $b)),*] };
  |                                            ^^^^^^^^^^
```

Ошибка возникает при раскрытии, то есть у вызывающего: длины становятся
известны только по аргументам.

## Необязательное: `?` и внутреннее правило

Структура настроек, у полей которой есть значения по умолчанию — или нет:

```rust
{{#include ../../code/ch23/src/repeat.rs:optional}}
```

`$(= $default:expr)?` — «ноль или одно значение». В подстановке нельзя
написать «если значение есть — его, иначе `Default::default()`», зато
можно передать `$($default)?` другому правилу того же макроса: `@or` без
аргументов даёт значение по умолчанию, `@or` с выражением — само
выражение. `UartConfig::default()` — 115200 бод, 8 бит, без чётности,
1 стоп-бит (тест `config_defaults`). Слово `@or` в начале — буквальные
токены, поэтому обычный вызов `config! { pub struct ... }` с этими
правилами не спутается; подробнее о внутренних правилах — в
[23.4](04-recursion.md).

## Вложенные повторения

Карта регистров нескольких устройств — повторение в повторении:

```rust
{{#include ../../code/ch23/src/repeat.rs:nested}}
```

Внешний уровень — устройства, внутренний — их регистры. `$base`
захвачен снаружи и используется внутри: `$base + $off` на каждой
итерации по регистрам. Список `ALL` идёт по обоим уровням сразу —
`$($( ... ),*)*` — и даёт плоский массив пар «имя, адрес»:
`("UART0.FR", 0x4000_C018)`, ..., `("SYSTICK.CVR", 0xE000_E018)` (тест
`nested_register_map`). `concat!` и `stringify!` склеивают строку при
компиляции — `&'static str`, ни байта кода.

<div class="box c">

**Как в C.** Препроцессор не умеет повторять. Вариативный макрос видит
`__VA_ARGS__` целиком и не может пройти по элементам; библиотеки вроде
Boost.Preprocessor и самодельные `FOR_EACH` генерируют для этого макросы
`FE_1`, `FE_2`, ..., `FE_64` — по одному на каждую длину, до заранее
выбранного предела. Карту регистров в C поэтому пишут руками
(`#define UART0_FR (UART0_BASE + 0x018)`) или генерируют внешним скриптом
из описания SVD — к этому вернётся [глава 24](../ch24/07-tasks.md).

</div>

## Подсчёт аргументов при компиляции

Сколько элементов в списке? Повторение не даёт счётчика, но может
произвести по одному токену на элемент, а количество токенов посчитает
компилятор:

```rust
{{#include ../../code/ch23/src/repeat.rs:count}}
```

`replace!` «подменяет» каждый аргумент выражением `()`, и `count!(a b c)`
превращается в `<[()]>::len(&[(), (), ()])` — длину [среза][g-slice] из трёх
значений нулевого размера. `len` у среза — `const fn`, поэтому результат
годится в константу и в длину массива: `[0u8; count!(x y z w)]` (тест
`counting_at_compile_time`). Рекурсии нет, и тысяча аргументов
посчитается так же быстро. `count_rec!` считает рекурсией и упирается в
предел глубины раскрытия — на 128-м аргументе ([23.4](04-recursion.md)).

Встроенный счётчик `${count(x)}` существует, но в rustc 1.97 нестабилен —
«meta-variable expressions are unstable» (E0658, issue #83527); doc-тест
это закрепляет. До стабилизации пользуются приёмом с `replace!`.

<div class="box trick">

**Трюк — длина таблицы из списка имён.** `SENSOR_NAMES` объявлен с длиной
`SENSORS`, которую `count!` вычислил из того же списка. В C
`sizeof(names) / sizeof(names[0])` даёт длину *уже определённого*
массива; здесь длина известна до инициализатора, и рассинхронизация «в
списке четыре имени, а в таблице три строки» — ошибка компиляции E0308:
«expected an array with a size of 4, found one with a size of 3». В 23.6
тот же приём задаёт длину таблицы обработчиков прерываний.

</div>

<div class="box check">

**Проверка.** `sum_and_bits`, `config_defaults`, `nested_register_map` и
`counting_at_compile_time` — тесты значений; три doc-теста `compile_fail`
в `code/ch23/src/repeat.rs` — несовпадение длин, неверная глубина и пустое
`+`; ещё два с кодами — таблица короче списка (E0308) и нестабильный
`${count}` (E0658). Все примеры —
`no_std` и собираются на три цели Cortex-M.

</div>
