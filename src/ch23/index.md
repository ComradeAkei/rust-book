# 23. Декларативные макросы

## Мотивирующая проблема

Препроцессор C — это подстановка текста. Он не знает ни выражений, ни
областей видимости, ни типов: аргумент макроса — строка токенов, и она
вклеивается в тело как есть. Четыре классические ловушки помещаются в
четыре строки:

```c
{{#include ../../code/ch23/c/macros.c:traps}}
```

Вывод программы `code/ch23/c/macros.c` (gcc 13.3, `-O2 -Wall -Wextra`):

```text
SQUARE(1 + 2) = 5
MAX(next(), 3) = 20, вызовов next: 2
SWAP(x, tmp): x = 1, tmp = 2
LOG2: вторая строка
```

`SQUARE(1 + 2)` превращается в `1 + 2 * 1 + 2`, и приоритет операций даёт
5 вместо 9. `MAX(next(), 3)` вычисляет `next()` дважды: первый вызов
сравнивается, второй возвращается. `SWAP(x, tmp)` объявляет свой `tmp`, и
он [затеняет][g-shadowing] переменную вызывающего: `int tmp = x; x = tmp; tmp = tmp;` —
ничего не поменялось. `LOG2` под `if` без фигурных скобок охраняет только
первый `puts`, второй выполняется всегда. Для последней ловушки в C есть
ритуал `do { ... } while (0)`, для остальных — только дисциплина: скобки
вокруг каждого аргумента, имена вида `_tmp_`, аргументы без побочных
эффектов.

Компилятор помогает мало. GCC с `-Wall -Wextra` замечает только `LOG2`
(`-Wmultistatement-macros`), захват имени `tmp` — лишь с `-Wshadow`, а
clang 18 с `-Wall -Wextra` молчит обо всех четырёх
(`code/ch23/c/run.sh` проверяет и вывод, и предупреждения).

Но у препроцессора есть и честное достоинство. В прошивках им описывают
регистры, таблицы прерываний, коды ошибок протокола — один список, из
которого генерируется несколько вещей. Это **X-macro**:

```c
{{#include ../../code/ch23/c/macros.c:xmacro}}
```

Добавить код ошибки — одна строка в `STATION_ERRORS`; перечисление и
таблица текстов не разойдутся.

## Что делает Rust

[`macro_rules!`][g-declarative-macro] работает не с текстом, а с **[деревьями токенов][g-token-tree]**: скобки в
аргументах всегда сбалансированы, а захваченный фрагмент — это уже
разобранный кусок синтаксиса. Отсюда ответы на ловушки:

- `$x:expr` — узел дерева выражения: подставленный, он остаётся одним
  операндом, и `square!(1 + 2)` равно 9 ([23.1](01-rules.md));
- локальные переменные из тела макроса не видны вызывающему и не
  затеняют его переменные — **гигиена** (hygiene), и `swap!(x, tmp)`
  работает ([23.3](03-hygiene.md));
- макрос раскрывается в целую синтаксическую единицу — выражение,
  операторы, элементы, — а тело `if` в Rust всегда в фигурных скобках, так
  что ловушке `LOG2` неоткуда взяться;
- повторное вычисление аргумента — единственная ловушка, от которой язык
  *не* защищает: подставленное дважды выражение вычисляется дважды. Лечится
  она, как в C с расширением GCC `({ ... })`, привязкой к имени — только
  блок в Rust и так выражение ([23.1](01-rules.md)).

X-macro переносится один в один, и сверх того макрос может разбирать
вход: [повторения][g-repetition] ([23.2](02-repeat.md)), рекурсия и разбор «по токену»
([23.4](04-recursion.md)) превращают список регистров или переходов
автомата в код, который проверит компилятор. Всё это работает при
компиляции, на [хосте][g-host], при любой [цели][g-target]: сгенерированный код — обычный
[`no_std`][g-no-std], и стоит он ровно столько же, сколько написанный руками
([23.6](06-hardware.md)).

- `macro_rules!` ([23.1](01-rules.md)) — правила, [виды фрагментов][g-fragment-specifier], порядок
  сопоставления, отсутствие отката.
- Повторения ([23.2](02-repeat.md)) — `$(...)*`, `+`, `?`, вложенные
  повторения, подсчёт аргументов при компиляции.
- Гигиена и `$crate` ([23.3](03-hygiene.md)) — какие имена прячет макрос,
  а какие нет, и как писать пути, которые не подменить.
- Рекурсия и [TT-muncher][g-tt-muncher] ([23.4](04-recursion.md)) — [внутренние правила][g-internal-rule],
  [накопители][g-accumulator], предел рекурсии.
- Видимость и экспорт ([23.5](05-scope.md)) — [текстовая область
  видимости][g-textual-scope], `#[macro_export]`, макросы по пути.
- Макросы для железа ([23.6](06-hardware.md)) — X-macro, таблица
  обработчиков, регистры, `unsafe` внутри макроса и цена раскрытия.

Главная мысль главы: макрос — функция из токенов в токены, которую
выполняет компилятор, и всё, что он сгенерировал, проходит те же проверки
типов и [заимствований][g-borrowing], что и рукописный код. Макрос не может сделать
программу менее безопасной — если только сам не спрячет `unsafe` от
вызывающего ([23.6](06-hardware.md)).

## Код главы

Примеры 23.1–23.6 лежат в `code/ch23`, задачи — в `exercises/ch23` и
`solutions/ch23`. Макросы раскрываются на хосте, а их код — `no_std`:
библиотека [без возможности][g-feature] `std` собирается на все три цели Cortex-M, а
макросы задач B и C использует прошивка `firmware/ch23-periph`.

```console
$ cargo test -p ch23                  # примеры, отказы компилятора, раскрытие, ассемблер
$ cargo test -p ch23-solutions        # задачи A–D
$ bash code/ch23/c/run.sh             # ловушки препроцессора C
$ cd firmware && cargo run --release -p ch23-periph   # задача C в QEMU
```

Программы, которые компилятор должен отвергнуть, — [doc-тесты][g-doctest]
`compile_fail`, где есть код ошибки — с кодом; коды сверяет nightly
[rustdoc][g-rustdoc] в CI. Тексты сообщений в главе сняты с rustc 1.97. Раскрытие
макросов показывает `rustc -Zunpretty=expanded` (флаг nightly; на stable
его открывает `RUSTC_BOOTSTRAP=1` — только для осмотра, не для сборки);
[крейт][g-crate] `cargo-expand` печатает то же, отформатировав. Тест
`rustc_swap_hygiene_expansion` сверяет [снимок][g-snapshot] раскрытия с закреплённым
rustc, а `rustc_macro_is_free` — ассемблер под thumbv7m-none-eabi.
