# 15.2. String и &str

`String` — это `Vec<u8>` с одним обещанием: байты образуют корректный
UTF-8. `&str` — заём такого буфера, толстая ссылка (указатель и длина в
байтах). Отсюда всё поведение строк, которое удивляет после C, где
строка — это `char *` с нулём в конце и один байт на символ.

## Длина — в байтах, не в символах

```rust
{{#include ../../code/ch15/src/strings.rs:lengths}}
```

`"adc0"` — 4 байта и 4 символа, но `"датчик"` — 12 байт и 6 символов, а
`"🌡"` — 4 байта и один символ. `len()` возвращает байты, потому что это
то, что знает буфер; число символов нужно считать обходом (`chars().count()`),
это O(n).

Поэтому индексации по номеру символа нет вовсе:

```rust,compile_fail
let s = String::from("датчик");
let c = s[0];   // E0277: String нельзя индексировать по usize
```

В C `s[0]` вернул бы первый байт, и для «датчик» это была бы половина
буквы «д». Rust не делает вид, что байт — это символ. Срез по байтам
допустим, но только на границе символа, иначе паника:

```rust,should_panic
let s = "датчик";
let _ = &s[..1];   // середина «д» — паника в рантайме
```

<div class="box c">

**Как в C.** `strlen` считает байты до нуля, и в UTF-8 это не число
символов. `s[i]` — байт, и перебор по байтам режет многобайтовые буквы.
`toupper` в цикле по `char *` меняет регистр на месте, байт в байт, —
и ломается на любой не-ASCII букве. Rust разводит эти понятия: байт,
символ и смещение символа — три разных обхода (ниже), а длина явно
названа байтовой.

</div>

## Три обхода: байты, символы, смещения

`s.bytes()` даёт байты, `s.chars()` — символы `char` (по 4 байта
каждый), `s.char_indices()` — пары «байтовое смещение, символ». Для `"дt"`
это `[0xd0, 0xb4, b't']`, `['д', 't']` и `[(0, 'д'), (2, 't')]`
соответственно: буква «д» занимает байты 0 и 1, а `t` начинается с
байта 2.

## Обрезать по границе символа

Имя датчика кладут в поле фиксированной длины — как `char name[16]` в
кадре. Обрезать строку по `max` байт нельзя как попало: срез обязан
кончиться на границе символа.

```rust
{{#include ../../code/ch15/src/strings.rs:truncate}}
```

`is_char_boundary` отступает назад, пока не упрётся в начало символа.
`truncate_bytes("датчик", 5)` даёт `"да"` (4 байта): пятый байт — середина
«т», и функция откатывается к четырём.

## UTF-8 проверяется один раз, на границе

Байты из кадра — ещё не `&str`. Проверка UTF-8 делается один раз, при
входе данных в программу, и дальше тип `&str` несёт это знание сам:

```rust
{{#include ../../code/ch15/src/strings.rs:from_wire}}
```

На испорченных байтах `from_utf8` возвращает `Utf8Error`, который говорит,
сколько байт успели разобрать (`valid_up_to`) и что именно сломалось:
`"invalid utf-8 sequence of 1 bytes from index 0"`. Это граница доверия:
внутри программы невалидного UTF-8 в `&str` уже не бывает.

## Смена регистра меняет длину

```rust
{{#include ../../code/ch15/src/strings.rs:case}}
```

`"straße".to_uppercase()` — это `"STRASSE"`: буква «ß» превращается в две
«SS», и длина растёт с 6 до 7 байт. Переписать на месте, как `toupper`,
нельзя — нужен новый буфер. Для «датчик» → «ДАТЧИК» длина не меняется
(12 байт), но это совпадение кириллицы, а не правило.

## Сборка строки без лишних выделений

Собирать отчёт через `format!` на каждое поле — это выделение на каждую
строку. `String::with_capacity` плюс `write!` прямо в буфер обходится
одним выделением:

```rust
{{#include ../../code/ch15/src/strings.rs:build}}
```

Для двух строк по шаблону «имя: значение» ёмкость `2 * 16 = 32` байта
хватает с запасом, и роста нет: тест `report_fits_capacity` проверяет,
что `capacity()` после сборки так и осталась 32. `write!` в `String`
никогда не возвращает ошибку (в отличие от записи в файл), поэтому
`let _ =` здесь честен, а не глушит проблему.
