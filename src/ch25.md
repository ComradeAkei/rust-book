# 25. Вычисления при компиляции

> Глава в работе. Ниже её план из программы курса: темы, связь с C и с железом, задачи. Полный текст по образцу [главы 6](ch06/index.md) появится на шаге 3.

**Темы.** const и static, const fn и её ограничения, блоки const { ... }, развитие const generics, const _: () = assert!(...). static с внутренней изменяемостью: атомики и Mutex::new в const-контексте. Почему static mut почти нельзя использовать в edition 2024. LazyLock против const-инициализации.

**Как в C.** constexpr из C23, _Static_assert, #error, макросы для таблиц.

**Железо.** const-данные попадают во flash (.rodata), изменяемые static в .data или .bss, то есть в ОЗУ. .data копируется из flash при старте. На МК это прямая экономия ОЗУ.

**Трюки и ловушки.** Таблицы CRC и синуса в const fn, разбор строковых литералов при компиляции. const копируется в каждое место использования, static существует в одном экземпляре. Адреса двух ссылок на одну const могут различаться.

**Задачи**

- A. Для 6 объявлений определите секцию (.rodata, .data, .bss) и проверьте через nm и llvm-objdump.
- B. Таблица CRC-32 в const fn. Вернитесь к таблице из build.rs в главе 8 и сравните оба подхода.
- C. const fn разбирает IPv4-адрес из строкового литерала, а неверный ввод даёт ошибку компиляции. Макрос-обёртка ip!("192.168.1.1").
- D. Проверка при компиляции, что статические буферы всех драйверов вместе помещаются в бюджет ОЗУ. Бюджет приходит из build.rs через env!, и превышение ломает сборку понятным сообщением.
